Каждая команда сопровождается условным примером вывода и пояснениями ко всем параметрам и флагам. Реальные адреса, логины, пароли и ключи не используются.

Каждая команда сопровождается примером результата и объяснением параметров. Упражнения используют отдельные учебные объекты; предусмотрены их очистка и проверка состояния системы.

## Практика point_1: локальный APT-репозиторий и обновление без Интернета

[point_1.md](Mod%201/point_1.md) — подробный материал для новичков в двух явно разделённых частях, целиком на одной удалённой Astra Linux SE 1.7 по SSH. Часть 1: пакеты, dpkg и APT, зависимости, проверка инструментов, установка недостающего генератора индекса, устройство и подключение репозиториев. Часть 2: пошаговое решение с собственными текстовыми пакетами; роли шлюза и целевого сервера моделируются каталогами этой же машины. Для команд объяснены смысл, параметры и ожидаемые результаты; предусмотрены чек-лист, подтверждение выполнения и очистка.

## Препромпт «АстраКонтур» для администратора Astra Linux SE 1.7

[astrakontur_astra_linux_se_1_7_system_administrator_preprompt_v1_1_final.md](Mod%201/astrakontur_astra_linux_se_1_7_system_administrator_preprompt_v1_1_final.md) — системный препромпт специализированного ИИ-ассистента по защищённой эксплуатации Astra Linux SE 1.7. Помогает разбирать журналы и конфигурации, диагностировать загрузку и службы, планировать обновления, работать с сетью и хранилищами, готовить сценарии Bash и инструкции восстановления. Задаёт порядок работы: сбор фактов о конкретной системе, обоснование решения, минимальное изменение, независимая проверка результата, документирование и контролируемый откат.

## Как использовать

1. Выберите файл под свою задачу и изучите его содержание.
2. Добавьте выбранный препромпт в инструкции ИИ-ассистента или в файлы проекта, если используемый сервис поддерживает такой способ работы.
3. В вводной инструкции замените `НАЗВАНИЕ_ФАЙЛА.md` на имя фактически добавленного файла.
4. В примере запроса на создание PM-ассистента указан исходный файл `AI_assist_preprompt.md`. Он не входит в этот набор: перед использованием укажите имя своего исходного препромпта и добавьте его в проект.

ИИ-материалы являются дополнительными примерами и не заменяют документацию Astra Linux. Команды и сценарии, полученные от ассистента, проверяйте на учебной виртуальной машине перед применением.

## Модуль 2. Файловая система, монтирование и дисковые устройства

[filesystem_hierarchy_and_mounting_practice.md](Mod%202/filesystem_hierarchy_and_mounting_practice.md) — подробная практика для начинающих на одной удалённой Astra Linux SE 1.7 по SSH. Каждая команда сопровождается пояснениями параметров и ожидаемого результата; предусмотрены восстановление после разрыва SSH и очистка.

### Практика point_2: XFS, noatime и подключение по UUID

[point_2.md](Mod%202/point_2.md) — подробный материал в двух частях для одной удалённой Astra Linux SE 1.7 по SSH. Сначала — пакетные инструменты и подготовка xfsprogs, поддержка XFS, устройство диска и раздела, UUID, временные отметки, смысл noatime, права и формат fstab. Затем — полное решение на собственном образе 512 MiB с разделом XFS 480 MiB: проверка принадлежности loop-устройства, ручное монтирование, каталог с наследованием группы, вымышленные записи, контрольные суммы и проверка atime. Повторное подключение по UUID моделируется применением отдельного model/etc/fstab, без изменения загрузочных настроек и перезагрузки сервера. Для XFS объяснён выбор pass=0 вместо 2. Для команд разобраны смысл, параметры и ожидаемые результаты; есть таблица результатов, подтверждение выполнения, восстановление после разрыва SSH и очистка.

## Модуль 3. Журналирование и планировщики заданий

[system_logging_and_log_analysis_practice.md](Mod%203/system_logging_and_log_analysis_practice.md) — подробная практика для новичков на одной удалённой Astra Linux SE 1.7 по SSH. Устройство journald и rsyslog, уровни важности и facility, выборки journalctl по загрузке, службе, времени и точной важности; собственные события и экспорт в текст и JSON. Отдельный экземпляр rsyslog принимает сообщения через личный Unix-сокет и направляет их в два учебных файла. Поиск и подсчёт событий через grep, awk и другие инструменты, непрерывный просмотр в одном SSH-сеансе, проверка и изменение правил, обнаружение ошибки конфигурации. Ротация и сжатие выполняются отдельной политикой logrotate со своим файлом состояния, после остановки только учебного процесса. Все команды и флаги объяснены, приведены ожидаемые результаты; предусмотрены отчёт, восстановление после SSH и очистка. Настройка отрабатывается на собственных файлах и процессе; существующие системные журналы не очищаются.
