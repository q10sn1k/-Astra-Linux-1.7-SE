# Модуль 3. Практика: планировщик заданий Cron

Вся работа выполняется **на одной удалённой Astra Linux SE 1.7 по SSH**, в Bash обычного пользователя с доступом к `sudo`. Создадим короткий сценарий, запустим его по расписанию раз в минуту, проверим результат и удалим задание.

Для упражнения используется отдельный файл в `/etc/cron.d`. Существующие расписания не редактируются. Сам сценарий выполняется от вашей обычной учётной записи, без административных прав. SSH, сеть и сервер перезапускать не нужно.

Копируйте блоки команд последовательно. При ошибке или сообщении `STOP` остановитесь и разберите причину. Примеры результатов условные: UID `1000`, пользователь `student`, даты и время на вашей машине будут другими.

## 1. Что такое Cron и как читать расписание

**Cron** — служба, которая проверяет расписания и запускает команды в подходящую минуту. Это удобно для периодического формирования отчётов, обслуживания и проверок. В упражнении команда только записывает время и UID пользователя в свои файлы.

**Crontab** — таблица заданий. У пользователя может быть личная таблица; для неё используется команда `crontab`. Файлы `/etc/crontab` и `/etc/cron.d/` — системный вариант таблицы с дополнительным полем пользователя.

| Поле | Допустимые значения | Пример |
| --- | --- | --- |
| Минута | 0–59 | `15` — в пятнадцатую минуту |
| Час | 0–23 | `9` — в девять часов |
| День месяца | 1–31 | `1` — первого числа |
| Месяц | 1–12 | `6` — в июне |
| День недели | 0–7 | `1` — понедельник; `0` и `7` — воскресенье |

`*` означает любое значение поля, `*/5` — шаг пять от начала диапазона, `1-5` — диапазон, `1,3,5` — перечисление.

Примеры ниже объясняют **только пять полей времени**, устанавливать их отдельными командами не нужно:

| Расписание | Когда срабатывает |
| --- | --- |
| `* * * * *` | Каждую минуту |
| `*/5 * * * *` | В минуты 00, 05, 10 и так далее каждого часа |
| `30 9 * * 1-5` | По будням в 09:30 |
| `0 2 1 * *` | Первого числа каждого месяца в 02:00 |

Cron ориентируется на время сервера. Если ограничены одновременно день месяца и день недели, обычный Cron использует условие **«или»** между этими полями. Например, `0 9 1 * 1` означает первое число месяца **и каждый понедельник** в 09:00.

Пропущенные из-за выключенного сервера обычные запуски задним числом не выполняются. Закрытие вашего SSH-сеанса само по себе не отменяет расписание.

## 2. Проверьте систему и службу

```bash
whoami
cat /etc/astra_version
date --iso-8601=seconds
command -v crontab
systemctl is-active cron.service
```

`whoami` показывает учётную запись; `cat` читает файл версии Astra. `date --iso-8601=seconds` выводит дату, время с секундами и смещение часового пояса. `command -v` ищет программу и показывает её путь. `systemctl is-active` проверяет, работает ли указанная служба, ничего не переключая.

**Пример результата:**

```text
student
1.7.x
2026-10-29T12:10:20+03:00
/usr/bin/crontab
active
```

Если программа найдена и служба `active`, переходите к разделу 3.

### Если Cron отсутствует

Выполните только при отсутствии пакета:

```bash
sudo apt-get --simulate install --no-install-recommends --no-upgrade cron
```

`sudo` даёт административные права для команды. `apt-get install` готовит установку пакета `cron`; `--simulate` показывает план без изменений; `--no-install-recommends` исключает необязательные рекомендуемые пакеты; `--no-upgrade` запрещает обновление самого запрошенного пакета, если он уже установлен. Зависимости всё равно могут потребовать изменений — прочитайте весь план.

**Ожидается:** перечень предлагаемых действий. Если предлагаются удаления или нежелательные изменения существующих пакетов, установку не продолжайте.

Если план подходит:

```bash
sudo apt-get install --no-install-recommends --no-upgrade --no-remove cron
```

`--no-remove` останавливает операцию, если APT собирается удалить пакеты. Перед подтверждением ещё раз прочитайте итоговый список. При установке служба может запуститься автоматически. Используйте уже настроенные репозитории Astra этого сервера; чужие репозитории добавлять не требуется.

**Ожидается:** успешная установка и настройка `cron`. Если пакет не найден или сервер изолирован от репозитория, сначала потребуется доступный источник пакетов соответствующего выпуска Astra; продолжать без Cron нельзя.

Если служба установлена, но неактивна, сначала выясните причину:

```bash
systemctl status cron.service --no-pager
sudo journalctl --unit=cron.service --lines=15 --no-pager
```

`status` показывает состояние службы; `--no-pager` выводит всё прямо в терминал. В `journalctl` параметр `--unit` выбирает службу, `--lines=15` ограничивает вывод последними пятнадцатью записями. Эти команды только читают состояние и журналы.

**Ожидается:** описание состояния и возможной причины остановки. Запуск остановленного Cron активирует также уже существующие расписания сервера. Если остановка была намеренной, учебную практику на этой машине пока не продолжайте. Если это учебная ВМ и Cron должен работать:

```bash
sudo systemctl start cron.service && systemctl is-active cron.service
```

`start` запускает службу; `&&` выполняет проверку только после успешного запуска. **Результат:** `active`. Перезапуск службы и изменение её автозапуска не нужны.

## 3. Подготовьте личный каталог

```bash
LAB_UID="$(id -u)"
LAB_USER="$(id -un)"
LAB_DIR="/var/tmp/astra-cron-$LAB_UID"
LAB_CRON="/etc/cron.d/astra-training-$LAB_UID"
printf 'Пользователь: %s\nКаталог: %s\nРасписание: %s\n' "$LAB_USER" "$LAB_DIR" "$LAB_CRON"
```

`id -u` возвращает числовой UID; `id -un` — имя пользователя (`-u` выбирает пользователя, `-n` заменяет номер именем). `$(...)` подставляет результат команды. Переменные `LAB_...` хранят пути для следующих шагов. `printf` подставляет строки вместо `%s`, а `\n` переводит строку. Двойные кавычки сохраняют каждое значение одним аргументом.

**Пример результата:**

```text
Пользователь: student
Каталог: /var/tmp/astra-cron-1000
Расписание: /etc/cron.d/astra-training-1000
```

Создайте каталог только для новой практики:

```bash
if [ "$LAB_UID" -eq 0 ]; then
    printf '%s\n' 'STOP: выполняйте практику от обычного пользователя, не root.'
elif [[ ! "$LAB_USER" =~ ^[a-zA-Z_][a-zA-Z0-9_-]*\$?$ ]]; then
    printf '%s\n' 'STOP: пример рассчитан на простое локальное имя пользователя.'
elif [ -e "$LAB_DIR" ] || [ -L "$LAB_DIR" ]; then
    printf '%s\n' 'STOP: учебный каталог уже существует; проверьте предыдущую практику.'
else
    mkdir -m 700 -- "$LAB_DIR"
fi
```

`if / elif / else / fi` выбирают одну ветку. `[ ... ]` — проверка: `-eq` сравнивает числа; `-e` обнаруживает существующий объект, `-L` — символическую ссылку, включая повреждённую. `||` означает «или». Проверка Bash `[[ ... =~ ... ]]` сопоставляет имя с шаблоном: сначала буква или `_`, затем буквы, цифры, `_` и `-`, необязательный `$` в конце. `!` отрицает совпадение. Доменные имена сложного вида в эту короткую практику не входят.

`mkdir -m 700` создаёт каталог с доступом только владельцу: чтение, запись и вход. `--` завершает разбор флагов. **Ожидается:** отсутствие вывода; при `STOP` дальше не идите. Каталог повторно не создавайте.

## 4. Создайте и проверьте сценарий

```bash
cat > "$LAB_DIR/task.sh" <<'EOF'
#!/bin/sh
PATH=/usr/bin:/bin
export PATH
umask 077
LAB_DIR="/var/tmp/astra-cron-$(id -u)"
printf 'time=%s uid=%s status=ok\n' "$(date --iso-8601=seconds)" "$(id -u)" > "$LAB_DIR/latest.txt" &&
    cat "$LAB_DIR/latest.txt"
EOF
chmod 600 -- "$LAB_DIR/task.sh"
/bin/sh -n "$LAB_DIR/task.sh"
```

`cat > файл <<'EOF'` записывает многострочный текст до отдельной строки `EOF`. Кавычки вокруг `'EOF'` сохраняют `$` и команды внутри текста: они выполнятся при запуске сценария. `>` создаёт файл или заменяет его содержимое.

В сценарии `#!/bin/sh` указывает интерпретатор; `PATH` задаёт каталоги поиска программ, `export` передаёт эту настройку дочерним процессам. `umask 077` закрывает доступ других пользователей к новым файлам. Сценарий заново определяет UID: переменных вашей SSH-оболочки у Cron нет.

`printf` записывает время, UID и `status=ok` в `latest.txt`; после успешной записи `&& cat` выводит ту же строку. `latest.txt` при каждом запуске заменяется, поэтому хранит только последний результат. Метка `status=ok` относится к этому учебному действию, а не к состоянию всего сервера.

`chmod 600` оставляет владельцу чтение и запись. Исполняемый бит здесь не нужен: сценарий явно читает `/bin/sh`. Его флаг `-n` проверяет синтаксис без выполнения. **Ожидается:** отсутствие сообщений. Проверка синтаксиса ещё не доказывает правильность работы.

Запустите вручную:

```bash
/bin/sh "$LAB_DIR/task.sh" >> "$LAB_DIR/manual.log" 2>&1 &&
    cat "$LAB_DIR/manual.log"
```

`>>` дописывает стандартный вывод в `manual.log`. `2>&1` направляет туда же ошибки: `2` — поток ошибок, `1` — обычный вывод. Порядок важен: сначала выбирается файл для потока 1, потом к нему присоединяется поток 2. Последний `cat` выполняется только при успешном запуске.

**Пример результата:**

```text
time=2026-10-29T12:12:40+03:00 uid=1000 status=ok
```

Если вывода нет из-за ошибки, прочитайте `manual.log` командой `cat` с тем же путём и исправьте причину до установки расписания.

## 5. Подготовьте расписание и подключите его

```bash
printf 'SHELL=/bin/sh\nPATH=/usr/bin:/bin\nMAILTO=""\n* * * * * %s /bin/sh "%s/task.sh" >> "%s/cron.log" 2>&1\n' \
    "$LAB_USER" "$LAB_DIR" "$LAB_DIR" > "$LAB_DIR/cron.conf"
cat "$LAB_DIR/cron.conf"
```

Здесь `printf` формирует готовый файл. Обратная косая черта в конце первой строки продолжает **команду Bash** на следующей строке. В самом файле задание будет одной строкой.

**Пример результата:**

```cron
SHELL=/bin/sh
PATH=/usr/bin:/bin
MAILTO=""
* * * * * student /bin/sh "/var/tmp/astra-cron-1000/task.sh" >> "/var/tmp/astra-cron-1000/cron.log" 2>&1
```

Первые пять звёздочек задают запуск каждую минуту. Следующее поле `student` определяет пользователя: хотя файл установит root, команда выполнится как `student`. В **личной** таблице `crontab -e` такого поля нет; приведённый формат предназначен именно для `/etc/cron.d`.

`SHELL` выбирает оболочку команды, `PATH` — поиск программ в этом файле расписания. `MAILTO=""` отключает почтовые уведомления для его заданий. Вывод и ошибки нашей команды собираются в `cron.log`; системные журналы при этом работают как обычно.

Время вычисляется внутри сценария. Это позволяет не помещать `%` в строку Cron: непосредственно в расписании неэкранированный `%` имеет специальный смысл. Каждая строка конфигурации, включая последнюю, заканчивается переводом строки благодаря `\n`.

Установите отдельный файл без перезаписи существующего:

```bash
sudo sh -c 'umask 022; set -C; cat > "$1"' sh "$LAB_CRON" < "$LAB_DIR/cron.conf" &&
    sudo stat -c '%U %a %n' -- "$LAB_CRON"
```

`sudo sh -c` запускает только короткую команду записи с правами администратора. Первый `sh` после текста команды задаёт её условное имя, следующий аргумент становится `$1` — путём назначения. `<` передаёт содержимое подготовленного файла на стандартный ввод `cat`.

`umask 022` при создании обычного файла даёт права `644`: запись владельцу, чтение всем. `set -C` запрещает перезапись существующего обычного файла через `>`; при конфликте остановитесь, не удаляйте чужой файл. Наше имя содержит только буквы, цифры и дефисы, без точки: это подходящий формат имени для `/etc/cron.d`.

`stat -c` выводит заданный формат: `%U` — владелец, `%a` — права цифрами, `%n` — имя. **Ожидается:**

```text
root 644 /etc/cron.d/astra-training-1000
```

Если права отличаются, сначала разберите причину. Cron требует владельца root и отсутствие записи для группы и остальных. Отдельной команды применения и перезапуска не требуется: служба перечитывает изменения автоматически.

## 6. Убедитесь, что задание запускается

Подождите одну-две минуты, затем выполните:

```bash
tail -n 5 -- "$LAB_DIR/cron.log"
cat "$LAB_DIR/latest.txt"
wc -l -- "$LAB_DIR/cron.log"
```

`tail -n 5` показывает последние пять строк; `cat` — последний результат; `wc -l` считает строки. **Пример:**

```text
time=2026-10-29T12:14:01+03:00 uid=1000 status=ok
time=2026-10-29T12:15:01+03:00 uid=1000 status=ok
time=2026-10-29T12:15:01+03:00 uid=1000 status=ok
2 /var/tmp/astra-cron-1000/cron.log
```

Первые две строки вывел `tail`, третью — `cat`, последнюю — `wc`. Секунда запуска может отличаться от `01`: Cron не гарантирует точность до секунды. В `cron.log` попадают только запуски по расписанию; ручная проверка использовала другой файл.

Повторите этот блок через минуту: должны измениться время в `latest.txt` и число строк в журнале. Это подтверждает повторный запуск. Снимок терминала с этими выводами и установленным расписанием подойдёт для отчёта.

### Если файл журнала не появился

```bash
systemctl is-active cron.service
sudo cat "$LAB_CRON"
sudo journalctl --since='5 minutes ago' --no-pager --identifier=CRON
```

Первая команда проверяет службу, вторая — реально установленную конфигурацию. В третьей `--since` ограничивает время последними пятью минутами, `--identifier=CRON` выбирает сообщения процесса с такой меткой, `--no-pager` отключает постраничный просмотр.

**Ожидается:** `active`, правильная строка задания и, в зависимости от настройки журналирования, записи Cron. Метка может отличаться, поэтому пустая выборка сама по себе не доказывает отсутствие запуска. Если journal не содержит событий, можно прочитать последние строки текстового журнала при его наличии:

```bash
sudo tail -n 100 /var/log/syslog | grep -F -- "$LAB_DIR/task.sh"
```

`tail -n 100` ограничивает чтение сотней последних строк, `|` передаёт их следующей команде; `grep -F` ищет буквальный путь без регулярных выражений. **Ожидается:** запись запуска нашего сценария. Отсутствие файла `/var/log/syslog` допустимо при другой схеме журналирования. Наличие записи запуска ещё не гарантирует успех сценария — результат проверяется по его файлам.

Проверьте имя файла без точки, поле пользователя, владельца и права, полный путь к сценарию, доступность каталога и `cron.log`. В Astra ограничения учётной записи, PAM и политики безопасности тоже могут запрещать запуск. Их отключать ради упражнения не следует: используйте журнал ошибки и помощь администратора.

## 7. Удалите задание и завершите практику

Сначала удаляется расписание, затем данные. Сравнение ниже защищает от удаления файла, который после установки кто-то изменил:

```bash
if [ "$LAB_CRON" = "/etc/cron.d/astra-training-$(id -u)" ] &&
    sudo cmp -s -- "$LAB_DIR/cron.conf" "$LAB_CRON"; then
    sudo rm -- "$LAB_CRON" && printf '%s\n' 'Учебное расписание удалено.'
else
    printf '%s\n' 'STOP: путь или содержимое расписания не совпадает; проверьте файл.'
fi
```

`=` сравнивает строки, `cmp -s` молча сравнивает содержимое файлов и возвращает успех только при совпадении. `rm` удаляет **один явно указанный учебный файл**, `--` завершает флаги. **Ожидается:** `Учебное расписание удалено.` При `STOP` каталог пока не удаляйте.

Подождите одну-две минуты: Cron должен заметить удаление, а уже начатый короткий сценарий — завершиться. Сравните `wc -l` для `cron.log` дважды с интервалом в минуту: количество строк перестанет расти. Службу Cron останавливать не нужно — она обслуживает и другие задания.

После сохранения нужного результата удалите личный каталог:

```bash
if [ "$LAB_DIR" = "/var/tmp/astra-cron-$(id -u)" ] &&
    [ ! -e "$LAB_CRON" ] && [ ! -L "$LAB_CRON" ]; then
    rm -rI -- "$LAB_DIR"
else
    printf '%s\n' 'STOP: проверьте путь и удаление расписания.'
fi
```

`! -e` и `! -L` проверяют отсутствие файла расписания и ссылки. `rm -r` удаляет каталог с содержимым, заглавная `-I` запрашивает подтверждение перед рекурсивным удалением. Убедитесь, что в вопросе указан ваш каталог `/var/tmp/astra-cron-...`, и подтвердите. **Ожидается:** удаление только учебных файлов. Пакет и общая служба Cron остаются установленными.

## 8. Если SSH оборвался

Подключитесь к той же машине под тем же пользователем. Повторите **только блок присваивания переменных из раздела 3**, затем проверку результатов из раздела 6. Повторно создавать каталог и устанавливать расписание не нужно. Для завершения выполните раздел 7.

Если сервер перезагрузился, задание сможет продолжить работу при работающем Cron и сохранности файлов в `/var/tmp`. Этот каталог не гарантирует бессрочное хранение: его может очищать политика системы. Для постоянной рабочей автоматизации нужны устойчивое размещение сценария, контроль ошибок и продуманное хранение журналов.

## 9. Что нужно запомнить

- Пять полей задают время; в `/etc/cron.d` после них обязательно указывается пользователь.
- Cron работает независимо от SSH-сеанса и не получает все переменные вашего терминала.
- Используйте явные пути, неинтерактивные сценарии и сохраняйте ошибки в журнал.
- Сначала проверяйте сценарий вручную, потом по расписанию; после практики удаляйте своё задание.
- `crontab -l` показывает личную таблицу текущего пользователя, поэтому наш файл из `/etc/cron.d` там не появится. При отсутствии личной таблицы сообщение `no crontab for ...` нормально. `crontab -e` редактирует эту таблицу; `crontab -r` удаляет её целиком и для нашей практики не нужен.

Справка по установленному на сервере варианту доступна через `man 5 crontab`, `man 8 cron` и `man 1 crontab`: цифры выбирают раздел руководства — формат файла, системную службу или пользовательскую команду. Выход из просмотра — `q`.

Дополнительные справочники: [формат crontab](https://manpages.debian.org/buster/cron/crontab.5.en.html), [служба Cron](https://manpages.debian.org/buster/cron/cron.8.en.html), [команда crontab](https://manpages.debian.org/buster/cron/crontab.1.en.html). Особенности конкретной установки Astra проверяйте по её локальной справке и действующим политикам.
