# Модуль 4. Проверка свободного места и резервное копирование конфигураций

Вся работа выполняется **на одной удалённой Astra Linux Special Edition 1.7 по SSH**, в Bash обычного пользователя с доступом к `sudo`. Второй сервер, графический редактор и действия в локальном терминале вашего компьютера не нужны.

Материал состоит из двух частей:

1. **Подготовка и основы:** пакеты, репозитории, команды для проверки диска, архивы, журналирование, Bash и работа в консольном редакторе nano.
2. **Практика:** создание полного сценария, проверка обычного запуска и предупреждения о нехватке места, проверка архива и восстановление учебных файлов, ежедневное расписание, результаты для отчёта и очистка.

Сценарий всегда проверяет файловую систему, на которой расположен настоящий `/var`. Сначала он архивирует маленький учебный каталог с вымышленными настройками. Отдельный режим позволяет прочитать настоящий `/etc/astra` и сохранить архив в `/backup/astra-point4/`. Это собственный подкаталог внутри требуемого `/backup/`, чтобы не смешивать упражнение с чужими резервными копиями.

| Режим | Источник | Архивы | Полномочия |
| --- | --- | --- | --- |
| `--lab` | `/var/tmp/astra-point4-UID/model/etc/astra` | `/var/tmp/astra-point4-UID/backup` | Обычный пользователь |
| `--lab --test-low-space` | Тот же учебный каталог | Тот же учебный каталог архивов | Обычный пользователь; решение о предупреждении проверяется с моделью 5% |
| `--system` | `/etc/astra` | `/backup/astra-point4` | root через `sudo` |

Основной маршрут использует `--lab`. Для проверки предупреждения **не заполняем диск**, не меняем разделы и не удаляем данные. В сообщении о моделировании отдельно указываются настоящий результат измерения и учебное значение 5%. Тестовые предупреждения действительно попадут в системный журнал с учебной меткой.

Режим `--system` нужен, если в отчёте требуется настоящий архив `/etc/astra`. Он читает конфигурации, но не применяет их и не перезапускает службы. Такой архив может содержать закрытые сведения: доступ к каталогу и файлам ограничивается root. Содержимое настоящих конфигураций не нужно вставлять в отчёт.

Примеры вывода условные: пользователь `student`, UID `1000`, даты и размеры на вашей машине отличаются. Команды сами получают UID; значения из примеров вручную подставлять не требуется.

## Часть 1. Подготовка, инструменты и работа с редактором

### 1. Как выполнять команды через SSH

Начинайте с раздела 2: там находится первый блок команд. Читайте объяснение, выполняйте **один полный блок** и проверяйте результат. При ошибке или `STOP` следующий шаг не выполняйте.

Команды вводятся в Bash удалённой Astra, а не на вашем компьютере. Приглашение вида `student@astra-lab:~$` копировать не нужно. Пароль `sudo` вводится без отображения символов — это нормально.

Когда открыт nano, вводимые строки становятся текстом файла. Команды проверки выполняйте уже **после сохранения и выхода из редактора**. Полный сценарий в разделе 9 предназначен для вставки в nano, а не для выполнения непосредственно в SSH-оболочке.

Не включайте общий `set -e` в своём терминале. Ниже ошибки обрабатываются условиями и проверками. В самостоятельном сценарии настройки Bash действуют только на его процесс.

### 2. Проверьте ОС, оболочку и права

```bash
whoami
hostname
cat /etc/astra_version
printf '%s\n' "$BASH_VERSION"
sudo -v
sudo dpkg --audit
```

`whoami` показывает пользователя, `hostname` — имя машины, `cat` читает файл версии. `printf '%s\n'` выводит строку и перевод строки; `$BASH_VERSION` содержит версию Bash. `sudo -v` проверяет административные полномочия, `dpkg --audit` ищет незавершённые состояния пакетов без их исправления.

**Пример результата:**

```text
student
astra-lab
1.7.4
5.0.3(1)-release
```

После успешных `sudo -v` и `dpkg --audit` сообщений обычно нет. Если пакетная база сообщает проблему, сначала разберите её.

### 3. Пакеты, пакетные менеджеры и репозитории

Пакет `.deb` — архив файлов программы с описанием версии и зависимостей. Зависимость — другой пакет, необходимый программе. При установке могут выполняться служебные сценарии, поэтому скачивание архива и установка — разные действия.

| Инструмент | Что делает |
| --- | --- |
| `dpkg` | Ведёт базу установленных пакетов |
| `apt-get` | Получает и устанавливает пакеты из настроенных источников |
| `apt-cache` | Показывает сведения из индексов APT |
| Репозиторий | Содержит пакеты и индекс доступных версий |

APT и dpkg обычно уже установлены в Astra. Ставить другой пакетный менеджер не требуется. Источники настраиваются в `/etc/apt/sources.list` и `/etc/apt/sources.list.d/`; используйте источники именно вашего выпуска Astra. Смешивать их с Debian, Ubuntu и другим выпуском ОС ради упражнения не нужно.

`apt-get update` обновляет сведения о доступных пакетах; `install` устанавливает выбранные пакеты; `upgrade` обновляет множество установленных программ. Общий `upgrade` для этой работы не выполняется.

Проверьте инструменты:

```bash
export PATH="/usr/sbin:/usr/bin:/sbin:/bin:$PATH"
command -v bash nano df du awk tar gzip logger flock mktemp realpath stat sha256sum
command -v find findmnt head tail wc ps ls install sort cmp ln dirname basename journalctl crontab
tar --version
nano --version
```

`export PATH=...` добавляет стандартные каталоги программ к пути поиска. `command -v` показывает путь найденной программы. `--version` выводит версию, не выполняя архивацию или редактирование.

**Ожидается:** пути ко всем программам, например `/usr/bin/nano`, `/usr/bin/tar`, затем версии. `df`, `du`, `mktemp`, `realpath`, `stat`, `sha256sum` и другие базовые команды входят в `coreutils`; `flock` — в `util-linux`, `logger` — в `bsdutils`; `awk` предоставляется, например, пакетом `mawk`.

Если всё найдено, установку пропустите. Если отсутствует, например, только nano, сначала проверьте источник и план:

```bash
apt-cache policy nano
sudo apt-get --simulate install --no-install-recommends --no-upgrade nano
```

`policy` показывает установленную и доступную версии. `--simulate` показывает действия без установки; `--no-install-recommends` исключает необязательные рекомендации; `--no-upgrade` запрещает обновление уже установленного явно запрошенного пакета, но не всех зависимостей.

**Ожидается:** кандидат из разрешённого репозитория и понятный план. Если предлагаются удаления или нежелательные изменения существующих пакетов, установку не продолжайте.

При подходящем плане:

```bash
sudo apt-get install --no-install-recommends --no-upgrade --no-remove nano
```

`--no-remove` запрещает удаление пакетов. **Ожидается:** успешная установка редактора. Если отсутствует другой инструмент, сначала определите его пакет по таблице выше и посмотрите отдельный план; переустанавливать весь базовый набор не нужно.

Если корректный репозиторий доступен, но индексы устарели:

```bash
sudo apt-get update
```

**Ожидается:** обновление индексов без ошибок подписи и обязательных источников. Команда не обновляет установленные программы. На изолированном сервере потребуется разрешённый локальный источник или подготовленный комплект пакетов этого выпуска; случайные зеркала подключать нельзя.

### 4. Что проверяет df и зачем отдельно проверять каталог архива

```bash
findmnt -T /var
df -h /var
df -B1 --output=size,avail /var
df -i /var
```

`findmnt -T` находит файловую систему, содержащую путь. Если `/var` не отдельный раздел, вы увидите корневую файловую систему — это нормально. `df -h` показывает объёмы в удобных единицах. `-B1` задаёт единицу один байт; `--output=size,avail` выбирает только полный размер и доступное место. `df -i` показывает свободные inode — записи файловой системы для объектов.

**Пример сокращённого результата:**

```text
TARGET SOURCE    FSTYPE OPTIONS
/      /dev/vda1 ext4   rw,relatime
Filesystem      Size  Used Avail Use% Mounted on
/dev/vda1        30G   12G   17G  42% /
  1B-blocks       Avail
32212254720 18253611008
```

Сценарий считает целый процент как `100 × доступные байты / полный размер`, отбрасывая дробную часть. Это точнее соответствует задаче проверки доступного места, чем механическое `100 - Use%`: на файловой системе могут быть зарезервированные блоки. На пороге 10% проверяется строгое условие «меньше 10», а не «меньше или равно».

Каталог архива может находиться на другой файловой системе. Поэтому низкое место на `/var` вызывает предупреждение, а возможность записи архива дополнительно проверяется по месту назначения. Даже при большом свободном объёме причиной ошибки записи могут быть inode, квота, права или режим только для чтения.

### 5. Архив и резервная копия

`tar` собирает дерево файлов в архив; gzip сжимает получившийся поток. Расширение `.tar.gz` обозначает архив tar со сжатием gzip. Дата и время в имени помогают различать запуски, но сами по себе не доказывают успешную запись.

Сценарий сначала пишет временный файл, затем проверяет gzip и чтение оглавления tar. Только после этого публикует окончательное имя и создаёт SHA-256. Так незавершённая запись не выглядит готовой копией.

Резервная копия должна быть проверяема восстановлением. Поэтому учебный архив распакуем в **новый пустой каталог** и сравним файлы. Восстановление поверх рабочего `/etc/astra` в практику не входит.

GNU tar умеет сохранять обычные права, владельцев, ACL и расширенные атрибуты. Для реальной Astra важны также политики безопасности и корректная процедура восстановления: один архив `/etc/astra` не является полной резервной копией всей ОС, а копирование действующих файлов не даёт снимка всех настроек в один момент времени.

### 6. Как logger связывает сценарий с системным журналом

`logger` отправляет сообщение в системную подсистему журналирования. Метка `-t` позволяет найти только события нашего сценария. Параметр `-p` задаёт категорию и важность, например `user.warning`, `user.info`, `user.err`.

| Запись | Когда создаётся |
| --- | --- |
| `user.warning` | Для решения о свободном месте ниже 10%, включая явно помеченную учебную симуляцию |
| `user.info` | После успешного создания и проверки архива |
| `user.err` | При обнаруженной ошибке |

Категория `user` подходит этому упражнению. Настройки `auth`, SSH и рабочих журналов не меняются. Новые сообщения сохраняются по обычной политике сервера и при очистке стенда из системного журнала не удаляются.

## Часть 2. Создание сценария и выполнение практики

### 7. Подготовьте личный стенд

```bash
LAB_UID="$(id -u)"
LAB_USER="$(id -un)"
LAB_BASE="/var/tmp/astra-point4-$LAB_UID"
LAB_SCRIPT="$LAB_BASE/astra-backup.sh"
LAB_TAG="astra-point4-lab-$LAB_UID"
LAB_CRON="/etc/cron.d/astra-point4-$LAB_UID"
LAB_SINCE="$(date --iso-8601=seconds)"
```

`id -u` получает числовой UID, `id -un` — имя пользователя. `$(...)` подставляет результат команды. Переменные сохраняют пути и метку журнала для следующих шагов. **Ожидается:** отсутствие вывода.

```bash
if [ "$LAB_UID" -eq 0 ]; then
    printf '%s\n' 'STOP: основной маршрут выполняется обычным пользователем.'
elif [ -e "$LAB_BASE" ] || [ -L "$LAB_BASE" ]; then
    printf '%s\n' 'STOP: каталог уже существует; проверьте предыдущую работу.'
else
    mkdir -m 700 -- "$LAB_BASE" &&
        mkdir -p -- "$LAB_BASE/model/etc/astra" &&
        mkdir -m 700 -- "$LAB_BASE/report"
fi
```

`if / elif / else / fi` выбирают ветку. `-eq` сравнивает числа; `-e` находит существующий объект, `-L` — символическую ссылку, включая повреждённую. `||` означает «или», `&&` выполняет следующую команду только после успеха. `mkdir -m 700` разрешает доступ только владельцу; `-p` создаёт недостающих родителей; `--` завершает разбор флагов.

**Ожидается:** отсутствие сообщений. Верхний каталог `700` защищает всё личное дерево. При `STOP` дальше не идите.

Создайте вымышленные конфигурации:

```bash
printf 'mode=training\nservice=example\n' > "$LAB_BASE/model/etc/astra/example.conf"
printf 'retention_days=7\n' > "$LAB_BASE/model/etc/astra/retention.conf"
find "$LAB_BASE/model/etc/astra" -maxdepth 1 -type f -print
```

`printf` записывает строки; `>` создаёт или заменяет только указанные учебные файлы. `find -maxdepth 1` ограничивает поиск одним уровнем, `-type f` выбирает обычные файлы, `-print` показывает имена. **Ожидается:** два файла внутри собственного `model/etc/astra`; настоящий `/etc/astra` не затрагивается.

### 8. Откройте nano и научитесь сохранять файл

Введите команду:

```bash
nano -w "$LAB_SCRIPT"
```

`nano` открывает текстовый редактор прямо в SSH-терминале. `-w` отключает автоматическое жёсткое разбиение длинных строк при вводе. `$LAB_SCRIPT` — полный путь нового файла.

**Ожидается:** окно nano с именем `astra-backup.sh` и пустой областью текста. Внизу находятся подсказки вида `^O` и `^X`: знак `^` означает клавишу Ctrl, которую нужно удерживать вместе с указанной буквой. Буква `O` — латинская, не цифра ноль.

Дальше действуйте так:

1. Скопируйте весь код из раздела 9, начиная с `#!/bin/bash` и заканчивая последней строкой `exit 0`.
2. Вставьте его **в открытый nano**. В терминалах Linux часто используется Ctrl+Shift+V, в Windows Terminal — Ctrl+Shift+V, в PuTTY — Shift+Insert или настроенная вставка правой кнопкой. Ctrl+V внутри nano может означать перемещение по тексту, а не вставку из буфера компьютера.
3. Проверьте начало файла: перед `#!/bin/bash` не должно быть строки с приглашением терминала, символов Markdown или тройных обратных кавычек.
4. Нажмите Ctrl+O. Внизу появится запрос имени файла. Не меняйте правильный путь; нажмите Enter.
5. Дождитесь сообщения о записи строк. Затем нажмите Ctrl+X для выхода.
6. Убедитесь, что снова видно приглашение Bash. Теперь можно выполнять команды раздела 10.

Enter в редакторе добавляет новую строку, а не запускает команду. При ручном наборе сохраняйте кавычки, обратные косые черты и порядок строк. Строка Bash обычно не заканчивается точкой или точкой с запятой, если они не указаны в коде.

| Сочетание | Действие |
| --- | --- |
| Ctrl+O, затем Enter | Записать файл по указанному пути |
| Ctrl+X | Выйти; при несохранённых изменениях nano задаст вопрос |
| Ctrl+G | Открыть встроенную помощь со списком команд |
| Ctrl+X в окне помощи | Закрыть помощь и вернуться к тексту |
| Стрелки | Передвинуть курсор |
| Home / End или Ctrl+A / Ctrl+E | Начало / конец текущей строки |
| PageUp / PageDown | Переместиться по тексту на экран |
| Ctrl+W, текст, Enter | Найти строку или слово |
| Ctrl+K | Вырезать текущую строку во внутренний буфер nano |
| Ctrl+U | Вставить вырезанный текст из буфера nano |
| Alt+U | Отменить редактирование |
| Alt+E | Повторить отменённое действие |
| Ctrl+C в запросе nano | Отменить текущий запрос; в основном окне обычно показать позицию |

Если Alt перехватывается терминалом, для Meta-команды nano обычно можно нажать Esc, отпустить, затем нужную букву, например `u`. Все действующие сочетания проверяются через Ctrl+G: пользовательские настройки могут их менять.

Если при Ctrl+X спрашивается сохранение, английское `Y` означает сохранить, `N` — выйти без сохранения; при сохранении затем подтвердите имя Enter. Подсказки в локализованной версии могут отличаться — смотрите нижнюю строку. Если случайно нажали Ctrl+S и терминал перестал обновляться, Ctrl+Q может возобновить вывод при включённом управлении потоком; основной способ сохранения здесь — Ctrl+O.

### 9. Полный текст сценария для вставки в nano

Следующий блок — **содержимое файла**, а не команда для немедленного выполнения в SSH. Комментарии объясняют этапы работы.

```bash
#!/bin/bash
# Проверка места на /var и архивирование конфигураций Astra Linux.
set -u
set -o pipefail
PATH=/usr/sbin:/usr/bin:/sbin:/bin
export PATH
export LC_ALL=C
umask 077

# 1. Разрешаем только два явных режима и отдельную учебную проверку.
usage() {
    printf '%s\n' 'Usage: astra-backup.sh --lab [--test-low-space] | --system' >&2
    exit 64
}
[[ "$#" -ge 1 && "$#" -le 2 ]] || usage
MODE="$1"
SIMULATE_LOW=0
case "$MODE" in --lab|--system) ;; *) usage ;; esac
if [[ "$#" -eq 2 ]]; then
    [[ "$MODE" = --lab && "$2" = --test-low-space ]] || usage
    SIMULATE_LOW=1
fi

# 2. Выбираем фиксированные пути; учебный режим не запускается через sudo.
if [[ "$MODE" = --lab ]]; then
    [[ "$EUID" -ne 0 ]] || { printf '%s\n' 'Run --lab without sudo.' >&2; exit 1; }
    BASE="/var/tmp/astra-point4-$(id -u)"
    CONFIG_DIR="$BASE/model/etc/astra"
    BACKUP_DIR="$BASE/backup"
    LOG_TAG="astra-point4-lab-$(id -u)"
else
    [[ "$EUID" -eq 0 ]] || { printf '%s\n' 'Run --system through sudo.' >&2; exit 1; }
    CONFIG_DIR=/etc/astra
    BACKUP_DIR=/backup/astra-point4
    LOG_TAG=astra-point4-system
fi
THRESHOLD=10
TMP_ARCHIVE=''

# 3. Ошибка видна и в терминале, и, если доступно, в системном журнале.
fail() {
    printf 'ERROR: %s\n' "$*" >&2
    logger --socket-errors=on -p user.err -t "$LOG_TAG" -- "mode=$MODE error=$*" || true
    exit 1
}
cleanup() {
    if [[ -n "$TMP_ARCHIVE" ]]; then
        rm -f -- "$TMP_ARCHIVE"
    fi
}
trap cleanup EXIT
trap 'exit 129' HUP
trap 'exit 130' INT
trap 'exit 143' TERM

# 4. Проверяем источник и защищённое место назначения.
[[ -d "$CONFIG_DIR" && ! -L "$CONFIG_DIR" ]] || fail 'Source directory is missing or is a symlink.'
if [[ "$MODE" = --lab ]]; then
    [[ -d "$BASE" && ! -L "$BASE" ]] || fail 'Prepare the lab directory first.'
    [[ "$(stat -c '%u:%a' -- "$BASE")" = "$EUID:700" ]] || fail 'Lab directory must belong to the user and have mode 700.'
    SOURCE_REAL="$(realpath -e -- "$CONFIG_DIR")" || fail 'Cannot resolve source.'
    [[ "$SOURCE_REAL" = "$BASE/"* ]] || fail 'Lab source is outside the lab.'
else
    if [[ ! -e /backup && ! -L /backup ]]; then
        mkdir -m 700 -- /backup || fail 'Cannot create /backup.'
    fi
    [[ -d /backup && ! -L /backup ]] || fail '/backup must be a real directory.'
    PARENT_UID="$(stat -c '%u' -- /backup)" || fail 'Cannot inspect /backup.'
    PARENT_MODE="$(stat -c '%a' -- /backup)" || fail 'Cannot inspect /backup permissions.'
    [[ "$PARENT_UID" -eq 0 ]] || fail '/backup must belong to root.'
    (( (8#$PARENT_MODE & 0022) == 0 )) || fail '/backup is writable by group or others.'
fi
[[ ! -L "$BACKUP_DIR" ]] || fail 'Backup directory must not be a symlink.'
mkdir -p -m 700 -- "$BACKUP_DIR" || fail 'Cannot create backup directory.'
[[ "$(stat -c '%u:%a' -- "$BACKUP_DIR")" = "$EUID:700" ]] || fail 'Backup directory must belong to the current user and have mode 700.'

# 5. Не допускаем двух одновременных копирований в один каталог.
exec 9> "$BACKUP_DIR/.point4.lock" || fail 'Cannot open lock file.'
if ! flock -n 9; then
    printf '%s\n' 'Another backup is already running.' >&2
    exit 75
fi

# 6. Проверяем файловую систему настоящего /var.
FREE_PERCENT="$(df -B1 --output=size,avail -- /var |
    awk 'NR==2 { if ($1<=0) exit 1; p=100*$2/$1; if (p<0) p=0; printf "%d\n",p }')" || fail 'Cannot measure /var.'
[[ "$FREE_PERCENT" =~ ^[0-9]+$ ]] || fail 'Invalid free-space value.'
[[ "$FREE_PERCENT" -le 100 ]] || fail 'Free-space value is above 100.'
DECISION_FREE="$FREE_PERCENT"
if [[ "$SIMULATE_LOW" -eq 1 ]]; then
    DECISION_FREE=5
fi
printf 'mode=%s actual_free_pct=%s decision_free_pct=%s simulation=%s\n' \
    "$MODE" "$FREE_PERCENT" "$DECISION_FREE" "$SIMULATE_LOW"
if [[ "$DECISION_FREE" -lt "$THRESHOLD" ]]; then
    logger --socket-errors=on -p user.warning -t "$LOG_TAG" -- \
        "mode=$MODE simulation=$SIMULATE_LOW low_space=/var threshold_pct=$THRESHOLD actual_free_pct=$FREE_PERCENT decision_free_pct=$DECISION_FREE" || fail 'Cannot log low-space warning.'
fi

# 7. Перед записью проверяем место именно в каталоге архивов.
SOURCE_BYTES="$(du --summarize --apparent-size --block-size=1 -- "$CONFIG_DIR" | awk '{print $1}')" || fail 'Cannot estimate source size.'
BACKUP_AVAIL="$(df -B1 --output=avail -- "$BACKUP_DIR" | awk 'NR==2 {print $1}')" || fail 'Cannot measure backup filesystem.'
[[ "$SOURCE_BYTES" =~ ^[0-9]+$ && "$BACKUP_AVAIL" =~ ^[0-9]+$ ]] || fail 'Invalid size estimate or available space.'
RESERVE_BYTES=$((10 * 1024 * 1024))
(( BACKUP_AVAIL > SOURCE_BYTES + RESERVE_BYTES )) || fail 'Insufficient space for archive and 10 MiB reserve.'

# 8. Архивируем сначала во временный файл в том же каталоге.
DATE="$(date +'%Y-%m-%d_%H-%M-%S')" || fail 'Cannot get current time.'
ARCHIVE_NAME="astra_config_backup_${DATE}_$$.tar.gz"
FINAL_ARCHIVE="$BACKUP_DIR/$ARCHIVE_NAME"
TMP_ARCHIVE="$(mktemp "$BACKUP_DIR/.astra-config-${DATE}.XXXXXX.part")" || fail 'Cannot create temporary archive.'
SOURCE_PARENT="$(dirname -- "$CONFIG_DIR")"
SOURCE_NAME="$(basename -- "$CONFIG_DIR")"
tar --create --gzip --acls --xattrs --file="$TMP_ARCHIVE" \
    --directory="$SOURCE_PARENT" -- "$SOURCE_NAME" || fail 'tar failed; completed archive was not published.'

# 9. Проверяем сжатие и чтение оглавления до окончательного имени.
gzip --test "$TMP_ARCHIVE" || fail 'gzip integrity test failed.'
tar --list --gzip --file="$TMP_ARCHIVE" > /dev/null || fail 'Cannot read archive contents.'
ln -T -- "$TMP_ARCHIVE" "$FINAL_ARCHIVE" || fail 'Cannot publish archive without overwriting an existing path.'
rm -f -- "$TMP_ARCHIVE" || fail 'Cannot remove temporary archive name.'
TMP_ARCHIVE=''
sha256sum "$FINAL_ARCHIVE" > "$FINAL_ARCHIVE.sha256" || fail 'Cannot create checksum; archive has been retained.'

# 10. Сообщаем об успехе; ошибка logger не превращается в ложный успех.
printf 'archive=%s\n' "$FINAL_ARCHIVE"
if ! logger --socket-errors=on -p user.info -t "$LOG_TAG" -- \
    "mode=$MODE backup=success archive=$FINAL_ARCHIVE actual_free_pct=$FREE_PERCENT simulation=$SIMULATE_LOW"; then
    printf '%s\n' 'Archive exists, but success could not be written to the system log.' >&2
    exit 2
fi
exit 0
```

Сохраните файл через Ctrl+O, Enter и выйдите через Ctrl+X. **Ожидается:** возвращение к приглашению Bash, без запуска сценария на этом этапе.

### 11. Разберите команды и логику сценария

#### 11.1. Настройки Bash и параметры

`#!/bin/bash` выбирает Bash при непосредственном запуске файла. `set -u` обнаруживает обращения к незаданным переменным. `set -o pipefail` возвращает ошибку цепочки, если ошиблась не последняя команда: без него неудача `df` могла бы скрыться за успешным `awk`.

`PATH` задаёт стандартные каталоги, `LC_ALL=C` делает машинно разбираемый вывод предсказуемым. `umask 077` закрывает доступ группы и остальных к создаваемым файлам. В Bash переменные задаются без пробелов вокруг `=`; `"$ПЕРЕМЕННАЯ"` сохраняет значение одним аргументом.

`$#` — число аргументов, `$1` и `$2` — первый и второй. `case` выбирает разрешённый режим; остальные варианты приводят к `usage` и коду `64`. Дополнительный флаг разрешён только вместе с `--lab`, поэтому моделирование не включится случайно в системном режиме.

`EUID` — эффективный UID процесса: `0` означает root. Для `--lab` требуется обычный пользователь, для `--system` — root. Благодаря фиксированным путям ошибочно переданное имя каталога не станет местом удаления или источником архивации.

#### 11.2. Проверки, ошибки и завершение

`[[ ... ]]` — проверка Bash. `-d` означает каталог, `-L` — ссылку; `!` отрицает условие. `-eq`, `-ne`, `-lt`, `-le`, `-ge` сравнивают числа: равно, не равно, меньше, не больше, не меньше. `=~` проверяет регулярное выражение; `^[0-9]+$` допускает только последовательность цифр.

`|| fail 'текст'` вызывает функцию ошибки при неудаче предыдущей команды. `$*` в функции собирает текст аргументов для сообщения. `>&2` выводит ошибку в поток 2. `logger ... || true` внутри `fail` делает последнюю попытку сообщить об ошибке, не скрывая её в терминале, если журнал тоже недоступен.

`trap cleanup EXIT` вызывает очистку при завершении сценария; `HUP`, `INT`, `TERM` обрабатываются с кодами 129, 130, 143. Временное имя хранится в `TMP_ARCHIVE`, и очистка удаляет только этот файл через `rm -f --`. Проверенный конечный архив она не удаляет. После успешного переименования через создание ссылки переменная обнуляется.

При принудительном необрабатываемом завершении, например SIGKILL, обработчик не выполнится. Может остаться скрытый `.part`, но он не будет называться завершённым архивом. Удалять такие файлы можно только после проверки отсутствия работающего копирования.

#### 11.3. Каталоги и права

`realpath -e` получает существующий канонический путь. В учебном режиме источник должен остаться внутри собственного стенда. Сам каталог источника и каталог назначения не могут быть символическими ссылками.

`stat -c '%u:%a'` показывает UID владельца и права цифрами. Требование `ваш_UID:700` защищает учебные архивы от других пользователей. В системном режиме дополнительно проверяется `/backup`: владелец root, отсутствие записи для группы и остальных. `8#$PARENT_MODE` трактует строку прав как восьмеричное число, `& 0022` проверяет биты записи группы и остальных, `(( ... ))` выполняет арифметическую проверку Bash.

Существующие `/backup` и собственный каталог архивов не получают автоматическое широкое `chmod`: если права не подходят, сценарий останавливается, чтобы администратор сначала разобрал причину. Каталог `/backup/astra-point4` должен иметь права `700` и владельца root.

#### 11.4. Блокировка параллельных запусков

`exec 9> файл` открывает файл блокировки на дескрипторе 9. Это дополнительный открытый файл процесса, а не ещё одна программа. `flock -n 9` пытается взять исключительную блокировку без ожидания; `-n` означает не ждать занятую блокировку. При занятости сценарий возвращает `75`.

Блокировка освобождается при закрытии дескриптора после завершения процесса. Сам пустой файл `.point4.lock` может оставаться: его наличие не означает, что задача всё ещё работает. Удалять его для «снятия» действующей блокировки нельзя.

#### 11.5. Измерение свободного места

`df -B1 --output=size,avail -- /var` выбирает размер и доступные байты нужной файловой системы. `awk 'NR==2 ...'` обрабатывает вторую строку после заголовка: `$1` — полный размер, `$2` — доступные байты. `p=100*$2/$1` вычисляет процент; при отрицательном доступном значении используется ноль. `printf "%d\n",p` выводит целую часть.

Проверки после `awk` отклоняют пустое, нечисловое или невозможное значение. Настоящее измерение сохраняется в `FREE_PERCENT`, а решение принимается по `DECISION_FREE`. Только в явно указанной учебной проверке оно заменяется на 5.

У `logger` параметр `--socket-errors=on` включает сообщения об ошибках работы с сокетом; `-p` задаёт категорию и важность; `-t` — метку; `--` завершает флаги. Возврат успеха от logger подтверждает отправку локальной подсистеме, но не доказывает бессрочное хранение: саму запись мы отдельно ищем в журнале.

#### 11.6. Место назначения и имена

`du --summarize --apparent-size --block-size=1` оценивает логический размер источника в байтах. `df --output=avail` отдельно измеряет доступное место назначения. Резерв `10 * 1024 * 1024` — 10 MiB сверх оценки. Это предварительная защита, а не гарантия отсутствия конкурирующих записей, квоты или ошибки файловой системы.

`date +'%Y-%m-%d_%H-%M-%S'` создаёт год, месяц, день, часы, минуты и секунды. `${DATE}` подставляет переменную с явной границей имени. `$$` — PID сценария, который различает запуски в одну секунду.

`mktemp` создаёт новый временный файл с непредсказуемым фрагментом вместо `XXXXXX`. Он находится в каталоге архивов, имеет закрытые права и заканчивается `.part`. `dirname` получает родительский каталог источника, `basename` — его последнее имя.

#### 11.7. Архивирование, проверка и публикация

| Параметр | Значение |
| --- | --- |
| `tar --create` или `-c` | Создать архив |
| `--gzip` или `-z` | Сжать или прочитать сжатие gzip |
| `--file=путь` или `-f путь` | Указать файл архива |
| `--directory=путь` или `-C путь` | Перейти в каталог перед обработкой имени источника |
| `--acls` | Сохранить ACL — дополнительные правила доступа |
| `--xattrs` | Сохранить расширенные атрибуты; извлечение защищённых атрибутов зависит от прав и политики ОС |
| `--list` или `-t` | Прочитать оглавление архива |
| `gzip --test` или `-t` | Проверить целостность сжатого потока |

В архив попадает `astra/...`, а не абсолютный `/etc/astra/...`: это позволяет извлекать данные в отдельный каталог. Символические ссылки внутри дерева по умолчанию сохраняются как ссылки; их цели не обходятся автоматически. Реальные ACL и метки безопасности нельзя считать проверенными только по успешному учебному восстановлению текстовых файлов.

Любой ненулевой код `tar`, включая изменение файла во время чтения, здесь считается неудачей: готовое имя не публикуется. Ошибки не подавляются флагами игнорирования.

`ln -T временный конечный` создаёт жёсткую ссылку — второе имя того же проверенного файла. `-T` запрещает трактовать конечный путь как каталог; существующий конечный путь не перезаписывается. Оба имени находятся на одной файловой системе. Затем временное имя удаляется, конечное остаётся. Для этого способа нужна поддержка жёстких ссылок в месте назначения, например на обычных ext4 или XFS.

`sha256sum` записывает контрольную сумму рядом с архивом. При ошибке создания суммы архив сохраняется, но сценарий сообщает об ошибке. Сумма помогает обнаружить изменение содержимого относительно сохранённого значения; она не защищает от одновременной подмены обоих файлов.

### 13. Проверьте архив, права и сумму

`ls -l` показывает подробности, `-a` — скрытый файл блокировки, `-h` — удобные единицы. **Ожидается:** архив `.tar.gz`, файл `.tar.gz.sha256` с правами `-rw-------` и `.point4.lock`.

`sed -n` печатает только совпавшую строку: `s/^archive=//p` убирает префикс `archive=`. Проверки `-n` и `-f` требуют непустой путь и обычный файл; шаблон ограничивает путь нашим каталогом. **Ожидается:** список `astra/`, `astra/example.conf`, `astra/retention.conf` и строка `...tar.gz: OK`. `gzip --test` при успехе обычно молчит.

```bash

mkdir -m 700 -- "$LAB_RESTORE" &&
```

`mkdir` без `-p` откажется использовать уже существующий каталог: проверка начинается в новом месте. `tar --extract` извлекает архив; `--no-same-owner` не пытается назначать владельцев из архива, оставляя владельцем извлекающего пользователя. `cmp` сравнивает содержимое; отсутствие вывода означает совпадение.

### 15. Проверьте предупреждение без заполнения диска

```bash
bash "$LAB_SCRIPT" --lab --test-low-space > "$LAB_BASE/report/run-low-test.txt" 2>&1
LAB_RC=$?
cat "$LAB_BASE/report/run-low-test.txt"
printf 'Код завершения: %s\n' "$LAB_RC"
```

**Пример результата:**


`actual_free_pct` показывает настоящую оценку свободного места; `decision_free_pct=5` и `simulation=1` явно обозначают моделирование. Никакие данные на диск для уменьшения свободного места не записываются, кроме обычного маленького архива и отчёта. После предупреждения сценарий продолжает создание архива, если место назначения позволяет.

Найдите свои сообщения:

```bash

```

`--identifier` выбирает метку, `--since` — время после начала работы, `--no-pager` отключает постраничный просмотр, `--output=short-iso` задаёт формат времени. **Ожидается:** сообщения `backup=success` и предупреждение с `simulation=1 low_space=/var`.

Для выборки только предупреждений можно добавить фильтр точной важности:


`PRIORITY=4` выбирает именно warning. **Ожидается:** учебное предупреждение; при действительно низком месте могут присутствовать и предупреждения обычного запуска с `simulation=0`.

Если записи сразу не появились, повторите чтение через секунду. При другой схеме журналирования проверьте доступный текстовый системный журнал:

```bash

    sudo tail -n 150 /var/log/syslog | grep -F -- "$LAB_TAG"
fi
```

`tail -n 150` ограничивает чтение последними 150 строками, `grep -F` ищет буквальную метку. **Ожидается:** доступные сообщения или отсутствие совпадений. Наличие `/var/log/syslog` зависит от конфигурации. Не очищайте журналы и не перезапускайте сборщик ради упражнения; при отсутствии доставки разберите настройки с администратором.

### 16. Посмотрите выполнение через bash -x

Режим отладки используется только на учебных данных:

```bash
bash -x "$LAB_SCRIPT" --lab > "$LAB_BASE/report/trace-lab.txt" 2>&1
LAB_RC=$?
printf 'Код отладочного запуска: %s\n' "$LAB_RC"
tail -n 35 -- "$LAB_BASE/report/trace-lab.txt"
```

`bash -x` печатает выполняемые команды после подстановки переменных. `tail -n 35` показывает конец трассировки. **Ожидается:** код `0`, команды проверки архива, сумма, запись успеха и завершение. Строки с `+` — диагностический вывод Bash; их не нужно копировать обратно в терминал.

Отладочный запуск действительно создаёт ещё один архив, а не просто показывает план. На настоящих конфигурациях подробная трассировка может раскрывать служебные пути и параметры, поэтому для отчёта используйте учебный запуск.

### 17. Подключите ежедневный учебный запуск

Проверим Cron:

```bash
systemctl is-active cron.service
```

**Ожидается:** `active`. Если пакет отсутствует, сначала посмотрите план установки `cron` так же, как для nano в разделе 3. Установка или запуск Cron могут активировать существующие задания сервера. Если служба намеренно остановлена, сначала выясните причину; запускать её без разбора не следует.

Для учебной ВМ, где Cron должен работать, после устранения причины остановки:

```bash
sudo systemctl start cron.service && systemctl is-active cron.service
```

`start` запускает службу, а не перезапускает её. **Ожидается:** `active`.

Подготовьте отдельное ежедневное задание:

```bash
if [[ "$LAB_USER" =~ ^[a-zA-Z_][a-zA-Z0-9_-]*\$?$ ]]; then
    printf 'SHELL=/bin/bash\nPATH=/usr/sbin:/usr/bin:/sbin:/bin\nMAILTO=""\n15 2 * * * %s /bin/bash "%s" --lab >> "%s/report/daily-job.log" 2>&1\n' \
        "$LAB_USER" "$LAB_SCRIPT" "$LAB_BASE" > "$LAB_BASE/cron-lab.conf"
    cat "$LAB_BASE/cron-lab.conf"
else
    printf '%s\n' 'STOP: пример расписания рассчитан на простое локальное имя пользователя.'
fi
```

Шаблон допускает простое локальное имя; сложные доменные варианты требуют отдельной адаптации. **Пример результата:**

```cron
SHELL=/bin/bash
PATH=/usr/sbin:/usr/bin:/sbin:/bin
MAILTO=""
15 2 * * * student /bin/bash "/var/tmp/astra-point4-1000/astra-backup.sh" --lab >> "/var/tmp/astra-point4-1000/report/daily-job.log" 2>&1
```

Пять полей означают: минута `15`, час `2`, любой день месяца, любой месяц, любой день недели — ежедневно в 02:15 по часам сервера. Следующее поле задаёт пользователя: оно обязательно в `/etc/cron.d`, но отсутствует в личном `crontab -e`.

`SHELL` выбирает оболочку, `PATH` задаёт поиск программ, `MAILTO=""` отключает почтовые уведомления этого файла. `>>` дописывает вывод, `2>&1` сохраняет ошибки там же. Время вычисляется внутри сценария, поэтому специальные для Cron символы `%` не попадают в строку задания.

Установите файл без перезаписи существующего:

```bash
sudo sh -c 'umask 022; set -C; cat > "$1"' sh "$LAB_CRON" < "$LAB_BASE/cron-lab.conf" &&
    sudo stat -c '%U %a %n' -- "$LAB_CRON"
```

`sudo sh -c` даёт права только команде записи. Первый `sh` после текста задаёт имя оболочки, следующий аргумент становится `$1`. `<` подаёт подготовленный файл на ввод `cat`. `umask 022` даёт новому файлу права `644`; `set -C` запрещает перезапись существующего обычного файла через `>`.

**Ожидается:** `root 644 /etc/cron.d/astra-point4-1000`. В имени нет точки. Cron автоматически обнаружит файл; перезапуск не требуется. При конфликте остановитесь, не удаляйте неизвестный файл.

Сценарий уже проверен вручную. Установка расписания **не означает немедленный запуск**: ближайший будет в следующие 02:15. Для подтверждения именно автоматического выполнения позже проверьте `daily-job.log`, новый архив и запись logger с соответствующим временем. До этого в отчёте указывайте «ежедневное задание подключено, сценарий проверен вручную».

Учебный каталог `/var/tmp` сохраняется после обычного выхода из SSH, но может очищаться политикой системы. Это временный стенд; для длительной эксплуатации нужен отдельный защищённый установленный сценарий, как в разделе 19.

### 18. Создайте настоящий архив /etc/astra, если это требуется

Этот раздел — отдельный маршрут после успешной учебной проверки. Системный режим читает настоящие настройки и создаёт закрытую копию в `/backup/astra-point4/`.

Сначала проверьте наличие источника и возможного места назначения:

```bash
sudo test -d /etc/astra && printf '%s\n' 'Каталог /etc/astra существует.'
sudo du -sh /etc/astra
if sudo test -d /backup; then
    sudo stat -c '%U %a %n' -- /backup
    df -h /backup
else
    printf '%s\n' '/backup ещё не создан; сценарий создаст его с закрытыми правами.'
fi
```

`du -s` показывает итог, `-h` — удобные единицы. `test -d` проверяет каталог без показа содержимого. **Ожидается:** существующий `/etc/astra`, его размер и сведения о `/backup` либо сообщение об отсутствии каталога. Если источник отсутствует, не создавайте там вымышленные файлы: используйте учебный режим и укажите это в отчёте.

Запустите без `-x`:

```bash
sudo /bin/bash "$LAB_SCRIPT" --system
LAB_SYSTEM_RC=$?
printf 'Код системного запуска: %s\n' "$LAB_SYSTEM_RC"
```

**Ожидается:** настоящее измерение `/var`, путь `archive=/backup/astra-point4/astra_config_backup_...tar.gz` и код `0`. При ошибке прав или политики безопасности её нужно разбирать; отключать защиту Astra не следует. Сценарий сам проверяет доступное место и защищённость каталогов.

```bash
sudo ls -lah /backup/astra-point4
sudo find /backup/astra-point4 -maxdepth 1 -type f -name '*.sha256' -exec sha256sum --check {} +
sudo journalctl --identifier=astra-point4-system --since='10 minutes ago' --no-pager --output=short-iso
```

`find` выбирает файлы сумм только в собственном подкаталоге; `-exec ... {} +` передаёт найденные пути программе проверки: `{}` — место подстановки, `+` объединяет их в один вызов. `--since='10 minutes ago'` ограничивает выборку журнала десятью минутами. **Ожидается:** закрытый архив и его сумма, `OK` для сумм и запись `mode=--system backup=success`. Это именно копия `/etc/astra` внутри `/backup/`. Учебная симуляция в системном режиме запрещена.

Не запускайте извлечение этого архива поверх `/etc/astra`. Подготовка промышленного восстановления с метками и действующими службами выходит за рамки учебной проверки.

### 19. Ежедневный системный режим с защищённым сценарием

Этот раздел нужен только если вы выполнили раздел 18 и хотите подключить ежедневное копирование настоящего `/etc/astra`. Для него используется **установленная копия сценария root**, а не изменяемый файл обычного пользователя.

```bash
if sudo test -e /usr/local/sbin/astra-point4-backup || sudo test -L /usr/local/sbin/astra-point4-backup; then
    printf '%s\n' 'STOP: имя установленного сценария уже занято.'
else
    sudo install -o root -g root -m 750 -- "$LAB_SCRIPT" /usr/local/sbin/astra-point4-backup &&
        sudo /bin/bash -n /usr/local/sbin/astra-point4-backup &&
        sudo stat -c '%U %G %a %n' -- /usr/local/sbin/astra-point4-backup
fi
```

`install` копирует файл: `-o root` задаёт владельца, `-g root` — группу, `-m 750` — чтение/запуск root и группы root, запись только root. **Ожидается:** `root root 750 ...`. Каталог `/usr/local/sbin` тоже должен принадлежать root и быть закрыт для записи обычными пользователями; проверьте это перед подключением root-задания:

```bash
sudo stat -c '%U %a %n' -- /usr/local /usr/local/sbin
```

**Ожидается:** root и права без записи группы/остальных, обычно `755`. При другой политике сначала разберите её с администратором, а не меняйте чужие права автоматически.

Подготовьте отдельное root-задание на 02:20:

```bash
cat > "$LAB_BASE/cron-system.conf" <<'EOF'
SHELL=/bin/bash
PATH=/usr/sbin:/usr/bin:/sbin:/bin
MAILTO=""
20 2 * * * root /usr/local/sbin/astra-point4-backup --system >> /backup/astra-point4/daily-job.log 2>&1
EOF
sudo sh -c 'umask 022; set -C; cat > "$1"' sh /etc/cron.d/astra-point4-system < "$LAB_BASE/cron-system.conf" &&
    sudo stat -c '%U %a %n' -- /etc/cron.d/astra-point4-system
```

**Ожидается:** `root 644 /etc/cron.d/astra-point4-system`. Время отличается от учебного, но оба задания независимы; для рабочего использования учебное расписание нужно убрать. Настоящий каталог `/backup/astra-point4` уже должен существовать после успешного ручного запуска: иначе перенаправление журнала Cron не сможет открыть файл.

Это ежедневное задание остаётся активным после закрытия SSH и перезагрузки. Сценарий не удаляет старые архивы автоматически. Сроки хранения и отдельное хранилище выбираются по условиям эксплуатации; одинаковый диск с исходными данными не защищает от отказа этого диска.

#### 4.1. Полный текст Bash-сценария

Используйте сохранённый `astra-backup.sh` из раздела 9 с комментариями. В отчёте укажите выбранный режим:

- учебный: настоящий контроль файловой системы `/var`, вымышленные конфигурации, архивы внутри личного стенда;

Эти варианты нельзя обозначать как одно и то же действие. Если выполнен только учебный маршрут, не утверждайте, что уже создана копия настоящих настроек безопасности.

```bash
sudo journalctl --identifier="$LAB_TAG" --since="$LAB_SINCE" --no-pager --output=short-iso \
```

`wc -l` считает строки. **Ожидается:** непустой файл с собственными событиями. Пустая выборка требует проверки доставки, а не добавления вымышленного вывода.

### 21. Если SSH оборвался

Подключитесь к той же машине под тем же обычным пользователем. Повторите **только блок переменных раздела 7**, не команды создания каталогов и файлов. Для чтения прежних событий уберите `--since` или укажите прежнее время начала.

Проверьте результат:

```bash
ls -lah "$LAB_BASE/backup"
ps -u "$LAB_UID" -o pid,args | grep -F -- "$LAB_SCRIPT"
```

`ps -u` выбирает процессы пользователя, `-o pid,args` — PID и командную строку. Сам `grep` может присутствовать в выводе; смотрите имя команды. **Ожидается:** архивы уже завершившегося запуска или текущий процесс, если работа ещё идёт.

Не завершайте все процессы `tar`, `bash` или `gzip` на сервере. Сценарий использует блокировку: повторный запуск не начнёт вторую запись в тот же каталог при занятой блокировке. После разрыва ручной запуск мог остановиться; окончательное имя, проверка gzip и сумма важнее самого наличия `.part`.

Ежедневные задания Cron работают независимо от SSH. Если они были подключены, сначала отключайте свои задания, потом удаляйте стенд. После перезагрузки основной учебный каталог может сохраниться в `/var/tmp`, но это зависит от политики очистки; root-архивы в `/backup` не удаляются этой практикой.

### 22. Разбор ошибок

| Сообщение или ситуация | Что означает и что делать |
| --- | --- |
| `Usage: ...`, код 64 | Пропущен режим или переданы неверные аргументы |
| `Run --lab without sudo` | Учебный маршрут запущен от root; вернитесь к обычному пользователю |
| `Run --system through sudo` | Для чтения настоящих конфигураций и закрытого `/backup` нужны административные права |
| `Cannot measure /var` | Ошибка df, недоступный путь или неверный вывод; не подставляйте произвольное число как реальное измерение |
| `Insufficient space...` | В месте назначения недостаточно пространства по предварительной оценке |
| `Another backup...`, код 75 | Блокировка занята; дождитесь своего процесса, не удаляйте lock-файл |
| `Permission denied` | Проверьте права и политики Astra; не используйте `chmod 777` |

| Архив есть, код 2 | Создание прошло, но успех не удалось записать через logger; проверьте журналирование |
| `gzip` или сумма сообщает ошибку | Не используйте такой файл для восстановления без разбора причины |
| Нет `/etc/astra` | Не создавайте поддельный рабочий каталог; выполните учебный маршрут и укажите адаптацию |

### 23. Завершение и очистка

#### 23.1. Сначала удалите учебное задание Cron

Если выполняли раздел 17:

```bash
if [ "$LAB_CRON" = "/etc/cron.d/astra-point4-$(id -u)" ] &&
    sudo cmp -s -- "$LAB_BASE/cron-lab.conf" "$LAB_CRON"; then
    sudo rm -- "$LAB_CRON" && printf '%s\n' 'Учебное ежедневное задание удалено.'
else
    printf '%s\n' 'STOP: путь или содержимое задания не совпадает; проверьте файл.'
fi
```

`cmp -s` сравнивает молча и разрешает удаление только при совпадении. **Ожидается:** подтверждение. Если расписание не подключали, этот блок пропустите. Саму службу Cron не останавливайте.

Подождите одну-две минуты, чтобы Cron заметил удаление и завершил уже начатое короткое учебное копирование. Перед удалением каталога убедитесь в отсутствии своего выполняющегося сценария командой `ps` из раздела 21. Не удаляйте каталог, пока архивирование работает.

#### 23.2. Отдельно отключите системное задание, если его создавали

Для завершения именно практики после раздела 19:

```bash
if sudo cmp -s -- "$LAB_BASE/cron-system.conf" /etc/cron.d/astra-point4-system; then
    sudo rm -- /etc/cron.d/astra-point4-system &&
        printf '%s\n' 'Системное ежедневное задание практики удалено.'
else
    printf '%s\n' 'STOP: сначала проверьте установленное системное расписание.'
fi
```

**Ожидается:** подтверждение. При намерении оставить реальную ежедневную задачу работающей этот шаг не выполняйте; установленный root-сценарий и `/backup/astra-point4` тогда должны сохраняться. Удаление личного учебного каталога не меняет установленную копию сценария.

Если системное расписание удалено и соответствующий запуск уже завершён, установленную копию можно убрать после сравнения:

```bash
if ! sudo test -e /etc/cron.d/astra-point4-system &&
    sudo cmp -s -- "$LAB_SCRIPT" /usr/local/sbin/astra-point4-backup; then
    sudo rm -- /usr/local/sbin/astra-point4-backup
else
    printf '%s\n' 'STOP: сценарий ещё используется или его содержимое изменилось.'
fi
```

**Ожидается:** отсутствие сообщений. Команда удаляет только установленный файл этого упражнения, не каталоги `/usr/local` и не архивы. Созданные настоящие копии `/backup/astra-point4` автоматически не удаляются.

#### 23.3. Удалите личный стенд после сохранения результатов

```bash
if [ "$LAB_BASE" = "/var/tmp/astra-point4-$(id -u)" ] &&
    [ ! -e "$LAB_CRON" ] && [ ! -L "$LAB_CRON" ]; then
    cd "$HOME" && rm -rI -- "$LAB_BASE"
else
    printf '%s\n' 'STOP: сначала проверьте путь и удаление учебного расписания.'
fi
```

`!` отрицает проверку. `cd "$HOME"` выводит оболочку из удаляемого дерева. `rm -r` удаляет дерево рекурсивно; заглавная `-I` запрашивает подтверждение. **Ожидается:** вопрос об удалении вашего `/var/tmp/astra-point4-UID`; проверьте путь и подтвердите. Для этого шага `sudo` не нужен.

Учебные архивы и отчёты исчезнут вместе со стендом. Системные пакеты, реальные конфигурации, настоящие резервные копии и история журналов сохраняются.

### 24. Ответы на частые вопросы

**Можно ли сразу перейти к коду?** Для первого прохождения начните с раздела 2: нужны инструменты, переменные и учебные каталоги. Код раздела 9 вставляется внутрь nano, а не запускается в терминале.

**Это работает, если `/var` не отдельный раздел?** Да: df проверяет файловую систему, содержащую `/var`. В отчёте называйте её именно так, если отдельного раздела нет.

**Почему предупреждение не останавливает копирование?** Это соответствует заданию: при низком месте нужно сообщить о проблеме, затем попытаться сохранить конфигурации. Дополнительная проверка места назначения не допускает заведомо недостаточную запись.

**Нужно ли каждый день вводить пароль sudo?** Нет: учебное Cron-задание работает обычным пользователем. Системное задание запускается Cron от root и использует установленный root-сценарий. Встраивать пароль в файл или добавлять произвольные разрешения `NOPASSWD` не требуется.

**Почему в архиве папка `astra`, а не абсолютный путь?** Относительные имена позволяют восстановить содержимое в отдельном месте и сначала проверить его. Для рабочей конфигурации процедура восстановления должна отдельно учитывать владельцев, ACL, атрибуты и политики безопасности.

**Успешная сумма доказывает полноценную резервную копию?** Она доказывает совпадение с сохранённой суммой. Проверка gzip, оглавление и восстановление дополняют проверку, но полный аварийный план ОС включает больше данных и требований.
