# Bash-скрипты и синтаксис: подробный гайд для начинающих на Astra Linux SE 1.7

Вся работа выполняется **на одной удалённой Astra Linux Special Edition 1.7 по SSH**, в Bash обычного пользователя. Открывать второй сервер, устанавливать графический редактор и менять настройки SSH не требуется.

Начнём с устройства терминала и консольного редактора nano. Создадим первый сценарий, научимся сохранять и запускать его, затем последовательно разберём основные конструкции Bash. В конце соберём самостоятельный сценарий отчёта по учебным файлам: с параметрами, проверкой ввода, циклом, функциями, обработкой ошибок и очисткой временного файла.

Все записи и удаления в упражнениях относятся к личному каталогу `/var/tmp/astra-bash-UID`. Системные службы, сеть, рабочие конфигурации и пакетная база в основном маршруте не изменяются. Административные права могут понадобиться только для установки отсутствующего nano или другого инструмента из разрешённого репозитория.

Примеры вывода условные. Пользователь называется `student`, UID равен `1000`, узел — `astra-lab`. Команды сами получают ваш UID; имена и время могут отличаться.

## 1. Как пользоваться этим гайдом

Читайте разделы по порядку. Первый блок проверки окружения находится в разделе 3. Скопируйте один полный блок, выполните его и сравните результат. При `STOP` или неожиданной ошибке сначала разберите причину.

У каждого примера указано, куда он вводится: **в терминал** или **в файл внутри nano**. Когда открыт редактор, набираемый текст становится содержимым файла, а не выполняется как команда. Примеры вывода предназначены только для чтения.

Многострочный блок с `<<'EOF'` вставляйте целиком, включая завершающую строку `EOF`. Определение функции тоже вставляется целиком. Если Bash показывает `>` после незаконченного ввода, Ctrl+C отменяет незавершённую команду; затем можно вставить её заново.

Не включайте `set -e` и `set -u` в своём SSH-терминале ради этого курса. Их действие разберём в отдельных дочерних процессах и сценариях. Так учебная ошибка не завершит текущую оболочку.

Основные упражнения выполняются в разделах 3–31. Раздел 32 содержит готовый итоговый сценарий и его проверки; далее — типичные ошибки, восстановление после разрыва SSH и очистка. Установку пакетов выполняйте только при отсутствии программ.

## 2. Терминал, оболочка и сценарий — разные вещи

**Терминал** показывает текст и передаёт нажатия клавиш. **SSH** доставляет команды на удалённую машину. **Bash** — командный интерпретатор: разбирает текст и запускает команды. **Сценарий**, или скрипт, — текстовый файл с последовательностью таких команд.

Например, приглашение:

```text
student@astra-lab:~$
```

означает, что оболочка ждёт команду. Имя пользователя, имя машины, `~` и завершающий `$` — элементы приглашения, а не часть копируемой команды. `~` обычно обозначает домашний каталог. Вид приглашения на вашей машине может быть другим.

Один и тот же текст `printf 'Привет\n'` можно выполнить непосредственно в Bash или сохранить в сценарий. В первом случае результат появляется сразу после Enter. Во втором сначала создаётся файл, затем отдельно запускается его интерпретатор.

| Обозначение в объяснении | Что нажать или сделать |
| --- | --- |
| Enter | Подтвердить команду в оболочке или добавить строку в редакторе |
| Ctrl+C | В терминале обычно прервать текущую команду; в nano действие зависит от контекста |
| Tab | Дополнить имя файла или команды в Bash; иногда второй Tab показывает варианты |
| Стрелка вверх | Вернуть предыдущую команду для просмотра и редактирования |
| Ctrl+A / Ctrl+E в Bash | Перейти в начало / конец вводимой строки при стандартных настройках readline |
| Ctrl+U в Bash | Удалить текст от начала строки до курсора; в nano это другая команда |
| Ctrl+L в Bash | Перерисовать или очистить экран, сохранив историю команд |
| Ctrl+D на пустой строке Bash | Передать конец ввода; это может завершить оболочку и SSH-сеанс |

Сочетания могут перехватываться вашим терминалом. Для упражнений достаточно обычного Enter, Tab, Ctrl+C и отдельно описанных команд nano. Ctrl+C не является универсальной командой копирования текста в терминале.

## 3. Проверьте Bash и редактор

Вводите в SSH-терминале:

```bash
whoami
hostname
cat /etc/astra_version
printf 'Bash: %s\n' "${BASH_VERSION:-не определён}"
command -v bash nano
```

`whoami` показывает пользователя, `hostname` — машину. `cat` читает файл версии. `printf` подставляет строку вместо `%s`, а `\n` добавляет перевод строки. `${BASH_VERSION:-не определён}` выводит запасной текст, если переменная не задана или пустая. `command -v` показывает путь найденной программы.

**Пример результата:**

```text
student
astra-lab
1.7.4
Bash: 5.0.3(1)-release
/bin/bash
/usr/bin/nano
```

Если Bash не определён, сначала введите `bash` и Enter: запустится Bash внутри текущего сеанса. `$SHELL` описывает настроенную оболочку учётной записи и не всегда доказывает, какой интерпретатор выполняет команды сейчас.

Основной маршрут рассчитан на обычного пользователя, не root. Сценарии не требуют административных полномочий.

### Если nano отсутствует

Пакет `.deb` содержит программу и сведения о зависимостях. APT получает пакеты из уже настроенных репозиториев Astra. Устанавливать другой пакетный менеджер не нужно; не подключайте ради редактора репозитории Debian, Ubuntu или другого выпуска Astra.

Сначала посмотрите доступную версию и план:

```bash
apt-cache policy nano
sudo apt-get --simulate install --no-install-recommends --no-upgrade nano
```

`policy` показывает установленную и доступную версии. `sudo` выполняет команду с административными правами и при необходимости запрашивает пароль без отображения символов. `--simulate` не применяет изменения; `--no-install-recommends` исключает необязательные рекомендации; `--no-upgrade` запрещает обновление уже установленного явно запрошенного пакета, но не всех зависимостей.

**Ожидается:** кандидат из разрешённого источника и понятный план. Если действительно нужна установка и план подходит:

```bash
sudo apt-get install --no-install-recommends --no-upgrade --no-remove nano
```

`--no-remove` запрещает удаления. **Ожидается:** успешная установка. При недоступном источнике сначала нужен разрешённый репозиторий вашего выпуска. `apt-get update` обновляет индексы, а не программы; общий `upgrade` для изучения Bash не требуется.

## 4. Создайте личный учебный каталог

```bash
BASHG_UID="$(id -u)"
BASHG_BASE="/var/tmp/astra-bash-$BASHG_UID"
if [ "$BASHG_UID" -eq 0 ]; then
    printf '%s\n' 'STOP: используйте обычного пользователя.'
elif [ -e "$BASHG_BASE" ] || [ -L "$BASHG_BASE" ]; then
    printf '%s\n' 'STOP: каталог уже существует; проверьте предыдущую работу.'
else
    mkdir -m 700 -- "$BASHG_BASE" &&
        mkdir -m 700 -- "$BASHG_BASE/scripts" "$BASHG_BASE/data" "$BASHG_BASE/report"
fi
```

`id -u` получает UID; `$(...)` подставляет результат. Переменные `BASHG_...` сохраняют учебные значения, не заменяя системные `HOME` и `PATH`. `-eq` сравнивает числа. `-e` проверяет существующий объект, `-L` — ссылку, в том числе повреждённую. `||` означает «или», `&&` выполняет следующий шаг только после успеха.

`mkdir -m 700` создаёт каталог с чтением, записью и входом только для владельца. `--` заканчивает разбор флагов. **Ожидается:** отсутствие вывода. При `STOP` не выполняйте дальнейшее создание файлов поверх прежнего стенда.

```bash
cd -- "$BASHG_BASE"
pwd
printf 'alpha\nbeta\ngamma\n' > "$BASHG_BASE/data/alpha.txt"
printf 'one\n' > "$BASHG_BASE/data/beta.txt"
printf 'first\nsecond\n' > "$BASHG_BASE/data/file with spaces.txt"
ls -l -- "$BASHG_BASE/data"
```

`cd` меняет текущий каталог, `pwd` показывает его. `>` создаёт или заменяет указанный учебный файл. Кавычки удерживают путь с пробелами целиком. `ls -l` показывает подробный список.

**Ожидается:** путь `/var/tmp/astra-bash-1000` и три файла. Позднее итоговый сценарий будет читать именно эти три `.txt`. Остальные результаты будем писать в `report`, чтобы не менять набор входных данных.

## 5. Откройте nano: первый вход в консольный редактор

В терминале выполните:

```bash
nano -w "$BASHG_BASE/scripts/hello.sh"
```

`nano` открывает редактор, `-w` отключает автоматическое жёсткое разбиение длинных строк. Путь задаёт новый файл. **Ожидается:** окно редактора с именем `hello.sh`, пустой областью текста и подсказками внизу.

На этом этапе Enter уже не запускает команду: он добавляет строку в файл. Стрелки двигают курсор. Если хотите написать текст вручную, просто начинайте печатать — отдельный «режим вставки», как в vi, не нужен.

Вставьте **в nano** следующий текст, начиная с первой строки. Тройные обратные кавычки из оформления Markdown не копируются.

```bash
#!/bin/bash
# Первый учебный сценарий.
printf 'Привет из Bash!\n'
printf 'Пользователь: %s\n' "$(id -un)"
```

В терминалах Linux и Windows Terminal для вставки часто используется Ctrl+Shift+V. В PuTTY — Shift+Insert или настроенная вставка правой кнопкой. Внутри nano Ctrl+V может означать переход по экрану, поэтому сначала используйте сочетание вставки вашего терминала.

**Ожидается:** четыре строки в редакторе. Перед `#!/bin/bash` нет приглашения терминала и лишних символов.

### Как сохранить и выйти

1. Нажмите **Ctrl+O**: удерживайте Ctrl и нажмите латинскую букву O, не цифру 0.
2. Внизу появится запрос имени файла. Если путь правильный, нажмите **Enter**.
3. Дождитесь сообщения о записанных строках.
4. Нажмите **Ctrl+X**.
5. Убедитесь, что снова видно приглашение Bash. Только теперь вводите следующие команды терминала.

Знак `^` в подсказках nano означает Ctrl: `^O` — Ctrl+O. `M-` означает Meta, обычно Alt. Например, `M-U` — Alt+U. Если Alt перехватывается, часто можно нажать Esc, отпустить и затем нажать нужную букву.

### Если nano спрашивает про несохранённые изменения

При Ctrl+X редактор может спросить, сохранять ли файл. В английском интерфейсе `Y` — да, `N` — нет; при сохранении затем подтвердите имя Enter. В локализованном интерфейсе смотрите реальные подписи внизу. Ctrl+C в таком запросе позволяет отменить запрос и вернуться к редактированию.

### Нужные сочетания nano

| Сочетание | Действие |
| --- | --- |
| Ctrl+O, Enter | Сохранить по выбранному пути |
| Ctrl+X | Выйти из файла; при несохранённых изменениях появится вопрос |
| Ctrl+G | Открыть встроенную помощь |
| Ctrl+X в помощи | Вернуться из помощи к тексту |
| Стрелки | Переместить курсор |
| Home / End или Ctrl+A / Ctrl+E | Начало / конец текущей строки |
| PageUp / PageDown | Перейти на экран выше / ниже |
| Ctrl+W, текст, Enter | Найти текст |
| Alt+W | Повторить поиск вперёд при стандартных назначениях |
| Ctrl+\ | Начать замену; отвечайте на запросы поиска и замены по нижней строке |
| Ctrl+K | Вырезать текущую строку или выделенный фрагмент |
| Ctrl+U | Вставить из внутреннего буфера nano |
| Alt+6 | Скопировать строку или выделение во внутренний буфер |
| Alt+A | Начать или закончить выделение; затем используйте стрелки |
| Alt+U | Отменить редактирование |
| Alt+E | Повторить отменённое |
| Ctrl+C в основном окне | Обычно показать позицию; в запросе — отменить запрос |

Буфер nano и буфер обмена вашего компьютера — не одно и то же. Ctrl+K/Ctrl+U работают внутри редактора; вставка из чата производится средствами терминала.

Клавиши могут переназначаться конфигурацией редактора. Ctrl+G показывает справку именно установленного nano. Если случайно нажали Ctrl+S и вывод перестал обновляться при включённом управлении потоком, Ctrl+Q может возобновить его. Для сохранения в этой практике используйте Ctrl+O.

## 6. Проверьте файл и выполните первый запуск

В Bash после выхода из nano:

```bash
cat "$BASHG_BASE/scripts/hello.sh"
bash -n "$BASHG_BASE/scripts/hello.sh"
bash "$BASHG_BASE/scripts/hello.sh"
```

`cat` показывает содержимое; `bash -n` проверяет синтаксис без выполнения; `bash файл` запускает команды из файла. **Ожидается:** сначала текст, затем проверка без сообщений и результат:

```text
Привет из Bash!
Пользователь: student
```

`#!/bin/bash` называется shebang: при непосредственном запуске файла ОС выбирает указанный интерпретатор. Строка `# Первый...` — комментарий. `printf` выводит текст; `$(id -un)` запускает `id` с флагами выбора пользователя `-u` и имени `-n`.

Разрешите непосредственный запуск:

```bash
chmod 700 -- "$BASHG_BASE/scripts/hello.sh"
"$BASHG_BASE/scripts/hello.sh"
```

`chmod 700` даёт владельцу чтение, запись и выполнение, остальным — ничего. **Ожидается:** тот же результат. При запуске через `bash файл` интерпретатор читает файл; исполняемый бит самого `.sh` для такого чтения не требуется. При непосредственном запуске нужен и подходящий shebang, и право выполнения.

Расширение `.sh` удобно человеку, но само по себе не выбирает интерпретатор. Bash-конструкции нельзя автоматически запускать через `sh`: на Astra `/bin/sh` может быть другой оболочкой.

Когда текущий каталог совпадает с каталогом файла, форма `./hello.sh` указывает «файл отсюда». Просто `hello.sh` ищется в `PATH`, куда текущий каталог обычно не включён. Добавлять `.` в системный путь ради упражнения не нужно.

## 7. Синтаксис команды, аргументы и комментарии

```bash
printf '%s\n' 'Один аргумент с пробелами' 'Второй аргумент'
ls -l -- "$BASHG_BASE/scripts/hello.sh"
```

У команды сначала идёт имя, затем флаги и аргументы. У `printf` первый аргумент — формат, следующие — значения. В `ls` флаг `-l` включает подробный вывод, `--` завершает флаги, последний аргумент — путь.

**Ожидается:** две строки текста и подробности о файле. Пробелы между аргументами важны: они разделяют слова; внутри кавычек пробел становится частью одного аргумента.

`#` в начале строки или после разделителя начинает комментарий, если не находится внутри кавычек. `#!/bin/bash` — особая первая строка. Символ `#` внутри `'текст # текст'` остаётся обычным текстом.

Длинную команду можно продолжить обратной косой чертой перед переводом строки:

```bash
printf 'Каталог: %s\nФайл: %s\n' \
    "$BASHG_BASE" \
    "$BASHG_BASE/scripts/hello.sh"
```

**Ожидается:** две строки с путями. После завершающего `\` не должно быть пробела: иначе он экранирует пробел, а не перевод строки. В `if`, `for` и функциях переносы часто разрешены самой грамматикой и дополнительная `\` не нужна.

## 8. Переменные: присваивание и подстановка

```bash
BASHG_NAME='Анна Иванова'
BASHG_COUNT=3
printf 'Имя: %s\nКоличество: %s\n' "$BASHG_NAME" "$BASHG_COUNT"
```

**Ожидается:** имя целиком и число `3`. Присваивание пишется **без пробелов вокруг `=`**. Для чтения добавляется `$`, для присваивания он перед именем не ставится.

| Правильно | Почему |
| --- | --- |
| `name=value` | Присвоить значение переменной |
| `name='два слова'` | Сохранить пробел |
| `printf '%s\n' "$name"` | Подставить значение одним аргументом |
| `printf '%s\n' "${name}_copy"` | Обозначить границу имени переменной |

Запись `name = value` оболочка пытается выполнить как команду `name` с аргументами, а не как присваивание. Имена чувствительны к регистру: `name` и `NAME` — разные переменные. В обычном имени используйте латинские буквы, цифры и `_`, не начиная с цифры.

Не заменяйте системные переменные `HOME`, `PATH`, `IFS` произвольными учебными значениями. Наши демонстрационные имена имеют префикс `BASHG_`.

## 9. Кавычки: главное правило работы с данными

```bash
printf '%s\n' '$BASHG_NAME'
printf '%s\n' "$BASHG_NAME"
printf '<%s>\n' $BASHG_NAME
printf '<%s>\n' "$BASHG_NAME"
```

**Ожидается при обычном разделителе слов:**

```text
$BASHG_NAME
Анна Иванова
<Анна>
<Иванова>
<Анна Иванова>
```

Одинарные кавычки сохраняют буквальный текст. Двойные допускают подстановку переменных и команд, но защищают значение от разбиения на слова и обычного разворачивания шаблонов файлов. Без кавычек результат подстановки может превратиться в несколько аргументов.

Особенно важно писать `"$path"`, `"$1"`, `"$@"`, когда обрабатываются имена и пользовательские данные. Одна переменная пути не должна неожиданно стать несколькими файлами.

Ещё одна форма Bash — `$'...'`: внутри неё обрабатываются управляющие последовательности. `$'\n'` означает настоящий перевод строки, `$'\t'` — табуляцию, `$'\r'` — возврат каретки. В обычном одинарно цитированном `'\n'` остаются два символа — обратная косая черта и `n`. Обработка `\n` внутри **формата printf** — отдельное действие самой команды printf. В итоговом сценарии форма `$'\n'` нужна для поиска настоящего перевода строки в заголовке.

`printf` использует отдельно заданный формат. Пишите `printf '%s\n' "$value"`, а не делайте произвольный пользовательский текст самим форматом: символы `%` в данных не должны становиться командами форматирования.

## 10. Командная подстановка и обработка строк

```bash
BASHG_NOW="$(date --iso-8601=seconds)"
BASHG_PATH="$BASHG_BASE/data/file with spaces.txt"
printf 'Время: %s\n' "$BASHG_NOW"
printf 'Последнее имя: %s\n' "${BASHG_PATH##*/}"
BASHG_FILENAME="${BASHG_PATH##*/}"
printf 'Без расширения: %s\n' "${BASHG_FILENAME%.txt}"
printf 'Длина имени: %s\n' "${#BASHG_FILENAME}"
```

`$(date ...)` запускает команду и подставляет её стандартный вывод, удаляя завершающие переводы строк. `date --iso-8601=seconds` формирует дату, время и смещение часового пояса. Синтаксис `$(...)` обычно читается проще старых обратных кавычек.

`${переменная##*/}` удаляет самый длинный подходящий префикс до последнего `/`; `${имя%.txt}` — подходящий короткий суффикс `.txt`; `${#имя}` — длину строки. Это подстановки Bash, не отдельные программы.

**Ожидается:** текущее время, `file with spaces.txt`, `file with spaces`, длина имени. В операциях `#`, `##`, `%`, `%%` используются шаблоны оболочки, а не регулярные выражения grep.

## 11. Пустые значения и значения по умолчанию

```bash
BASHG_EMPTY=''
printf 'Пустое: <%s>\n' "$BASHG_EMPTY"
printf 'Запасное: %s\n' "${BASHG_EMPTY:-не задано}"
printf 'После чтения: <%s>\n' "$BASHG_EMPTY"
```

**Ожидается:** пустое значение, затем `не задано`, затем снова пустое. `:-` подставляет запасной текст, но не меняет переменную.

| Форма | Смысл |
| --- | --- |
| `${v:-text}` | Использовать text, если v не задана или пуста |
| `${v:=text}` | В таком случае ещё и присвоить text переменной |
| `${v:+text}` | Подставить text, только если v задана и непуста |
| `${v:?message}` | Сообщить об отсутствующем значении; в сценарии может завершить оболочку |

Последнюю форму не нужно пробовать непосредственно в SSH-оболочке. Для обязательных параметров можно также явно проверить значение и вывести понятную ошибку через `if`.

## 12. Числа и арифметика

```bash
BASHG_A=7
BASHG_B=2
printf 'Сумма: %s\n' "$((BASHG_A + BASHG_B))"
printf 'Деление: %s\n' "$((BASHG_A / BASHG_B))"
printf 'Остаток: %s\n' "$((BASHG_A % BASHG_B))"
BASHG_A=$((BASHG_A + 1))
printf 'Новое значение: %s\n' "$BASHG_A"
```

`$((...))` вычисляет целочисленное выражение. **Ожидается:** `9`, `3`, `1`, `8`. Обычная арифметика Bash не является вычислением дробных чисел: `7/2` даёт целую часть `3`.

Не передавайте в арифметику непроверенные пользовательские строки. Ведущий ноль может означать восьмеричную запись: `08` без явного основания не подходит. Для проверенной последовательности десятичных цифр можно указать основание:

```bash
BASHG_RAW='008'
if [[ "$BASHG_RAW" =~ ^[0-9]{1,4}$ ]]; then
    BASHG_NUMBER=$((10#$BASHG_RAW))
    printf 'Десятичное число: %s\n' "$BASHG_NUMBER"
fi
```

`=~` проверяет регулярное выражение; `^` и `$` задают границы, `{1,4}` — от одной до четырёх цифр. `10#` задаёт десятичную систему. **Ожидается:** `8`.

Конструкция `((выражение))` без `$` используется как команда-проверка: результат ноль даёт код неуспеха, ненулевой — успех. Поэтому `((counter++))` при исходном нуле может вернуть `1`, хотя счётчик увеличился. Для простого увеличения в учебных сценариях удобно `counter=$((counter + 1))`.

## 13. Вывод printf и ввод read

Создадим отдельный сценарий через терминал, чтобы изучить ещё один способ записи файла:

```bash
cat > "$BASHG_BASE/scripts/ask-name.sh" <<'EOF'
#!/bin/bash
if IFS= read -r -p 'Введите учебное имя: ' name; then
    printf 'Здравствуйте, %s!\n' "$name"
else
    printf '%s\n' 'Ввод не получен.' >&2
    exit 1
fi
EOF
bash -n "$BASHG_BASE/scripts/ask-name.sh"
bash "$BASHG_BASE/scripts/ask-name.sh"
```

`cat > файл <<'EOF'` записывает текст до отдельного `EOF`. Кавычки у ограничителя сохраняют `$name` для будущего запуска; без них текущая оболочка могла бы подставить своё значение ещё при создании файла.

`read` читает строку в переменную; `-r` не трактует обратные косые черты как экранирование, `-p` показывает приглашение. `IFS=` относится к этому чтению и сохраняет пробелы по краям строки. `>&2` направляет ошибку в поток ошибок. `exit 1` завершает дочерний сценарий, а не SSH-терминал.

**Ожидается:** приглашение. Введите `Анна Иванова` и Enter; появится `Здравствуйте, Анна Иванова!`. В `read` есть `-s` для скрытия вводимых символов, но для этого упражнения настоящие пароли вводить не нужно.

## 14. Аргументы сценария: $1, $# и "$@"

```bash
cat > "$BASHG_BASE/scripts/arguments.sh" <<'EOF'
#!/bin/bash
printf 'Имя запуска: %s\n' "$0"
printf 'Аргументов: %s\n' "$#"
printf 'Первый: %s\n' "${1:-не передан}"
for argument in "$@"; do
    printf 'Аргумент: <%s>\n' "$argument"
done
EOF
bash "$BASHG_BASE/scripts/arguments.sh" 'Анна Иванова' 'учебный файл.txt'
```

**Ожидается:** число `2`, первое имя целиком, затем два отдельных аргумента. `$0` — имя запуска, `$1` — первый аргумент, `$2` — второй, `$#` — количество. Для десятого используется `${10}`: запись `$10` не эквивалентна ей.

`"$@"` сохраняет каждый аргумент отдельным, включая пустой и содержащий пробелы. `"$*"` объединяет аргументы в одну строку с разделителем. Для передачи списка дальше обычно нужен именно `"$@"`.

`shift` убирает первый позиционный аргумент: прежний `$2` становится `$1`. В разделе 32 это понадобится для разбора параметров. Перед `shift 2` нужно убедиться, что два аргумента действительно существуют.

## 15. Код завершения и ожидаемая неудача

```bash
true
BASHG_RC=$?
printf 'true: %s\n' "$BASHG_RC"
false
BASHG_RC=$?
printf 'false: %s\n' "$BASHG_RC"
```

`true` возвращает успех, `false` — неуспех без дополнительного вывода. `$?` содержит код **последней** выполненной команды; сохраняйте его сразу. **Ожидается:** `true: 0`, `false: 1`.

Код `0` обычно означает успех, ненулевой — другое состояние. Его точное значение определяется программой. У `grep` код `1` означает отсутствие совпадения, а не обязательно повреждение файла или системы.

```bash
grep -F 'неизвестная_строка' "$BASHG_BASE/data/alpha.txt"
BASHG_RC=$?
printf 'Код grep: %s\n' "$BASHG_RC"
```

`grep -F` ищет буквальный текст. **Ожидается:** строк совпадения нет, код `1`. Если файл невозможно прочитать, будет ошибка и другой код; эти случаи нельзя смешивать.

## 16. Условия if, elif, else

```bash
BASHG_VALUE=12
if (( BASHG_VALUE < 10 )); then
    printf '%s\n' 'Меньше десяти.'
elif (( BASHG_VALUE == 10 )); then
    printf '%s\n' 'Ровно десять.'
else
    printf '%s\n' 'Больше десяти.'
fi
```

**Ожидается:** `Больше десяти.` Синтаксис: `if проверка; then команды; elif другая проверка; then ...; else ...; fi`. `fi` завершает условие. Перед `then` нужна граница команд — перевод строки или `;`.

`if` принимает не только квадратные скобки: он проверяет успех команды. Поэтому `if grep -F ...; then ...` тоже корректно. `else` и `elif` необязательны, `fi` обязателен.

### Проверки строк, файлов и чисел

```bash
if [[ -f "$BASHG_BASE/data/alpha.txt" && -r "$BASHG_BASE/data/alpha.txt" ]]; then
    printf '%s\n' 'Обычный файл существует и доступен для чтения.'
fi
if [[ "$BASHG_NAME" = 'Анна Иванова' ]]; then
    printf '%s\n' 'Имя совпало.'
fi
```

**Ожидается:** обе строки. `[[ ... ]]` — конструкция Bash; она не подставляется вместо обычной команды и требует пробелов рядом со скобками.

| Проверка | Значение |
| --- | --- |
| `-e путь` | Объект существует |
| `-f путь` | Обычный файл |
| `-d путь` | Каталог |
| `-L путь` | Символическая ссылка, в том числе с недоступной целью |
| `-r/-w/-x путь` | Возможность чтения / записи / выполнения для текущего контекста |
| `-s путь` | Файл существует и имеет ненулевой размер |
| `-z строка` | Строка пустая |
| `-n строка` | Строка непустая |
| `строка = строка`, `!=` | Равенство или неравенство строк |
| `-eq/-ne` в `[ ... ]` | Числа равны / не равны |
| `-lt/-le/-gt/-ge` | Меньше / не больше / больше / не меньше |
| `! проверка` | Отрицание |
| `&&`, `||` внутри `[[ ... ]]` | «И», «или» |

Форма `[ ... ]` — команда `test`; пробелы там тоже обязательны. Для строк в ней особенно важно цитирование: `[ "$value" = text ]`. Формы `[[ ... ]]` и арифметика `(( ... ))` относятся к Bash и не обязаны работать в другом `/bin/sh`.

## 17. Последовательность, &&, || и группы

```bash
printf '%s\n' 'Первая команда.'
true && printf '%s\n' 'Выполнилось после успеха.'
false || printf '%s\n' 'Выполнилось после неуспеха.'
```

**Ожидается:** три строки. Обычный перевод строки или `;` запускает следующую команду независимо от результата предыдущей. `&&` требует успеха слева, `||` — неуспеха.

Цепочка `проверка && действие || запасное` не всегда заменяет `if`: запасное выполнится и тогда, когда проверка успешна, но само действие вернуло ошибку. Для сложного выбора используйте явный `if`.

```bash
BASHG_GROUP=1
( BASHG_GROUP=2 )
printf 'После скобок: %s\n' "$BASHG_GROUP"
{ BASHG_GROUP=3; }
printf 'После фигурных скобок: %s\n' "$BASHG_GROUP"
```

`(...)` создаёт подоболочку: изменение переменной не возвращается в родителя. `{ ...; }` группирует команды в текущей оболочке. **Ожидается:** `1`, затем `3`. Перед закрывающей `}` нужна граница команд: здесь `;`.

## 18. Выбор нескольких вариантов через case

```bash
BASHG_ACTION=status
case "$BASHG_ACTION" in
    start)
        printf '%s\n' 'Выбран учебный вариант start.'
        ;;
    status|show)
        printf '%s\n' 'Выбран учебный просмотр.'
        ;;
    *)
        printf '%s\n' 'Неизвестный вариант.'
        ;;
esac
```

**Ожидается:** `Выбран учебный просмотр.` Здесь ничего не запускает настоящую службу: строки просто демонстрируют выбор.

`case ... in` начинает выбор, `esac` заканчивает. `;;` завершает ветку. `status|show` означает два допустимых шаблона; `*` — любой оставшийся вариант. Это шаблоны Bash, не произвольный код и не регулярные выражения.

## 19. Циклы for, while и until

### Перебор известного списка

```bash
for BASHG_ITEM in alpha 'two words' gamma; do
    printf 'Элемент: <%s>\n' "$BASHG_ITEM"
done
```

**Ожидается:** три элемента, второй — целиком. `for ... in` перебирает список, `do` начинает тело, `done` завершает. Переменная получает очередной элемент, а не номер автоматически.

### Цикл по числам

```bash
for ((BASHG_I=1; BASHG_I<=3; BASHG_I++)); do
    printf 'Шаг %s\n' "$BASHG_I"
done
```

**Ожидается:** шаги 1, 2, 3. В арифметическом `for` три позиции: начальное значение, условие продолжения, изменение после шага. Это Bash-синтаксис.

### Цикл while

```bash
BASHG_N=1
while (( BASHG_N <= 3 )); do
    printf 'while: %s\n' "$BASHG_N"
    BASHG_N=$((BASHG_N + 1))
done
```

`while` повторяет тело, пока проверка успешна. **Ожидается:** три строки. Изменение счётчика обязательно: забытое изменение может сделать цикл бесконечным. Если команда неожиданно повторяется без конца в терминале, Ctrl+C прерывает её.

### Цикл until, break и continue

```bash
BASHG_N=0
until (( BASHG_N >= 3 )); do
    BASHG_N=$((BASHG_N + 1))
    printf 'until: %s\n' "$BASHG_N"
done
for BASHG_N in 1 2 3 4 5; do
    if (( BASHG_N == 2 )); then continue; fi
    if (( BASHG_N == 4 )); then break; fi
    printf 'Осталось: %s\n' "$BASHG_N"
done
```

`until` выполняет тело, пока условие ещё не стало успешным: здесь выводит 1–3. `continue` пропускает остаток текущего шага, `break` прекращает цикл. Второй пример выводит только 1 и 3.

### Чтение файла построчно

```bash
BASHG_LINES=0
while IFS= read -r BASHG_LINE; do
    BASHG_LINES=$((BASHG_LINES + 1))
    printf '%s: <%s>\n' "$BASHG_LINES" "$BASHG_LINE"
done < "$BASHG_BASE/data/alpha.txt"
printf 'Строк прочитано: %s\n' "$BASHG_LINES"
```

`< файл` подаёт содержимое на стандартный ввод цикла. `IFS= read -r` сохраняет пробелы и обратные косые черты. **Ожидается:** три пронумерованные строки и итог `3`.

Вариант `команда | while ...` обычно запускает тело цикла в подоболочке: изменения счётчика могут не вернуться наружу. Для счётчика, который нужен после цикла, удобнее показанное `done < файл`.

Если последняя строка не заканчивается переводом строки, обычный `while read` может её не обработать. Учебный пример с учётом этого случая:

```bash
printf 'first\nlast' > "$BASHG_BASE/data/no-final-newline.list"
while IFS= read -r BASHG_LINE || [[ -n "$BASHG_LINE" ]]; do
    printf 'Прочитано: <%s>\n' "$BASHG_LINE"
done < "$BASHG_BASE/data/no-final-newline.list"
```

**Ожидается:** `first` и `last`. Дополнительное условие допускает непустое значение, полученное при конце файла. Это не повод искусственно дописывать данные в чужие файлы.

## 20. Функции, local и return

```bash
bashg_greet() {
    local person="${1:-гость}"
    printf 'Здравствуйте, %s!\n' "$person"
}
bashg_greet 'Анна Иванова'
bashg_greet
```

**Ожидается:** приветствие Анне и гостю. `имя() { ... }` определяет функцию, а вызов имени выполняет её. Внутри `$1` относится к аргументу функции. `local` ограничивает переменную функцией, чтобы случайно не изменить одноимённую внешнюю переменную.

Функция возвращает код завершения, а данные обычно выводит в stdout:

```bash
bashg_add() {
    local left="$1" right="$2"
    printf '%s\n' "$((left + right))"
}
BASHG_SUM="$(bashg_add 4 6)"
printf 'Получено: %s\n' "$BASHG_SUM"
```

**Ожидается:** `10`. Значения в этом примере заданы нами как числа; для пользовательского ввода нужна отдельная проверка.

`return 1` заканчивает функцию с неуспехом; `return 0` — с успехом. `exit` завершает весь исполняющий сценарий или оболочку. Не используйте `exit` внутри функции, которую просто вставили в SSH-терминал, если не хотите завершить этот терминал.

Кодом `return` нельзя передать произвольную строку или большое число как результат вычисления. Для данных используйте вывод и `$(...)`, для состояния — код. Диагностику выводите в stderr, чтобы она не смешивалась с захватываемыми данными.

## 21. Массивы и имена с пробелами

```bash
BASHG_ITEMS=('alpha' 'two words' 'gamma')
printf 'Элементов: %s\n' "${#BASHG_ITEMS[@]}"
printf 'Первый: %s\n' "${BASHG_ITEMS[0]}"
BASHG_ITEMS+=('delta')
printf 'Элемент: <%s>\n' "${BASHG_ITEMS[@]}"
```

**Ожидается:** исходное число `3`, первый элемент `alpha`, затем четыре элемента с сохранением пробелов. Индексация начинается с нуля. `+=('delta')` добавляет элемент, `${#массив[@]}` считает элементы.

`"${массив[@]}"` передаёт каждый элемент отдельным аргументом. Это основная форма для списков путей. `"${массив[*]}"` объединяет их в один аргумент.

### Шаблоны имён файлов

```bash
(
    shopt -s nullglob
    for BASHG_FILE in "$BASHG_BASE/data"/*.txt; do
        [[ -f "$BASHG_FILE" ]] || continue
        printf 'Файл: <%s>\n' "$BASHG_FILE"
    done
)
```

`*.txt` разворачивается в подходящие имена непосредственно оболочкой. Кавычками защищается каталог, а `*` остаётся вне кавычек, чтобы быть шаблоном. Уже найденное имя с пробелами остаётся одним элементом.

`shopt -s nullglob` делает пустым список при отсутствии совпадений; без него буквальное `*.txt` может остаться аргументом. Настройка помещена в `(...)` и не меняет вашу основную оболочку. **Ожидается:** три пути, включая `file with spaces.txt`. Скрытые имена и вложенные каталоги этот шаблон не охватывает.

Не разбирайте вывод `ls` через `for x in $(ls ...)`: пробелы и переводы строк разрушат границы имён. Для известного каталога используйте glob или корректно подготовленный массив.

### Ассоциативный массив

```bash
declare -A BASHG_PORTS=([web]=8080 [dns]=53)
printf 'Учебный web: %s\n' "${BASHG_PORTS[web]}"
printf 'Учебный dns: %s\n' "${BASHG_PORTS[dns]}"
```

`declare -A` создаёт массив с текстовыми ключами. **Ожидается:** 8080 и 53. Это просто данные; сетевые порты не открываются. На порядок обхода ассоциативного массива полагаться не нужно.

## 22. Окружение и export

```bash
BASHG_LOCAL_ONLY='значение родителя'
export BASHG_EXPORTED='training'
bash -c 'printf "Локальное: %s\n" "${BASHG_LOCAL_ONLY:-не передано}"; printf "Экспорт: %s\n" "$BASHG_EXPORTED"'
```

`export` передаёт переменную дочерним процессам. `bash -c 'текст'` запускает отдельный Bash с командами из аргумента. Одинарные кавычки оставляют подстановки для дочернего процесса.

**Ожидается:** локальное значение не передано, экспортированное — `training`. Это предполагает, что новое учебное имя ранее не было экспортировано в вашем окружении.

Дочерний процесс не может обычным присваиванием изменить окружение родителя. Поэтому запуск сценария не должен автоматически менять текущий каталог и переменные SSH-оболочки. Способ выполнить файл в текущем контексте разберём в разделе 25.

## 23. Стандартный ввод, вывод и ошибки

У процесса есть стандартные потоки: `0` — stdin, `1` — stdout, `2` — stderr. Обычный `printf` пишет в stdout; `>&2` выбирает stderr.

```bash
bash -c 'printf "обычный вывод\n"; printf "учебная ошибка\n" >&2' \
    > "$BASHG_BASE/report/stdout.log" 2> "$BASHG_BASE/report/stderr.log"
cat "$BASHG_BASE/report/stdout.log"
cat "$BASHG_BASE/report/stderr.log"
```

**Ожидается:** два отдельных файла и при чтении две строки. `>` создаёт или обнуляет файл, `2>` отдельно перенаправляет ошибки. Права записи проверяются до запуска самой команды.

```bash
printf 'первая строка\n' > "$BASHG_BASE/report/append.log"
printf 'вторая строка\n' >> "$BASHG_BASE/report/append.log"
bash -c 'printf "out\n"; printf "err\n" >&2' \
    > "$BASHG_BASE/report/combined.log" 2>&1
cat "$BASHG_BASE/report/append.log"
cat "$BASHG_BASE/report/combined.log"
```

`>>` дописывает. `2>&1` присоединяет stderr к **текущему назначению** stdout. **Ожидается:** обе дописанные строки, затем `out` и `err` из объединённого файла.

Порядок важен: `> файл 2>&1` отправляет оба потока в файл; `2>&1 > файл` сначала привязывает stderr к прежнему stdout, поэтому результат другой. Это одна из причин сначала писать ясные перенаправления, а затем запускать отладку.

`/dev/null` отбрасывает направленный в него поток; он не является архивом ошибок. Скрывайте вывод только когда понимаете, какой результат проверяется.

## 24. Каналы, here-document и here-string

### Канал между командами

```bash
printf 'INFO|alpha\nERROR|beta\nINFO|gamma\n' > "$BASHG_BASE/data/events.log"
grep -F 'INFO|' "$BASHG_BASE/data/events.log" | cut -d '|' -f 2
```

`|` соединяет stdout слева со stdin справа. `grep -F` выбирает буквальное `INFO|`; `cut -d '|'` задаёт разделитель, `-f 2` — второе поле. **Ожидается:** `alpha`, `gamma`. Это учебный формат, а не универсальный разбор произвольных журналов или CSV.

Канал обычно не перенаправляет stderr. Без `pipefail` код всей цепочки обычно равен коду последней команды — это важно для обнаружения ошибок.

### Here-document: несколько строк

```bash
cat > "$BASHG_BASE/report/literal.log" <<'EOF'
Имя переменной: $BASHG_NAME
Текст остаётся буквальным.
EOF
cat > "$BASHG_BASE/report/expanded.log" <<EOF
Значение: $BASHG_NAME
Каталог: $BASHG_BASE
EOF
cat "$BASHG_BASE/report/literal.log"
cat "$BASHG_BASE/report/expanded.log"
```

**Ожидается:** первый файл содержит буквальное `$BASHG_NAME`, второй — его значение. Кавычки у ограничителя управляют подстановками. Завершающий `EOF` должен быть отдельной строкой без лишних пробелов; сам он в файл не попадает.

### Here-string: одна строка на ввод

```bash
IFS='|' read -r BASHG_LEVEL BASHG_MESSAGE <<< 'INFO|training message'
printf 'Уровень: %s\nТекст: %s\n' "$BASHG_LEVEL" "$BASHG_MESSAGE"
```

`<<<` подаёт строку, а `IFS='|'` задаёт разделитель именно этой команде `read`. **Ожидается:** `INFO` и `training message`. При более сложном формате с кавычками и разделителями внутри полей нужен другой способ разбора.

## 25. Запуск файла, source и текущий каталог

```bash
cat > "$BASHG_BASE/scripts/source-demo.sh" <<'EOF'
BASHG_FROM_FILE='получено из файла'
EOF
bash "$BASHG_BASE/scripts/source-demo.sh"
printf 'После bash: %s\n' "${BASHG_FROM_FILE:-не задано}"
source "$BASHG_BASE/scripts/source-demo.sh"
printf 'После source: %s\n' "$BASHG_FROM_FILE"
```

**Ожидается:** после отдельного Bash значение не появилось в родительской оболочке; после `source` оно доступно. `source файл`, как и `. файл`, выполняет его команды в текущем контексте, а не просто читает пары «ключ–значение».

Используйте `source` только для известного доверенного кода. Нельзя безопасно разбирать чужую конфигурацию простым `source`: внутри могут находиться любые команды, включая `exit`, изменение каталога и другие действия.

Сценарий наследует текущий рабочий каталог вызывающего процесса. Путь к самому `.sh` не переключает каталог автоматически. Поэтому для файлов, расположенных рядом со сценарием, полезно получить его каталог:

```bash
cat > "$BASHG_BASE/scripts/location.sh" <<'EOF'
#!/bin/bash
script_dir="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd -P)" || exit 1
printf 'Рабочий каталог: %s\n' "$PWD"
printf 'Каталог сценария: %s\n' "$script_dir"
EOF
( cd -- "$BASHG_BASE/data" && bash "$BASHG_BASE/scripts/location.sh" )
```

`${BASH_SOURCE[0]}` — имя текущего исходного файла Bash; `dirname` выделяет каталог, `cd` переходит туда в командной подстановке, `pwd -P` показывает физический путь. **Ожидается:** рабочий каталог `data`, каталог сценария `scripts`. Переход внутри `$(...)` не меняет каталог вашей SSH-оболочки.

## 26. Короткие параметры через getopts

```bash
cat > "$BASHG_BASE/scripts/short-options.sh" <<'EOF'
#!/bin/bash
name='гость'
while getopts ':n:h' option; do
    case "$option" in
        n) name="$OPTARG" ;;
        h) printf '%s\n' 'Использование: short-options.sh [-n имя] [аргументы]'; exit 0 ;;
        :) printf 'Параметру -%s нужно значение.\n' "$OPTARG" >&2; exit 64 ;;
        \?) printf 'Неизвестный параметр: -%s\n' "$OPTARG" >&2; exit 64 ;;
    esac
done
shift "$((OPTIND - 1))"
printf 'Имя: %s\n' "$name"
for argument in "$@"; do
    printf 'Остаток: <%s>\n' "$argument"
done
EOF
bash "$BASHG_BASE/scripts/short-options.sh" -n 'Анна Иванова' -- 'учебный файл'
```

`getopts` — встроенный разбор коротких опций. В строке `:n:h` двоеточие после `n` требует значение для `-n`; у `-h` значения нет. Начальное `:` позволяет самостоятельно обработать ошибки. `OPTARG` хранит значение, `OPTIND` — индекс следующего аргумента.

`shift "$((OPTIND - 1))"` убирает уже разобранные параметры. `--` в вызове завершает опции. **Ожидается:** имя целиком и один оставшийся аргумент. Для длинных `--label`, `--dry-run` можно использовать явный `while` и `case`, как в итоговом сценарии.

## 27. Фоновые команды, wait и trap

### Короткая работа в фоне

```bash
sleep 1 &
BASHG_JOB_PID=$!
printf 'Запущен учебный PID: %s\n' "$BASHG_JOB_PID"
wait "$BASHG_JOB_PID"
printf '%s\n' 'Учебная фоновая команда завершена.'
```

`&` запускает команду в фоне, `$!` получает PID последней фоновой команды, `wait` ждёт именно её. `sleep 1` делает паузу примерно на секунду. **Ожидается:** PID и подтверждение завершения. Сохранённый PID не нужно копировать из примера.

`jobs` показывает задания текущей оболочки, а не все процессы сервера. Ctrl+Z обычно приостанавливает текущую программу, а Ctrl+C прерывает; это разные действия. Если случайно приостановили nano, `jobs -l` покажет номер задания и PID; `fg` возвращает текущее задание на передний план. При нескольких заданиях сначала определите своё, не завершайте чужие процессы.

Обычный фон через `&` не является надёжным способом запуска ежедневной серверной задачи: завершение сеанса и политика системы могут повлиять на процесс. Для расписаний используйте разобранные в других практиках Cron или systemd, а не бесконечный цикл в SSH.

### Временный файл и очистка

```bash
cat > "$BASHG_BASE/scripts/trap-demo.sh" <<'EOF'
#!/bin/bash
script_dir="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd -P)" || exit 1
work_dir="$(cd -- "$script_dir/.." && pwd -P)" || exit 1
temp_file="$(mktemp "$work_dir/report/.trap-demo.XXXXXX")" || exit 1
cleanup() {
    rm -f -- "$temp_file"
    printf '%s\n' 'Учебный временный файл удалён.'
}
trap cleanup EXIT
trap 'exit 129' HUP
trap 'exit 130' INT
trap 'exit 143' TERM
printf 'Временный файл: %s\n' "$temp_file"
printf '%s\n' 'Можно нажать Ctrl+C или дождаться десяти секунд.'
sleep 10
EOF
bash "$BASHG_BASE/scripts/trap-demo.sh"
```

`mktemp` создаёт новый файл с уникальным фрагментом вместо `XXXXXX`. `trap cleanup EXIT` вызывает очистку при обычном выходе. Обработчики HUP, INT, TERM завершают сценарий с понятными кодами; затем срабатывает EXIT. `rm -f --` удаляет только сохранённый временный путь, допуская отсутствие файла.

**Ожидается:** путь временного файла, затем сообщение очистки. Можно нажать Ctrl+C, пока сценарий ждёт, или дождаться естественного завершения. После этого вернётся приглашение Bash. SIGKILL и потерю питания обработчик перехватить не может, поэтому trap не заменяет продуманное размещение временных файлов.

## 28. Проверка синтаксиса и отладка

```bash
bash -n "$BASHG_BASE/scripts/arguments.sh"
bash -x "$BASHG_BASE/scripts/arguments.sh" 'Анна Иванова' \
    > "$BASHG_BASE/report/trace-arguments.log" 2>&1
sed -n '1,25p' "$BASHG_BASE/report/trace-arguments.log"
```

`bash -n` не выполняет сценарий; успех обычно не печатает сообщений. `bash -x` **выполняет** его и показывает команды после подстановок. `sed -n '1,25p'` выводит выбранные строки: `-n` отключает автоматический общий вывод, `p` печатает диапазон.

**Ожидается:** трассировка со строками, начинающимися на `+`, и обычный результат сценария. Символы `+` копировать обратно в терминал не нужно. Трассировка может раскрывать подставленные значения, поэтому используйте учебные данные, а не настоящие пароли и токены.

Создадим файл с намеренно незавершённым условием, но не будем его выполнять:

```bash
cat > "$BASHG_BASE/scripts/broken-syntax.sh" <<'EOF'
#!/bin/bash
if true; then
    printf 'training\n'
EOF
if bash -n "$BASHG_BASE/scripts/broken-syntax.sh"; then
    printf '%s\n' 'Неожиданно: ошибка не обнаружена.'
else
    printf '%s\n' 'Ожидаемая ошибка: условие не закрыто через fi.'
fi
```

**Ожидается:** сообщение о синтаксической ошибке и пояснение. Номер указанной строки может находиться после настоящего пропуска: Bash дошёл до конца, ожидая `fi`.

Открыть конкретную строку можно `nano -w +3 "$BASHG_BASE/scripts/broken-syntax.sh"`. Добавьте `fi` в конце, сохраните через Ctrl+O, Enter, выйдите Ctrl+X и повторите `bash -n`. Теперь проверка должна молчать. Автоматическая проверка синтаксиса не доказывает правильность логики и путей.

## 29. Переводы строк Windows и скрытые символы

Файл, подготовленный в Windows, может содержать CRLF вместо LF. Тогда в shebang может оказаться лишний `\r`, а оболочка — пытаться найти интерпретатор с неправильным именем. Для воспроизводимого примера создадим **отдельный учебный файл**:

```bash
printf '#!/bin/bash\r\nprintf "training\\n"\r\n' > "$BASHG_BASE/scripts/crlf-demo.sh"
sed -n '1,5l' "$BASHG_BASE/scripts/crlf-demo.sh"
```

У sed команда `l` показывает непечатаемые символы и конец строки. **Ожидается:** видимые `\r` перед обозначением конца строки `$`.

Исправьте только этот файл:

```bash
sed -i 's/\r$//' "$BASHG_BASE/scripts/crlf-demo.sh"
bash -n "$BASHG_BASE/scripts/crlf-demo.sh" && bash "$BASHG_BASE/scripts/crlf-demo.sh"
```

`sed -i` меняет файл на месте; `s/\r$//` убирает CR только с конца строк. **Ожидается:** `training`. Для рабочего файла сначала сохраняют нужную копию; не применяйте такое исправление ко всему дереву конфигураций.

## 30. set -e, set -u и pipefail без «магии»

Ниже параметры передаются **дочернему Bash**, а не включаются в текущем SSH-сеансе.

```bash
bash -c 'false | true; printf "Обычный код канала: %s\n" "$?"'
bash -o pipefail -c 'false | true; printf "Код с pipefail: %s\n" "$?"'
```

**Ожидается:** 0 и 1. `-o pipefail` учитывает неудачу команд канала; без него обычно виден только результат последней.

```bash
bash -e -c 'printf "до ошибки\n"; false; printf "после ошибки\n"'
BASHG_RC=$?
printf 'Код дочернего Bash: %s\n' "$BASHG_RC"
```

`-e` включает режим завершения при некоторых необработанных ошибках. **Ожидается:** `до ошибки`, код `1`; строка после false не выполняется. У `-e` есть исключения в условиях, списках `&&/||` и других контекстах. Это не универсальный механизм «остановиться при любом сбое».

```bash
bash -u -c 'unset BASHG_UNSET_DEMO; printf "%s\n" "$BASHG_UNSET_DEMO"'
BASHG_RC=$?
printf 'Незаданная переменная, код: %s\n' "$BASHG_RC"
```

`-u` обнаруживает обращение к незаданной переменной. `unset` удаляет только собственную учебную переменную в дочернем процессе. **Ожидается:** ошибка `unbound variable` и ненулевой код, а SSH остаётся открыт.

Используйте понятные проверки и обработку ожидаемых состояний. Например, отсутствие совпадения grep — обычный результат поиска, который лучше разобрать через `if`, а не неожиданно завершать весь сценарий.

## 31. Маленькие привычки, которые делают сценарий понятнее

### Закрытые права новых файлов

```bash
(
    umask 077
    printf 'training\n' > "$BASHG_BASE/report/private-demo.log"
    stat -c '%a %n' -- "$BASHG_BASE/report/private-demo.log"
)
```

`umask 077` ограничивает права новых объектов; `stat -c` показывает числовые права `%a` и имя `%n`. Скобки ограничивают действие настройки подоболочкой. **Ожидается:** `600` для нового файла. Umask не изменяет уже существующие файлы.

### Сообщение об ошибке и явный код

Удобно проверять критическую команду через `if` или `||`, выводить понятный текст в stderr и завершать **сценарий** с кодом ошибки. Для функции в текущей оболочке используйте `return`, если нужно выйти только из функции.

### Данные остаются данными

Строка пользователя должна попадать в `printf '%s'`, сравнение или отдельный аргумент команды, а не становиться новым программным текстом. Для примеров этого курса не нужны `eval`, сборка команды строкой и запуск этой строки через `bash -c`.

Наши употребления `bash -c` выше содержат заранее известный учебный код. Это отличается от выполнения непроверенной строки, полученной из файла или ввода.

### Комментарии объясняют причину

Полезный комментарий объясняет, зачем проверяется путь или почему временный файл создаётся рядом с итоговым. Не нужно превращать каждую очевидную строку в длинный комментарий; для подробного разбора служит текст гайда.

## 32. Итоговая практика: сценарий отчёта по учебным файлам

Сценарий читает только обычные `.txt` из `data`, считает строки, отмечает короткие файлы, записывает SHA-256 и формирует отдельный отчёт. Он показывает, как соединить изученные конструкции в законченную программу.

| Параметр | Что делает |
| --- | --- |
| `--label 'текст'` | Задаёт однострочный заголовок |
| `--min-lines число` | Задаёт минимальное число строк, по умолчанию 2 |
| `--dry-run` | Показывает выбранные файлы и параметры без создания отчёта |
| `--help` | Показывает справку |

Файлы не исправляются и не удаляются. Метка `short` — результат сравнения с порогом, а не доказательство неисправности ОС. Имя отчёта формируется из времени и PID, а не из произвольного пользовательского заголовка.

### 32.1. Создайте файл через nano

В терминале:

```bash
nano -w "$BASHG_BASE/scripts/workspace-report.sh"
```

**Ожидается:** редактор нового файла. Следующий блок вставляется **в nano**, целиком. Затем Ctrl+O, Enter и Ctrl+X.

```bash
#!/bin/bash
# Отчёт по собственным учебным текстовым файлам.
set -u
set -o pipefail
PATH=/usr/bin:/bin
export PATH
umask 077

usage() {
    printf '%s\n' \
        'Usage: workspace-report.sh [--label TEXT] [--min-lines N] [--dry-run] [--help]'
}
die() {
    printf 'ERROR: %s\n' "$1" >&2
    exit "${2:-1}"
}

# Разбор аргументов до любых записей в файловую систему.
label='Учебный отчёт'
min_lines=2
dry_run=0
while (( $# > 0 )); do
    case "$1" in
        --label)
            (( $# >= 2 )) || die 'The --label option requires a value.' 64
            label="$2"
            shift 2
            ;;
        --min-lines)
            (( $# >= 2 )) || die 'The --min-lines option requires a value.' 64
            [[ "$2" =~ ^[0-9]{1,4}$ ]] || die 'N must contain 1 to 4 decimal digits.' 64
            min_lines=$((10#$2))
            shift 2
            ;;
        --dry-run)
            dry_run=1
            shift
            ;;
        --help)
            usage
            exit 0
            ;;
        *)
            usage >&2
            die 'Unknown argument.' 64
            ;;
    esac
done
[[ -n "$label" && "$label" != *$'\n'* && "$label" != *$'\r'* ]] || die 'Label must be a nonempty single line.' 64
(( EUID != 0 )) || die 'Run this exercise as an ordinary user.'

# Путь вычисляется относительно сценария, а не текущего каталога.
script_dir="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd -P)" || die 'Cannot locate script.'
work_dir="$(cd -- "$script_dir/.." && pwd -P)" || die 'Cannot locate workspace.'
data_dir="$work_dir/data"
output_dir="$work_dir/report"
[[ -d "$data_dir" && ! -L "$data_dir" ]] || die 'The data directory is missing or is a symlink.'

# Собираем список, сохраняя имена с пробелами отдельными элементами.
shopt -s nullglob
files=()
for path in "$data_dir"/*.txt; do
    if [[ -f "$path" && ! -L "$path" ]]; then
        files+=("$path")
    fi
done
(( ${#files[@]} > 0 )) || die 'No regular .txt input files found.'

# Этот режим не создаёт ни каталог, ни временный или итоговый файл.
if (( dry_run == 1 )); then
    printf 'dry_run=1 label=%s min_lines=%s files=%s\n' "$label" "$min_lines" "${#files[@]}"
    printf 'file=%s\n' "${files[@]}"
    exit 0
fi

[[ ! -L "$output_dir" ]] || die 'Output directory must not be a symlink.'
mkdir -p -m 700 -- "$output_dir" || die 'Cannot create output directory.'
temp_report=''
cleanup() {
    if [[ -n "$temp_report" ]]; then
        rm -f -- "$temp_report"
    fi
}
trap cleanup EXIT
trap 'exit 129' HUP
trap 'exit 130' INT
trap 'exit 143' TERM
temp_report="$(mktemp "$output_dir/.report.XXXXXX")" || die 'Cannot create temporary report.'

short_count=0
{
    printf 'label=%s\nmin_lines=%s\nfiles=%s\n' "$label" "$min_lines" "${#files[@]}" || die 'Cannot write report header.'
    for path in "${files[@]}"; do
        [[ -r "$path" ]] || die 'An input file is not readable.'
        lines="$(wc -l < "$path")" || die 'Cannot count lines.'
        if (( lines < min_lines )); then
            state=short
            short_count=$((short_count + 1))
        else
            state=ok
        fi
        printf 'file=%s lines=%s state=%s\n' "${path##*/}" "$lines" "$state" || die 'Cannot write file result.'
        sha256sum -- "$path" || die 'Cannot calculate checksum.'
    done
    printf 'summary_files=%s summary_short=%s\n' "${#files[@]}" "$short_count" || die 'Cannot write summary.'
} > "$temp_report" || die 'Cannot write report.'

# Публикуем полное содержимое новым именем без перезаписи прежнего.
stamp="$(date +'%Y-%m-%d_%H-%M-%S')" || die 'Cannot get current time.'
final_report="$output_dir/report_${stamp}_$$.txt"
ln -T -- "$temp_report" "$final_report" || die 'Cannot publish report.'
rm -f -- "$temp_report" || die 'Cannot remove temporary name.'
temp_report=''
printf 'report=%s\nfiles=%s short=%s\n' "$final_report" "${#files[@]}" "$short_count"
exit 0
```

**Ожидается после сохранения:** возвращение в Bash. Код ещё не запускался.

### 32.3. Посмотрите план без записи отчёта

```bash
bash "$BASHG_BASE/scripts/workspace-report.sh" \
    --label 'Первый отчёт' --min-lines 002 --dry-run
```

**Ожидается:** `dry_run=1`, порог `2`, число файлов `3` и три пути. `002` нормализуется как десятичное число, а не восьмеричное. Опция `--dry-run` работает потому, что её явно реализовали в программе; Bash не добавляет такой режим любому сценарию автоматически.

### 32.4. Создайте и прочитайте отчёт

```bash
bash "$BASHG_BASE/scripts/workspace-report.sh" \
    --label 'Первый отчёт' --min-lines 2 \
    > "$BASHG_BASE/report/report-run.log" 2>&1
BASHG_RC=$?
cat "$BASHG_BASE/report/report-run.log"
printf 'Код завершения: %s\n' "$BASHG_RC"
```

**Пример результата:**

```text
report=/var/tmp/astra-bash-1000/report/report_2026-11-11_12-10-00_12345.txt
files=3 short=1
Код завершения: 0
```

В `alpha.txt` три строки, в `beta.txt` одна, в `file with spaces.txt` две. При пороге 2 коротким считается только `beta.txt`. Если вы намеренно изменяли исходные файлы, итог закономерно будет другим.

```bash
BASHG_RESULT="$(sed -n 's/^report=//p' "$BASHG_BASE/report/report-run.log")"
if [[ "$BASHG_RC" -eq 0 && "$BASHG_RESULT" = "$BASHG_BASE/report/report_"*.txt && -f "$BASHG_RESULT" ]]; then
    cat "$BASHG_RESULT"
    stat -c '%a %n' -- "$BASHG_RESULT"
else
    printf '%s\n' 'STOP: ожидаемый готовый отчёт не найден.'
fi
```

`sed` извлекает путь из строки с начальным `report=`. Проверки ограничивают чтение ожидаемым каталогом и форматом имени. **Ожидается:** заголовок, результаты по трём файлам, суммы и итог; права готового файла `600`.

### 32.5. Проверьте отказ при неверном аргументе

```bash
if bash "$BASHG_BASE/scripts/workspace-report.sh" --min-lines wrong; then
    printf '%s\n' 'Неожиданно: неверное число принято.'
else
    BASHG_RC=$?
    printf 'Ожидаемый отказ; код: %s\n' "$BASHG_RC"
fi
```

**Ожидается:** понятная ошибка и код `64`. Новый отчёт этим запуском не создаётся. Похожим образом обрабатываются неизвестная опция и отсутствие значения после `--label` или `--min-lines`.

### 32.6. Запустите из другого каталога и с минимальным окружением

```bash
(
    cd -- "$BASHG_BASE/data" &&
        env -i PATH=/usr/bin:/bin /bin/bash "$BASHG_BASE/scripts/workspace-report.sh" --label 'Минимальное окружение'
)
```

`env -i` очищает наследуемое окружение только запускаемой команды; затем задаётся её `PATH`. Скобки сохраняют текущий каталог родительской оболочки. **Ожидается:** ещё один отчёт и тот же подсчёт файлов. Сценарий не зависит от переменных `BASHG_...` внутри своего процесса: пути получены из расположения файла.

Это полезная проверка перед автоматизацией: в Cron среда отличается от интерактивного SSH. Здесь расписание не устанавливается; порядок работы с ним разобран в [практике Cron](../Mod%203/cron_scheduling_practice.md).

### 32.7. Зачем нужны последние проверки сценария

`set -u` обнаруживает незаданные переменные, но перед обращением к `$2` мы всё равно проверяем число аргументов. `set -o pipefail` задаёт ожидаемое поведение каналов; критические операции дополнительно имеют явные проверки.

Пользовательский заголовок — только значение `%s`, он не становится командой и не участвует в имени файла. Проверка запрещает пустую и многострочную метку. Число ограничено четырьмя цифрами перед арифметикой.

`files` — массив. `nullglob` не оставляет буквальный `*.txt`; дополнительная проверка исключает каталоги и ссылки. `wc -l` считает переводы строк, поэтому для текста без завершающего LF это не всегда число логических строк. Исходные три `.txt` специально заканчиваются LF.

`sha256sum -- "$path"` вычисляет SHA-256 содержимого файла — контрольную сумму, обычно показываемую как 64 шестнадцатеричных символа. `--` завершает флаги. При изменении содержимого ожидается другая сумма; для проверки нужно сравнить её с сохранённым значением. Это не независимое доказательство подлинности, если можно подменить и данные, и эталон.

В `date +'%Y-%m-%d_%H-%M-%S'` знак `+` задаёт формат: `%Y` — год, `%m` — месяц, `%d` — день, `%H` — час в 24-часовом виде, `%M` — минуты, `%S` — секунды. `$$` добавляет PID исполняющего сценария. Заголовок пользователя не влияет на путь выходного файла.

`{ ...; } > "$temp_report"` направляет вывод группы в один файл и сохраняет `short_count` в текущем процессе. При сбое `die` выходит с ошибкой; EXIT удаляет незавершённый временный файл.

У `ln -T` флаг `-T` запрещает трактовать конечный путь как каталог. Жёсткая ссылка создаёт новое имя уже полностью записанного файла и не перезаписывает существующее. Временный и итоговый файл находятся на одной файловой системе; способ требует поддержки жёстких ссылок, обычно доступной на ext4 и XFS. Затем удаляется только временное имя, а готовое содержимое остаётся.

Режим `short` не приводит к ошибке запуска: задача сценария — сформировать отчёт, а не менять входные файлы. Код `0` подтверждает завершение этой операции, не «полную исправность сервера».

## 33. Шпаргалка по синтаксису и типичным ошибкам

| Задача | Форма |
| --- | --- |
| Переменная | `value='текст'` |
| Безопасная подстановка | `"$value"`, `"${value}_suffix"` |
| Результат команды | `value="$(команда)"` |
| Арифметика | `result=$((a + b))` |
| Проверка Bash | `[[ условие ]]` |
| Числовая проверка | `(( число > 0 ))` |
| Условие | `if ...; then ...; else ...; fi` |
| Выбор | `case "$value" in ... esac` |
| Перебор | `for x in ...; do ...; done` |
| Повтор | `while проверка; do ...; done` |
| Функция | `name() { ...; }` |
| Все аргументы отдельно | `"$@"` |
| Все элементы массива отдельно | `"${array[@]}"` |
| Перезаписать / дописать | `> файл` / `>> файл` |
| Только ошибки | `2> файл` |
| Оба потока в файл | `> файл 2>&1` |
| Подать файл на ввод | `< файл` |
| Соединить команды | `команда1 | команда2` |
| Очистка при завершении | `trap функция EXIT` |
| Проверить синтаксис | `bash -n файл` |
| Выполнить с трассировкой | `bash -x файл` |

В таблице показаны схемы языка, а не один блок для выполнения: имена и многоточия обозначают место конкретных команд.

| Симптом | Что проверить |
| --- | --- |
| `command not found` после присваивания | Нет ли пробелов в `name = value` |
| `syntax error near unexpected token` | Пробелы у скобок, `then`, `do`, `fi`, `done`, закрытие кавычек |
| `unexpected end of file` | Не пропущены ли `fi`, `done`, `}`, кавычка или ограничитель here-document |
| Терминал показывает `>` | Текущая конструкция не закончена; Ctrl+C отменяет её |
| `Permission denied` при прямом запуске | Права выполнения, путь и политика файловой системы; не используйте `chmod 777` |
| `bad interpreter` с `^M` | Переводы строк CRLF или неправильный shebang |
| Файл с пробелом распался на слова | Кавычки у подстановки и массив с `"${array[@]}"` |
| Изменение переменной потерялось | Не происходило ли оно в дочернем процессе, `$(...)`, `(...)` или цикле канала |
| Скрипт ищет файл не там | Текущий каталог отличается от каталога сценария |
| Успешный код скрывает сбой канала | Результат последней команды, `pipefail`, явная проверка ожидаемых ошибок |
| `unbound variable` | Значение не задано при `-u`; проверьте аргументы или используйте обоснованное значение по умолчанию |
| Число `008` не вычисляется | Проверка ввода и десятичное основание `10#` |

## 34. Что сохранить как результат обучения

Можно сделать скриншоты:

1. `hello.sh` в nano с первой строкой, комментарием и командами.
2. Успешного `bash -n` и первого запуска.
3. Примера аргументов с пробелами и обработки условия или цикла.
4. `--dry-run` итогового сценария с тремя входными файлами.
5. Готового отчёта: имя файла, `files=3 short=1`, содержимое и права `600`.
6. Отказа с кодом `64` при неверном числе.

Скриншоты должны содержать ваши команды и результат, а не скопированный пример вывода. Итоговый сценарий можно сохранить вместе с отчётом; он содержит только собственные учебные данные. Трассировки с настоящими секретами в отчёт не добавляются.

## 35. Если SSH оборвался

Подключитесь к той же Astra под тем же обычным пользователем. Восстановите только переменные:

```bash
BASHG_UID="$(id -u)"
BASHG_BASE="/var/tmp/astra-bash-$BASHG_UID"
ls -l -- "$BASHG_BASE/scripts"
```

**Ожидается:** уже созданные сценарии. Повторно создавать стенд и вставлять все блоки поверх файлов не требуется. Открывайте нужный `.sh` по абсолютному пути и продолжайте после проверки его содержимого и `bash -n`.

Демонстрационные функции и переменные терминала нужно определить заново, если они нужны для конкретного примера. Готовый итоговый сценарий от них не зависит. Если редактор сообщил о найденном аварийном или блокировочном файле, сначала изучите варианты сохранения своей работы; не удаляйте непонятный файл автоматически.

`/var/tmp` может переживать перезагрузку, но подчиняется политике очистки системы. Для постоянных рабочих сценариев место и порядок установки выбирают отдельно; этот каталог предназначен для обучения.

## 36. Завершите упражнения и удалите личный стенд

Сначала сохраните нужные скриншоты и итоговый код. Дождитесь завершения `trap-demo.sh` и короткой фоновой команды из раздела 27. В этом гайде задания Cron и systemd не создавались.

```bash
if [ "$BASHG_BASE" = "/var/tmp/astra-bash-$(id -u)" ] &&
    [ -d "$BASHG_BASE" ] && [ ! -L "$BASHG_BASE" ]; then
    cd "$HOME" && rm -rI -- "$BASHG_BASE"
else
    printf '%s\n' 'STOP: проверьте путь личного стенда.'
fi
```

`[ ... ]` проверяет точный путь, наличие каталога и отсутствие ссылки. `cd "$HOME"` выводит оболочку из удаляемого дерева. `rm -r` удаляет дерево рекурсивно; заглавная `-I` запрашивает подтверждение перед рекурсивным удалением.

**Ожидается:** вопрос об удалении только вашего `/var/tmp/astra-bash-UID`. Проверьте путь и подтвердите. После этого учебные файлы исчезнут. `sudo` здесь не нужен.

## 37. Как пользоваться встроенной справкой

```bash
help printf
help read
help getopts
bash --version
```

`help` показывает справку **встроенной команды Bash**. `bash --version` — версию интерпретатора. **Ожидается:** справочный текст и сведения о версии. Он может быть на английском, но соответствует установленной программе.

`man bash` открывает руководство оболочки, `man nano` — редактора, `man chmod` — прав, `man printf` может описывать отдельную внешнюю программу printf, а не встроенную команду. В man выход — `q`, поиск — `/`, затем слово и Enter; `n` повторяет поиск вперёд. В nano собственная помощь открывается Ctrl+G.
