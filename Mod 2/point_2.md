# Модуль 2. Подключение XFS по UUID с параметром noatime

Вся работа выполняется **на одной удалённой Astra Linux Special Edition 1.7**, к которой вы уже подключились по SSH. Команды вводятся в Bash этой машины. Второй сервер, подключение физического диска и работа в локальном терминале вашего компьютера не требуются.

Материал состоит из двух частей:

1. **Подготовка и объяснение.** Разберём инструменты, пакеты и репозитории, устройство XFS, имена устройств, UUID, параметры монтирования, права и формат `fstab`.
2. **Практика с решением.** Смоделируем новый диск файлом-образом, создадим в нём раздел XFS, смонтируем его с `noatime`, предоставим доступ через отдельный каталог, проверим данные и применим запись с UUID после повторного подключения устройства.

Для тренировки используем собственный образ 512 MiB с разделом 480 MiB. Разметка выполняется внутри этого файла. Форматирование допускается только после проверки, что выбранное loop-устройство действительно связано с нашим образом. Реальные диски сервера просматриваем, но не изменяем.

**Требование об автоматическом монтировании адаптировано для работы по SSH:** вместо изменения настоящего `/etc/fstab` создаём его модель в отдельном каталоге `model/etc/fstab`. После отключения и нового подключения образа применим всю эту таблицу командой `mount --all --fstab ...`. Это проверяет пригодность записи для подключения по UUID без ручного указания имени устройства. Перезагрузка ОС и реальная настройка загрузочного монтирования сервера не выполняются.

Образ не становится постоянным аппаратным диском. После настоящей перезагрузки его loop-связь сама по себе не обязана восстановиться. Запись UUID в настоящем `fstab` не создаёт эту связь. В реальной системе сначала обеспечивают доступность устройства, затем его монтирование и только потом запуск использующего его приложения.

Примеры вывода условные. UUID, версии программ, язык сообщений и номера loop-устройств у вас будут другими. В примерах UID и GID равны `1000`, устройство называется `/dev/loop9`, раздел — `/dev/loop9p1`. Эти номера вручную подставлять не нужно: команды получат их автоматически.

## Часть 1. Что нужно понимать и подготовить до выполнения задания

### 1. Как работать с командами в удалённом терминале

После входа по SSH команда выполняется на Astra Linux, даже если подключение открыто из Windows PowerShell. Пути `/etc`, `/dev` и `/mnt` относятся к удалённой машине.

Копируйте по одному блоку, в указанном порядке. Вводить нужно команды из блоков `bash`, а не примеры вывода. Не добавляйте приглашение вида `student@astra:~$` в начало строки.

Многострочный блок с `<<'EOF'` вставляется целиком, включая отдельную завершающую строку `EOF`. Это способ передать команде несколько строк текста. Если Bash показывает `>` и ждёт продолжения из-за неполного ввода, Ctrl+C отменяет его; затем вставьте блок заново.

Переменные и функции ниже живут в текущем сеансе Bash. Образ, loop-связь и монтирование не исчезают при разрыве SSH. В части 2 предусмотрено восстановление состояния без повторного форматирования.

#### 1.1. Подтвердите ОС, пользователя и оболочку

```bash
whoami
hostname
cat /etc/os-release
cat /etc/astra_version
printf '%s\n' "$BASH_VERSION"
```

| Команда или запись | Что делает и зачем нужна |
| --- | --- |
| `whoami` | Показывает пользователя текущего сеанса |
| `hostname` | Показывает имя машины, на которой выполняются команды |
| `cat` | Читает текстовый файл и печатает его содержимое |
| `/etc/os-release` | Сведения об операционной системе |
| `/etc/astra_version` | Сведения о выпуске Astra Linux |
| `printf` | Печатает значения в заданном формате |
| `%s` | Место для строки |
| `\n` | Перевод строки |
| `"$BASH_VERSION"` | Версия текущей Bash; кавычки сохраняют значение одним аргументом |

У приведённых `whoami`, `hostname` и `cat` флагов нет.

**Пример сокращённого результата:**

```text
student
astra-lab
PRETTY_NAME="Astra Linux"
...
1.7.x
5.0.3(1)-release
```

**Что должно получиться.** Вы подтвердили нужную Astra Linux и непустое значение версии Bash. Номера обновления и оболочки могут отличаться от примера. Если версия Bash не выводится, уточните используемую оболочку перед копированием многострочных конструкций.

### 2. Пакетные инструменты: что уже установлено и чего может не хватать

Пакет `.deb` содержит файлы программы и сведения о её установке. Пакетный менеджер учитывает, какие файлы и версии установлены, а репозиторий предоставляет пакеты и индекс доступных версий.

В Astra Linux используются инструменты семейства `dpkg` и APT. Для этой практики устанавливать другой пакетный менеджер не требуется. Дополнительный пакет `xfsprogs` содержит средства работы с XFS; он не заменяет APT и не форматирует диски просто от факта своей установки.

| Инструмент | Назначение |
| --- | --- |
| `dpkg-query` | Посмотреть сведения об установленных пакетах |
| `dpkg --audit` | Проверить незавершённые состояния пакетной базы |
| `apt-cache policy` | Посмотреть известные версии пакета и его источники |
| `apt-get` | Рассчитать и выполнить выбранную установку через APT |
| `lsblk`, `findmnt`, `blkid` | Исследовать устройства, файловые системы и монтирование |
| `sfdisk` | Записать и прочитать таблицу разделов нашего образа |
| `losetup` | Связать файл-образ с loop-устройством |
| `mkfs.xfs` | Создать XFS на выбранном устройстве; это операция, уничтожающая прежнее содержимое выбранной области |
| `xfs_info` | Посмотреть геометрию и параметры XFS |
| `xfs_repair` | Проверять и исправлять структуры XFS; в этой практике используется только режим без изменений |

#### 2.1. Проверьте sudo и пакетную базу

```bash
sudo -v
sudo dpkg --audit
```

`sudo` предоставляет разрешённые административные права. Его `-v` проверяет полномочия и обновляет срок их подтверждения. При запросе введите пароль своей учётной записи; символы не показываются.

`dpkg --audit` проверяет согласованность состояний установленных пакетов. Параметр `--audit` ничего не исправляет и не устанавливает.

**Ожидаемый результат:** после возможного запроса пароля обе команды завершаются без текста. Если `dpkg` перечисляет частично установленные пакеты или иные проблемы, не начинайте новую установку поверх этого состояния; покажите вывод администратору.

#### 2.2. Найдите необходимые программы

```bash
command -v apt-get apt-cache dpkg-query lsblk findmnt mount umount mountpoint
sudo sh -c 'command -v losetup sfdisk blkid mkfs.xfs xfs_info xfs_repair udevadm modprobe'
```

`command -v` выводит путь к найденной программе; `-v` здесь означает просмотр команды. Во второй строке `sudo` запускает `sh`, а `sh -c` выполняет переданную строку команд. Одинарные кавычки передают её как один аргумент. Проверка административных утилит выполняется с путём поиска, доступным через `sudo`, поскольку `/sbin` может отсутствовать в обычном пользовательском `PATH`.

**Пример сокращённого результата:**

```text
/usr/bin/apt-get
/usr/bin/apt-cache
/usr/bin/dpkg-query
/bin/lsblk
/bin/findmnt
...
/sbin/losetup
/sbin/sfdisk
/sbin/blkid
/sbin/mkfs.xfs
/sbin/xfs_info
/sbin/xfs_repair
/bin/udevadm
/sbin/modprobe
```

Пути могут начинаться с `/usr/bin` или `/usr/sbin`. Если имя отсутствует в выводе, соответствующая программа не найдена в этом окружении. Не подменяйте её случайным файлом из Интернета.

#### 2.3. Посмотрите состояние пакета xfsprogs

```bash
dpkg-query -W -f='${binary:Package}\t${Version}\t${Status}\n' xfsprogs
apt-cache policy xfsprogs
```

`dpkg-query -W` запрашивает сведения о конкретном пакете. `-f` задаёт формат: `${binary:Package}` — имя, `${Version}` — версия, `${Status}` — состояние. Это поля `dpkg-query`, поэтому одинарные кавычки защищают их от подстановки Bash. `\t` разделяет поля табуляцией, `\n` завершает строку.

`apt-cache policy` читает уже известные APT сведения о версиях; `policy` — действие, а не флаг. Сеть при этом не опрашивается.

**Пример результата при установленном пакете:**

```text
xfsprogs    ...    install ok installed
xfsprogs:
  Installed: ...
  Candidate: ...
  Version table:
    ...
```

Если пакет не установлен, `dpkg-query` сообщит `no packages found matching xfsprogs`, а в `policy` может быть `Installed: (none)`. Это ожидаемая ситуация, а не повреждение файловой системы.

**Что должно получиться.** Вы поняли, требуется ли подготовка инструментов. При уже доступных `mkfs.xfs`, `xfs_info` и `xfs_repair` переустановка не нужна.

#### 2.4. Проверьте источники перед установкой

```bash
cat /etc/apt/sources.list
ls -l /etc/apt/sources.list.d/
apt-cache policy
```

`cat` читает основной список источников, флагов нет. `ls -l` показывает файлы дополнительных источников и их свойства. `apt-cache policy` выводит источники и приоритеты, известные по существующим индексам.

**Пример структуры вывода:**

```text
deb ...
total ...
...
Package files:
 100 /var/lib/dpkg/status
     release a=now
 ...
```

**Что должно получиться.** Вы увидели источники вашей Astra Linux. Источник может быть внутренним зеркалом, разрешённым сетевым репозиторием или доступным установочным источником. Если основной файл отсутствует, настройки могут находиться в `sources.list.d`; это нужно оценить по конкретной системе.

Не копируйте сюда адреса Debian или Ubuntu. Совпадение расширения `.deb` не означает совместимость пакетов. Подключение репозитория лишь добавляет источник, а не устанавливает ПО автоматически. Создавать новый репозиторий ради упражнения с XFS не требуется: используйте уже разрешённые источники.

#### 2.5. Если xfsprogs отсутствует

При доступных разрешённых источниках сначала обновите индексы и посмотрите план:

```bash
sudo apt-get update
sudo apt-get --simulate --no-remove --no-upgrade --no-install-recommends install xfsprogs
```

| Элемент | Значение |
| --- | --- |
| `sudo` | Даёт административные права |
| `apt-get update` | Получает сведения о доступных пакетах, не обновляя установленные программы |
| `--simulate` | Только рассчитывает план установки |
| `--no-remove` | Останавливает операцию, требующую удаления пакетов |
| `--no-upgrade` | Не обновляет уже установленный пакет, явно названный в команде; это не общий запрет на обновление всех зависимостей |
| `--no-install-recommends` | Не включает необязательные рекомендации |
| `install xfsprogs` | Выбирает пакет инструментов XFS |

**Пример подходящего сокращённого результата:**

```text
Reading package lists... Done
The following NEW packages will be installed:
  xfsprogs
0 upgraded, 1 newly installed, 0 to remove ...
```

Фактический план зависит от состояния системы. Если он требует обновления библиотек, замены пакетной системы или изменения работающих служб, не выполняйте его ради этой практики. Недостающие зависимости должен оценить администратор.

При ожидаемом плане и разрешённой установке:

```bash
sudo apt-get --no-remove --no-upgrade --no-install-recommends install xfsprogs
sudo sh -c 'command -v mkfs.xfs xfs_info xfs_repair'
```

У первой команды убран только `--simulate`: установка теперь настоящая. Остальные флаги сохраняют разобранный смысл. Прочитайте план ещё раз до ответа на запрос подтверждения. Вторая строка через `sh -c` проверяет наличие инструментов; `command -v` выводит их пути.

**Пример сокращённого результата:**

```text
Setting up xfsprogs (...) ...
/sbin/mkfs.xfs
/sbin/xfs_info
/sbin/xfs_repair
```

Если отсутствует только `sfdisk`, отдельно рассмотрите установку пакета `fdisk` из тех же проверенных источников. Он не заменяет XFS и не запускает разметку автоматически. При уже доступном `sfdisk` этот вариант пропустите.

```bash
sudo apt-get --simulate --no-remove --no-upgrade --no-install-recommends install fdisk
```

`--simulate` только рассчитывает план, `--no-remove` запрещает удаления, `--no-upgrade` не обновляет уже установленный явно названный пакет, `--no-install-recommends` исключает рекомендации. `install fdisk` выбирает пакет инструмента разметки, `sudo` предоставляет права чтения административных настроек.

**Пример подходящего результата:**

```text
The following NEW packages will be installed:
  fdisk
0 upgraded, 1 newly installed, 0 to remove ...
```

Если план ожидаемый и установка разрешена, выполните её:

```bash
sudo apt-get --no-remove --no-upgrade --no-install-recommends install fdisk
sudo sh -c 'command -v sfdisk'
```

Убран только `--simulate`: установка настоящая. Параметры `--no-remove`, `--no-upgrade` и `--no-install-recommends` имеют тот же смысл; повторно проверьте план до подтверждения. `sh -c` выполняет строку проверки в окружении `sudo`, `command -v` показывает найденную программу.

**Пример сокращённого результата:**

```text
Setting up fdisk (...) ...
/sbin/sfdisk
```

На машине без доступа к источникам инструменты с зависимостями нужно подготовить заранее. Не меняйте сеть и правила SSH ради установки пакетов. Основная практика ниже не требует Интернета после подготовки инструментов.

#### 2.6. Проверьте поддержку XFS в ядре

```bash
grep -w xfs /proc/filesystems
```

`grep` выбирает строки по шаблону; `-w` требует совпадения отдельного слова `xfs`. `/proc/filesystems` показывает файловые системы, известные текущему ядру. Чтение этого файла ничего не монтирует.

**Пример результата:**

```text
        xfs
```

Если строки нет, драйвер может существовать как ещё не загруженный модуль. При разрешённой загрузке штатного модуля текущего ядра:

```bash
sudo modprobe xfs
grep -w xfs /proc/filesystems
```

`modprobe` загружает модуль и необходимые ему модули по имени; флагов в этом вызове нет. Это не установка пакета и не форматирование диска. Повторная `grep -w` проверяет появление поддержки.

**Ожидаемый результат:** `modprobe` обычно молчит, затем выводится строка `xfs`. Если модуль отсутствует или операция запрещена политикой Astra Linux, остановитесь и уточните подготовку учебной ВМ. Средства защиты не отключаются, модуль после упражнения принудительно не выгружается.

### 3. Что такое XFS и как она связана с устройством

XFS — файловая система с журналом метаданных. Журнал помогает восстановить согласованность структур после прерывания работы, но не является резервной копией и не гарантирует сохранение каждого последнего изменения приложения.

| Объект | Что означает | Что будет в практике |
| --- | --- | --- |
| Файл-образ | Обычный файл, изображающий накопитель | `disk.img`, размер 512 MiB |
| Loop-устройство | Связь ядра, предоставляющая доступ к файлу как к блочному устройству | `/dev/loopN` |
| Таблица разделов | Описание областей накопителя | MBR внутри образа |
| Раздел | Одна область устройства | `/dev/loopNp1`, размер 480 MiB |
| XFS | Способ организации файлов и метаданных внутри раздела | Создаётся один раз на пустом учебном разделе |
| Точка монтирования | Каталог, через который видны файлы XFS | `/mnt/astra-xfs-UID` |
| LABEL | Короткая метка файловой системы | Например, `X1000` |
| UUID | Идентификатор файловой системы | Получается через `blkid` |

Имя `/dev/loopN` может измениться после отключения и нового подключения. UUID остаётся прежним, пока не выполнено новое форматирование или специальное изменение идентификатора. UUID файловой системы и `PARTUUID` раздела — разные свойства.

Если реальный новый диск **уже имеет нужную XFS**, его не форматируют заново: проверяют устройство, свойства и монтируют существующую файловую систему. `mkfs.xfs` ниже нужен только для изготовления собственной пустой модели.

### 4. Что меняет noatime

У файла есть несколько разных временных отметок:

| Отметка | Смысл |
| --- | --- |
| `atime` | Время доступа к содержимому |
| `mtime` | Время изменения содержимого |
| `ctime` | Время изменения состояния inode, например прав или владельца; это не время создания |

Чтение файла может требовать обновления `atime`. Параметр `noatime` отключает автоматическое обновление этой отметки при доступе, в том числе для каталогов. Он не отключает изменения содержимого, `mtime` и `ctime`, а также не запрещает явную установку временных отметок командой `touch`.

На Linux часто уже используется `relatime`: время доступа обновляется не при каждом чтении, а при выполнении определённых условий. Поэтому выигрыш от `noatime` зависит от нагрузки и исходного режима. Сам факт добавления параметра не доказывает ускорение приложения или измеримое продление ресурса физического носителя. В образе мы проверим поведение времени доступа, а не проведём испытание ресурса диска.

В условии задания упоминается GxP. Для практики используем только вымышленные записи. `atime` не заменяет журнал действий приложения, а контрольная сумма не заменяет управление доступом и проверяемый аудит. Если приложение рассчитывает на время доступа, отключение его обновления должно соответствовать требованиям этого приложения. Одно монтирование с `noatime` не подтверждает соответствие системы GxP.

### 5. Как устроена строка fstab и почему для XFS выбран pass=0

Таблица `fstab` содержит описания источника, точки, типа и параметров. Для физического раздела пример формата выглядит так:

```text
UUID=<фактический_UUID> /путь/к/данным xfs defaults,noatime 0 0
```

Это **шаблон**, а не команда для вставки в рабочий `/etc/fstab`. Фактическую строку мы сформируем из переменных во второй части.

| Поле | Объяснение |
| --- | --- |
| `UUID=...` | Источник определяется идентификатором файловой системы |
| `/путь/к/данным` | Точка монтирования должна существовать |
| `xfs` | Тип файловой системы |
| `defaults,noatime` | Набор параметров, разделённых запятыми |
| Первый `0` | Не включать файловую систему в отбор утилитой резервного копирования dump |
| Второй `0` | Не назначать обычную проверку через fsck по этой записи |

`defaults` обозначает стандартный набор, в том числе чтение и запись, автоматический отбор при общем монтировании и обычные ограничения на пользовательское монтирование. Конкретное поведение зависит также от ядра и типа файловой системы. Для учебного каталога дополнительно укажем `nosuid,nodev,noexec`.

В исходном задании приведён последний столбец `2`. Для XFS здесь используем **`0`**: `fsck.xfs` не выполняет проверку, аналогичную `e2fsck`, и обычно просто успешно завершается. При необходимости согласованность XFS исследуют её собственными инструментами; `xfs_repair` запускают на размонтированной файловой системе. В этой практике автоматическое исправление и сброс журнала не применяются.

При загрузке Astra Linux настройки настоящего `/etc/fstab` обрабатываются системными механизмами монтирования. Здесь мы не меняем этот файл и не перезагружаем сервер. Вместо этого повторно подключим образ и проверим применение отдельной модели таблицы.

### 6. Что проверить перед началом изменений

#### 6.1. Посмотрите устройства и системное монтирование

```bash
lsblk -o NAME,TYPE,SIZE,FSTYPE,LABEL,UUID,MOUNTPOINT
findmnt --target / --output SOURCE,TARGET,FSTYPE,OPTIONS
cat /etc/fstab
```

`lsblk` перечисляет блочные устройства; `-o` задаёт столбцы: имя, тип объекта, размер, тип файловой системы, метку, UUID и точку монтирования.

`findmnt --target /` показывает файловую систему, содержащую путь `/`; `--output` выбирает источник, точку, тип и параметры. `cat` читает существующий `/etc/fstab` без изменений, флагов нет.

**Пример сокращённого результата:**

```text
NAME TYPE SIZE FSTYPE LABEL UUID MOUNTPOINT
vda  disk  30G
vda1 part  29G ext4         ...  /
...
SOURCE    TARGET FSTYPE OPTIONS
/dev/vda1 /      ext4   rw,relatime,...
# ...
UUID=... / ext4 defaults 0 1
```

**Что должно получиться.** Вы узнали системное устройство и не используете его в последующих изменяющих командах. Пустая точка монтирования в `lsblk` не означает, что диск свободен для форматирования: он может быть частью LVM, использоваться как swap или содержать нужные данные.

#### 6.2. Проверьте свободное место

```bash
df -hT /var/tmp /mnt "$HOME"
```

`df` показывает заполнение файловых систем. `-h` выводит размеры в удобных единицах; `-T` добавляет тип. Пути выбирают соответствующие файловые системы, `$HOME` — домашний каталог текущего пользователя удалённой машины.

**Пример структуры результата:**

```text
Filesystem     Type Size Used Avail Use% Mounted on
/dev/vda1      ext4  29G  12G   16G  43% /
/dev/vda1      ext4  29G  12G   16G  43% /
...
```

Повторение строк допустимо. Для практики желательно иметь не менее 1 GiB свободного места на файловой системе `/var/tmp`, чтобы оставить запас для образа 512 MiB и работы сервера. Разреженный образ сначала может занимать меньше своей логической длины, но на это нельзя полагаться как на замену свободному месту.

После подготовки должны быть доступны Bash, разрешённый `sudo`, инструменты XFS и loop, поддержка XFS в ядре и свободное место. В ограниченном контейнере монтирование может быть запрещено даже root; обходить такую политику не нужно.

## Часть 2. Практика: XFS, noatime и подключение по UUID на одной машине

### 1. Задание в условиях удалённой учебной машины

На сервере нужно сделать доступным новое хранилище XFS для вымышленных записей лабораторного журнала. Необходимо определить устройство, подготовить точку монтирования, подключить XFS с `noatime`, дать доступ через отдельный каталог, сохранить описание с UUID и проверить повторное подключение по этому описанию.

Вместо физического диска создадим собственный файл `disk.img`. На нём будет один раздел XFS. Все команды выполняются в текущем SSH-сеансе на этой же машине. Никаких реальных журналов исследований и производственных документов в упражнении нет.

Модель `fstab` находится в нашем каталоге, а не в системном `/etc`. Она содержит запись для автоматического отбора при общем монтировании, без `noauto`. После повторного подключения образа применим только эту таблицу. Это эмуляция этапа монтирования по сохранённой конфигурации, а не испытание реальной загрузки ОС.

### 2. Подготовьте имена объектов

#### 2.1. Сохраните значения в переменные

```bash
XFS_UID="$(id -u)"
XFS_GID="$(id -g)"
XFS_BASE="/var/tmp/astra-xfs-$XFS_UID"
XFS_IMAGE="$XFS_BASE/disk.img"
XFS_MNT="/mnt/astra-xfs-$XFS_UID"
XFS_LABEL="X$XFS_UID"
XFS_FSTAB="$XFS_BASE/model/etc/fstab"
printf '%s\n' "$XFS_IMAGE" "$XFS_MNT" "$XFS_LABEL" "$XFS_FSTAB"
```

`id -u` возвращает UID пользователя, `id -g` — его основную GID. `$(...)` подставляет вывод команды. Присваивание без пробелов вокруг `=` сохраняет значение переменной. Двойные кавычки защищают значение при подстановке.

| Переменная | Для чего нужна |
| --- | --- |
| `XFS_UID` | Ваш числовой идентификатор пользователя |
| `XFS_GID` | Числовой идентификатор вашей основной группы |
| `XFS_BASE` | Собственный каталог этой практики |
| `XFS_IMAGE` | Файл, изображающий диск |
| `XFS_MNT` | Собственная точка монтирования |
| `XFS_LABEL` | Короткая метка XFS; префикс `X` оставляет её в пределах ограничения длины метки |
| `XFS_FSTAB` | Модель таблицы монтирования с путём `model/etc/fstab` |

`printf '%s\n'` печатает каждое значение с новой строки.

**Пример вывода:**

```text
/var/tmp/astra-xfs-1000/disk.img
/mnt/astra-xfs-1000
X1000
/var/tmp/astra-xfs-1000/model/etc/fstab
```

Все дальнейшие переменные `$XFS_...` оставляйте в командах как написано. Не заменяйте их значениями UID и устройства из примеров.

#### 2.2. Убедитесь, что пути не заняты

```bash
ls -ld "$XFS_BASE" "$XFS_MNT"
```

`ls -l` показывает подробности, `-d` — сам каталог вместо его содержимого.

**Ожидаемый результат первого запуска:**

```text
ls: cannot access '/var/tmp/astra-xfs-1000': No such file or directory
ls: cannot access '/mnt/astra-xfs-1000': No such file or directory
```

Это ожидаемые сообщения: наших каталогов пока нет. Если путь уже существует, не продолжайте создание и форматирование. Восстановите состояние прежней попытки по разделу 12 части 2. Отказ в доступе — не доказательство отсутствия пути.

#### 2.3. Создайте каталоги

```bash
sudo mkdir -m 0755 -- "$XFS_BASE" "$XFS_MNT"
sudo install -d -m 0755 "$XFS_BASE/model/etc"
ls -ld "$XFS_BASE" "$XFS_MNT" "$XFS_BASE/model/etc"
```

`mkdir` создаёт два новых каталога. `-m 0755` разрешает владельцу чтение, запись и проход, остальным — чтение и проход. `--` завершает список флагов. Здесь нет `-p`: существующий путь вызовет ошибку и обнаружит повторный запуск.

`install -d` создаёт каталог с промежуточными путями, `-m 0755` задаёт права. При выполнении через `sudo` владельцем будет root. `ls -ld` проверяет свойства созданных каталогов.

**Пример результата:**

```text
drwxr-xr-x ... root root ... /mnt/astra-xfs-1000
drwxr-xr-x ... root root ... /var/tmp/astra-xfs-1000
drwxr-xr-x ... root root ... /var/tmp/astra-xfs-1000/model/etc
```

**Что должно получиться.** Появились новые каталоги, не занятые другими данными. Образ и модель конфигурации будут защищены от замены обычным пользователем.

### 3. Создайте новый диск внутри файла

#### 3.1. Подготовьте образ 512 MiB

```bash
sudo test ! -e "$XFS_IMAGE" && sudo truncate -s 512M "$XFS_IMAGE"
sudo chmod 0600 "$XFS_IMAGE"
sudo ls -lh "$XFS_IMAGE"
sudo du -h "$XFS_IMAGE"
```

| Команда или параметр | Объяснение |
| --- | --- |
| `test ! -e` | Проверяет отсутствие указанного пути: `-e` означает существование, `!` — отрицание |
| `&&` | Выполняет следующую команду только после успеха предыдущей |
| `truncate` | Задаёт логическую длину обычного файла |
| `-s 512M` | Размер 512 × 1024 × 1024 байт |
| `chmod 0600` | Чтение и запись только владельцу root |
| `ls -lh` | Подробный вывод с удобным представлением логического размера |
| `du -h` | Фактически выделенное дисковое место в удобных единицах |

**Пример результата:**

```text
-rw------- 1 root root 512M ... /var/tmp/astra-xfs-1000/disk.img
0       /var/tmp/astra-xfs-1000/disk.img
```

Образ может оказаться разреженным: логическая длина уже 512 MiB, но ещё не записанные области пока не занимают столько блоков. При форматировании и записи потребление места увеличится. Различие `ls` и `du` здесь нормально.

Этот шаг не повторяется над уже используемым образом. При ошибке проверки существования или создания остановитесь.

#### 3.2. Создайте один раздел 480 MiB

```bash
sudo sfdisk "$XFS_IMAGE" <<'EOF'
label: dos
unit: sectors

start=2048, size=983040, type=83
EOF
sudo sfdisk --dump "$XFS_IMAGE"
```

`sfdisk` записывает описание разделов в **наш файл-образ**, а не в физический диск. В первой команде флагов нет. `<<'EOF'` передаёт строки до завершающего маркера без подстановки переменных в тексте описания.

| Запись | Значение |
| --- | --- |
| `label: dos` | Таблица разделов MBR/DOS; не тип файловой системы |
| `unit: sectors` | Начало и длина указаны в секторах |
| `start=2048` | Начало первого раздела на отметке 1 MiB при секторе 512 байт |
| `size=983040` | 983040 × 512 байт = 480 MiB |
| `type=83` | Тип Linux-раздела в MBR; XFS пока не создана |
| `--dump` | Прочитать и напечатать существующую таблицу, не создавая её повторно |

**Пример сокращённого результата:**

```text
Disk .../disk.img: 512 MiB, 536870912 bytes, 1048576 sectors
... Created a new partition ... of size 480 MiB.
The partition table has been altered.
label: dos
device: /var/tmp/astra-xfs-1000/disk.img
unit: sectors
...disk.img1 : start=2048, size=983040, type=83
```

**Что должно получиться.** Один раздел 480 MiB внутри образа 512 MiB. Такой размер оставляет запас по минимальным требованиям инструментов создания XFS; маленький образ из упражнения с ext4 сюда переносить не нужно. Часть места вне раздела остаётся свободной.

### 4. Подключите образ и подтвердите устройство

#### 4.1. Получите свободное loop-устройство

```bash
XFS_LOOP="$(sudo losetup --find --show --partscan --nooverlap "$XFS_IMAGE")"
XFS_PART="${XFS_LOOP}p1"
sudo udevadm settle --timeout=10
printf '%s\n' "$XFS_LOOP" "$XFS_PART"
```

`losetup` связывает образ с loop-устройством. `--find` выбирает свободное устройство, `--show` печатает его имя, `--partscan` просит прочитать таблицу разделов, `--nooverlap` не создаёт независимую повторную связь для уже используемого образа. Вывод сохраняется в `XFS_LOOP`.

`XFS_PART="${XFS_LOOP}p1"` добавляет к имени устройства обозначение первого раздела. Фигурные скобки отделяют имя переменной от текста `p1`.

`udevadm settle` ждёт завершения обработки событий устройств, `--timeout=10` ограничивает ожидание десятью секундами. `printf` показывает значения.

**Пример результата:**

```text
/dev/loop9
/dev/loop9p1
```

Если `losetup` или обработка событий завершились ошибкой, не продолжайте. Пустой путь и отсутствие раздела нельзя исправлять подстановкой реального диска сервера.

#### 4.2. Посмотрите связь и дерево нашего устройства

```bash
sudo losetup --list --output NAME,BACK-FILE "$XFS_LOOP"
lsblk -o NAME,TYPE,SIZE,FSTYPE,MOUNTPOINT "$XFS_LOOP"
```

`losetup --list` включает таблицу, `--output NAME,BACK-FILE` выбирает имя и файл-основу. Последний аргумент ограничивает просмотр нашим устройством.

`lsblk -o` выбирает столбцы. Переданный `$XFS_LOOP` ограничивает дерево именно этим устройством и его разделом.

**Пример результата:**

```text
NAME       BACK-FILE
/dev/loop9 /var/tmp/astra-xfs-1000/disk.img
NAME     TYPE SIZE FSTYPE MOUNTPOINT
loop9    loop 512M
loop9p1  part 480M
```

`FSTYPE` пока пуст: разметка не создаёт XFS. Продолжайте только при совпадении `BACK-FILE` с вашим образом.

#### 4.3. Определите проверку перед форматированием

```bash
xfs_check_device() {
    local backing
    if [[ ! "$XFS_LOOP" =~ ^/dev/loop[0-9]+$ ]] || [[ "$XFS_PART" != "${XFS_LOOP}p1" ]] || [[ ! -b "$XFS_PART" ]]; then
        printf '%s\n' 'STOP: expected training loop partition is absent.' >&2
        return 1
    fi
    backing="$(sudo losetup --list --noheadings --raw --output BACK-FILE "$XFS_LOOP")" || return 1
    if [[ "$backing" != "$XFS_IMAGE" ]]; then
        printf '%s\n' 'STOP: loop device belongs to another image.' >&2
        return 1
    fi
    printf '%s\n' "OK: $XFS_PART belongs to $XFS_IMAGE"
}
xfs_check_device
```

Это функция Bash: именованная последовательность проверок. Определение функции само по себе ничего не форматирует, последняя строка вызывает проверку.

| Элемент | Объяснение |
| --- | --- |
| `local backing` | Переменная, существующая только внутри вызова функции |
| `[[ ... ]]` | Условие Bash |
| `=~ ^/dev/loop[0-9]+$` | Имя строго вида `/dev/loop` и одна или больше цифр |
| `!` | Отрицание |
| `!=` | Строки не равны |
| `-b` | Путь существует как блочное устройство |
| `||` | Переход к обработке ошибки при неуспешном условии или команде |
| `--noheadings` | Вывод без заголовка |
| `--raw` | Вывод без выравнивающих отступов таблицы |
| `--output BACK-FILE` | Только файл-основа устройства |
| `>&2` | Направление сообщения в поток ошибок |
| `return 1` | Завершение функции с признаком ошибки |

`--list` сохраняет табличный режим `losetup`, а сравнение проверяет точное совпадение с нашим `$XFS_IMAGE`.

**Пример результата:**

```text
OK: /dev/loop9p1 belongs to /var/tmp/astra-xfs-1000/disk.img
```

**Что должно получиться.** Подтверждены имя, наличие раздела и принадлежность образу. Не изменяйте loop-связи между проверкой и следующим действием.

### 5. Создайте XFS на пустом учебном разделе

#### 5.1. Выполните форматирование один раз

```bash
xfs_check_device && sudo mkfs.xfs -L "$XFS_LABEL" "$XFS_PART"
```

Функция проверяет устройство. `&&` разрешает следующую команду только после успеха проверки. `mkfs.xfs` создаёт XFS, `-L` задаёт метку, последний аргумент выбирает раздел нашего образа. `sudo` нужен для записи в блочное устройство.

Флага `-f` для принудительной перезаписи здесь нет. Если инструмент обнаружил неожиданную существующую файловую систему или сообщает об использовании устройства, остановитесь и проверьте состояние. Не добавляйте принудительный флаг ради продолжения.

**Пример структуры результата:**

```text
OK: /dev/loop9p1 belongs to /var/tmp/astra-xfs-1000/disk.img
meta-data=/dev/loop9p1 ...
data     = ...
naming   = ...
log      =internal ...
realtime =none ...
```

Числа зависят от версии `xfsprogs` и настроек. `meta-data` описывает метаданные, `data` — область данных, `log` — журнал, `realtime` — отдельную область специального назначения, которая здесь не создаётся.

**Что должно получиться.** XFS создана только внутри учебного раздела. На этой стадии она ещё не смонтирована. Позже при повторном подключении этот шаг не повторяют.

#### 5.2. Сохраните UUID

```bash
sudo blkid "$XFS_PART"
XFS_UUID="$(sudo blkid -s UUID -o value "$XFS_PART")"
printf '%s\n' "$XFS_UUID"
lsblk -o NAME,TYPE,SIZE,FSTYPE,LABEL,UUID,MOUNTPOINT "$XFS_LOOP"
```

`blkid` читает свойства файловой системы. В первом вызове флагов нет. Во втором `-s UUID` выбирает поле UUID, `-o value` печатает только значение; подстановка сохраняет его в переменной. `printf` показывает сохранённую строку. `lsblk -o` выбирает столбцы нашей ветки устройств.

**Пример сокращённого результата:**

```text
/dev/loop9p1: LABEL="X1000" UUID="aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee" TYPE="xfs" ...
aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee
NAME     TYPE SIZE FSTYPE LABEL UUID                                 MOUNTPOINT
loop9    loop 512M
loop9p1  part 480M xfs    X1000 aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee
```

**Что должно получиться.** UUID непустой, тип — `xfs`, метка соответствует вашей. Если тип другой, не переходите к монтированию с `-t xfs` и не форматируйте устройство повторно без выяснения причины.

### 6. Выполните ручное монтирование с noatime

#### 6.1. Подключите раздел в собственный каталог

```bash
xfs_check_device && sudo mount -t xfs -o rw,noatime,nosuid,nodev,noexec "$XFS_PART" "$XFS_MNT"
findmnt --mountpoint "$XFS_MNT" --output SOURCE,TARGET,FSTYPE,OPTIONS
```

`mount` подключает файловую систему к каталогу. `-t xfs` задаёт тип. `-o` передаёт параметры, разделённые запятыми. Последние два аргумента — источник и точка монтирования. Вызов выполняется после проверки устройства.

| Параметр | Что означает |
| --- | --- |
| `rw` | Чтение и запись |
| `noatime` | Не обновлять автоматически время доступа |
| `nosuid` | Не учитывать соответствующие привилегии set-user-ID/set-group-ID на этом монтировании |
| `nodev` | Не интерпретировать файлы устройств на носителе как устройства |
| `noexec` | Не разрешать непосредственный запуск исполняемых файлов с этой файловой системы |

Эти ограничения подходят нашему каталогу данных. `noexec` не мешает программе прочитать сценарий как обычный текст и не является полной изоляцией содержимого.

`findmnt --mountpoint` ищет точное монтирование в указанном каталоге; `--output` выбирает источник, точку, тип и параметры.

**Пример сокращённого результата:**

```text
OK: /dev/loop9p1 belongs to /var/tmp/astra-xfs-1000/disk.img
SOURCE       TARGET               FSTYPE OPTIONS
/dev/loop9p1 /mnt/astra-xfs-1000   xfs    rw,nosuid,nodev,noexec,noatime,...
```

Сам `mount` при успехе обычно ничего не печатает. Порядок параметров в выводе может отличаться. Главное — источник наш, тип `xfs`, присутствует `noatime`.

#### 6.2. Определите проверку монтирования

```bash
xfs_check_mount() {
    local source fstype
    xfs_check_device || return 1
    source="$(findmnt --noheadings --raw --mountpoint "$XFS_MNT" --output SOURCE)" || return 1
    fstype="$(findmnt --noheadings --raw --mountpoint "$XFS_MNT" --output FSTYPE)" || return 1
    if [[ "$source" != "$XFS_PART" || "$fstype" != xfs ]]; then
        printf '%s\n' 'STOP: expected XFS is not mounted at the training path.' >&2
        return 1
    fi
    printf '%s\n' "OK: $XFS_MNT is XFS from $XFS_PART"
}
xfs_check_mount
```

Функция сначала проверяет устройство, затем точный источник и тип монтирования. `local` ограничивает временные переменные вызовом функции. `findmnt --noheadings --raw` убирает заголовок и выравнивание; `--mountpoint` выбирает точный каталог, `--output` — нужное поле. `|| return 1` останавливает функцию при ошибке. `!=` означает неравенство, `>&2` — поток ошибок.

**Пример результата:**

```text
OK: /dev/loop9p1 belongs to /var/tmp/astra-xfs-1000/disk.img
OK: /mnt/astra-xfs-1000 is XFS from /dev/loop9p1
```

**Что должно получиться.** Перед записью можно подтвердить, что вы обращаетесь к нашей XFS, а не к каталогу на системном разделе под отсутствующим монтированием.

#### 6.3. Посмотрите параметры XFS и доступное место

```bash
xfs_check_mount && sudo xfs_info "$XFS_MNT"
df -hT "$XFS_MNT"
```

`xfs_info` читает геометрию смонтированной XFS; флагов в этом вызове нет. Она не форматирует и не увеличивает файловую систему. Проверка перед `&&` подтверждает правильный объект.

`df -hT` показывает использование места в удобных единицах и тип файловой системы. Аргумент выбирает нашу точку.

**Пример структуры результата:**

```text
OK: ...
OK: ...
meta-data=/dev/loop9p1 ...
data     = ...
log      =internal ...
...
Filesystem     Type Size Used Avail Use% Mounted on
/dev/loop9p1    xfs   ...  ...   ...   ... /mnt/astra-xfs-1000
```

Размер полезного пространства меньше размера раздела из-за структур самой XFS. Это не причина повторно запускать `mkfs` или менять размер системного диска.

### 7. Сделайте учебные данные доступными пользователю и группе

Корень новой XFS первоначально принадлежит root. Для упражнения не меняем владельца всей точки рекурсивно и не открываем всем запись. Создадим внутри один каталог, доступный вам и вашей основной группе.

#### 7.1. Подготовьте каталог с наследованием группы

```bash
xfs_check_mount && sudo install -d -o "$XFS_UID" -g "$XFS_GID" -m 2770 "$XFS_MNT/records"
ls -ld "$XFS_MNT/records"
```

`install -d` создаёт каталог. `-o` назначает владельца по UID, `-g` — группу по GID, `-m 2770` задаёт права. `sudo` нужен для создания каталога в корне файловой системы.

В `2770` старшая `2` включает setgid для каталога: новые объекты наследуют его группу. `7` разрешает чтение, запись и проход владельцу; следующая `7` — группе; `0` не даёт доступа остальным. Для каталога «выполнение» означает возможность проходить по пути.

**Пример результата:**

```text
OK: ...
OK: ...
drwxrws--- 2 student student ... /mnt/astra-xfs-1000/records
```

Буква `s` в группе показывает setgid каталога. Его наследование группы работает и при параметре монтирования `nosuid`; это не выдаёт исполняемому файлу привилегии.

**Что должно получиться.** Доступ есть у вашей учётной записи и членов выбранной группы. Если ваша основная группа содержит только вас, второй пользователь автоматически не появится. Создание реальных пользователей, изменение групп и предоставление прав на производственные данные в упражнение не входят. Дополнительные ограничения Astra Linux также продолжают действовать.

#### 7.2. Создайте вымышленный журнал и ведомость сумм

```bash
xfs_check_mount && (
    umask 0007
    printf '%s\n' 'Training record 001' 'No real laboratory data are stored here.' > "$XFS_MNT/records/journal.txt"
    cd "$XFS_MNT/records"
    sha256sum journal.txt > SHA256SUMS
)
cat "$XFS_MNT/records/journal.txt"
ls -l "$XFS_MNT/records"
```

Круглые скобки запускают группу команд в отдельной подоболочке. Поэтому установленная там `umask` не изменяет маску вашей основной оболочки после завершения блока.

`umask 0007` убирает все права остальных пользователей у вновь создаваемых объектов. Для обычного файла с исходным режимом `0666` получится `0660`: чтение и запись владельцу и группе. Наследуемая группа берётся от каталога с setgid.

`printf '%s\n'` записывает две строки. `>` создаёт или перезаписывает только названный учебный файл. `cd` меняет каталог внутри подоболочки. `sha256sum` вычисляет SHA-256 и сохраняет относительное имя вместе с суммой в `SHA256SUMS`. `cat` читает журнал, `ls -l` показывает права файлов.

**Пример результата:**

```text
OK: ...
OK: ...
Training record 001
No real laboratory data are stored here.
total ...
-rw-rw---- 1 student student ... journal.txt
-rw-rw---- 1 student student ... SHA256SUMS
```

**Что должно получиться.** Файлы доступны выбранному владельцу и группе. Они не содержат настоящих сведений о пациентах, исследованиях или производстве. Возможность изменить и файл, и ведомость означает, что такая сумма не доказывает защиту от умышленной подмены.

### 8. Проверьте смысл noatime на собственном файле

Не нужно запускать нагрузочный тест или заполнять диск. Достаточно установить старую отметку доступа, прочитать файл и сравнить её до и после. Содержимое файла при этом не меняется.

#### 8.1. Установите старое время доступа и сохраните значение

```bash
xfs_check_mount && touch -a -t 200001010000 "$XFS_MNT/records/journal.txt"
stat -c 'atime=%x | mtime=%y | ctime=%z' "$XFS_MNT/records/journal.txt"
XFS_ATIME_BEFORE="$(stat -c '%X' "$XFS_MNT/records/journal.txt")"
```

`touch -a` меняет только отметку доступа; `-t 200001010000` задаёт 1 января 2000 года, 00:00 в часовом поясе сервера. Эта явная установка разрешена и при `noatime`: параметр запрещает автоматическое обновление при доступе, а не ручное изменение отметки.

`stat` показывает свойства файла. `-c` задаёт формат. `%x` — время доступа, `%y` — изменения содержимого, `%z` — изменения состояния inode. Символы `|` находятся в кавычках и являются частью текста, а не конвейерами. `%X` возвращает время доступа как целое число секунд с начала эпохи Unix. Подстановка сохраняет это число в переменной.

**Пример структуры результата:**

```text
OK: ...
OK: ...
atime=2000-01-01 00:00:00.000000000 ... | mtime=... | ctime=...
```

`ctime` после `touch` может измениться: это ожидаемое изменение состояния inode. `mtime` не должно измениться только из-за установки `atime`.

#### 8.2. Прочитайте файл и сравните отметки

```bash
cat "$XFS_MNT/records/journal.txt" > /dev/null
XFS_ATIME_AFTER="$(stat -c '%X' "$XFS_MNT/records/journal.txt")"
printf 'before=%s\nafter=%s\n' "$XFS_ATIME_BEFORE" "$XFS_ATIME_AFTER"
if [[ -n "$XFS_ATIME_BEFORE" && "$XFS_ATIME_BEFORE" = "$XFS_ATIME_AFTER" ]]; then
    printf '%s\n' 'OK: reading did not update atime.'
else
    printf '%s\n' 'STOP: check the actual mount options and background access.'
fi
```

`cat` читает файл полностью. `> /dev/null` убирает его содержимое с экрана, но чтение выполняется. `stat -c '%X'` снова получает отметку, `printf` показывает оба значения.

`-n` в условии требует непустую исходную отметку, `&&` требует успеха обеих проверок, а `=` сравнивает строки с числовыми отметками. При равенстве непустых значений печатается `OK`; при отличии или отсутствии результата нужно проверить реальное монтирование и возможные действия других процессов.

**Пример результата:**

```text
before=<число секунд>
after=<то же число секунд>
OK: reading did not update atime.
```

**Что должно получиться.** Чтение не обновило время доступа на монтировании с `noatime`. Это проверка одного свойства, а не доказательство ускорения приложения или соответствия GxP. Не изменяйте временные отметки реальных документов для повторения опыта.

### 9. Сохраните подключение по UUID в модели fstab

#### 9.1. Сформируйте фактическую строку

```bash
printf 'UUID=%s %s xfs defaults,noatime,nosuid,nodev,noexec 0 0\n' "$XFS_UUID" "$XFS_MNT" | sudo tee "$XFS_FSTAB"
```

`printf` подставляет UUID и путь в два `%s`, `\n` завершает строку. `|` передаёт её программе `tee`. `sudo tee` записывает файл с правами root и одновременно показывает строку в терминале. Флагов у `tee` здесь нет; запись идёт только в `$XFS_FSTAB` внутри нашей модели.

**Пример результата:**

```text
UUID=aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee /mnt/astra-xfs-1000 xfs defaults,noatime,nosuid,nodev,noexec 0 0
```

| Элемент строки | Смысл |
| --- | --- |
| `UUID=...` | Выбор XFS по её UUID, не по номеру loop |
| Путь `/mnt/astra-xfs-1000` | Собственная точка монтирования |
| `xfs` | Тип файловой системы |
| `defaults` | Стандартный набор параметров, включая автоматический отбор записи при общем монтировании |
| `noatime` | Не обновлять автоматически время доступа |
| `nosuid,nodev,noexec` | Ограничения для учебного каталога данных, разобранные выше |
| `0 0` | Не выбирать для dump и не назначать обычную проверку fsck |

Здесь **нет `noauto`**, иначе запись пропускалась бы при автоматическом отборе. Также не добавляем `nofail` просто ради маскировки ошибок: в нашей модели нужно заметить недоступность данных. Для реального обязательного хранилища поведение при его отсутствии определяется вместе с зависимостями приложения, а не одним универсальным флагом.

#### 9.2. Прочитайте таблицу и проверьте её без монтирования

```bash
cat "$XFS_FSTAB"
sudo findmnt --fstab --tab-file "$XFS_FSTAB" --output SOURCE,TARGET,FSTYPE,OPTIONS
sudo findmnt --verify --verbose --tab-file "$XFS_FSTAB"
```

`cat` читает файл без изменений. У `findmnt` параметр `--fstab` выбирает режим чтения таблицы, `--tab-file` задаёт нашу модель, `--output` выбирает столбцы. Следующая команда с `--verify` проверяет разбор и пригодность записи; `--verbose` добавляет подробности.

**Пример сокращённого результата:**

```text
UUID=... /mnt/astra-xfs-1000 xfs defaults,noatime,nosuid,nodev,noexec 0 0
SOURCE   TARGET               FSTYPE OPTIONS
UUID=... /mnt/astra-xfs-1000   xfs    defaults,noatime,nosuid,nodev,noexec
...
Success, no errors or warnings detected
```

**Что должно получиться.** Таблица содержит одну нашу запись, UUID разрешается в существующий раздел, ошибок проверки нет. При предупреждениях сначала выясните их смысл. Проверка таблицы ещё не подтверждает, что файловая система действительно смонтирована.

### 10. Смоделируйте повторное появление диска и применение таблицы

В этом разделе не перезагружается вся машина. Сначала штатно отключим только наш образ, затем подключим его вновь. После этого применим сохранённую таблицу без ручного выбора `/dev/loopNp1` в команде монтирования.

#### 10.1. Сохраните данные и размонтируйте

```bash
cd "$HOME"
sync
xfs_check_mount && sudo umount "$XFS_MNT"
if mountpoint -q "$XFS_MNT"; then
    printf '%s\n' 'STOP: training filesystem is still mounted.'
else
    printf '%s\n' 'Training filesystem is unmounted.'
fi
```

`cd "$HOME"` выводит текущую оболочку из каталога данных. `sync` просит записать накопленные изменения, флагов нет. Это не замена размонтированию.

`umount` без флагов отключает файловую систему от дерева путей после проверки источника. `mountpoint -q` тихо проверяет, осталось ли монтирование; `if` выбирает понятное сообщение.

**Пример результата:**

```text
OK: ...
OK: ...
Training filesystem is unmounted.
```

Если появляется `target is busy`, выйдите из этого каталога во всех своих оболочках и закройте свои файлы. Не используйте принудительное размонтирование и не завершайте неизвестные процессы сервера. Если монтирование осталось, следующий шаг не выполняется.

#### 10.2. Отключите связь с образом

```bash
if findmnt --noheadings --source "$XFS_PART"; then
    printf '%s\n' 'STOP: the training partition is still mounted.'
else
    xfs_check_device && sudo losetup --detach "$XFS_LOOP"
fi
sudo udevadm settle --timeout=10
sudo losetup --associated "$XFS_IMAGE"
```

`findmnt --source` ищет монтирования нашего раздела, `--noheadings` убирает заголовок. При найденном монтировании выполняется только сообщение об остановке.

`losetup --detach` отключает одно проверенное устройство. `udevadm settle --timeout=10` ожидает события. `losetup --associated` перечисляет связи только нашего образа.

**Ожидаемый результат:** строка `OK` проверки устройства, а последняя команда — без вывода. Если связь осталась, не продолжайте новое подключение и не удаляйте образ. Отключение ядром может откладываться при сохранённых ссылках на устройство.

#### 10.3. Подключите тот же образ и сравните UUID

```bash
XFS_LOOP="$(sudo losetup --find --show --partscan --nooverlap "$XFS_IMAGE")"
XFS_PART="${XFS_LOOP}p1"
sudo udevadm settle --timeout=10
xfs_check_device
XFS_CURRENT_UUID="$(sudo blkid -s UUID -o value "$XFS_PART")"
printf 'saved=%s\ncurrent=%s\n' "$XFS_UUID" "$XFS_CURRENT_UUID"
```

`losetup` использует те же параметры: `--find` — свободное устройство, `--show` — его путь, `--partscan` — чтение разделов, `--nooverlap` — контроль повторной связи. Переменные получают новое имя устройства и его первого раздела. `udevadm settle` с тайм-аутом ждёт обработку событий.

`blkid -s UUID -o value` читает текущий UUID. Его сохраняем в другую переменную, чтобы не затереть прежнее значение. `printf` показывает оба.

**Пример результата:**

```text
OK: /dev/loop10p1 belongs to /var/tmp/astra-xfs-1000/disk.img
saved=aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee
current=aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee
```

Номер loop может измениться, UUID должен остаться тем же. Разметка и `mkfs.xfs` **не повторяются**.

#### 10.4. Примените автоматический отбор только нашей таблицы

```bash
if [[ -n "$XFS_UUID" && "$XFS_CURRENT_UUID" = "$XFS_UUID" ]]; then
    xfs_check_device && sudo mount --all --fstab "$XFS_FSTAB" --types xfs --verbose
else
    printf '%s\n' 'STOP: the saved and current UUID do not match.'
fi
```

| Элемент | Значение |
| --- | --- |
| `[[ -n "$XFS_UUID" ]]` | UUID непустой |
| `&&` внутри условия | Обе проверки должны пройти |
| `=` | UUID совпадают |
| `xfs_check_device &&` | Монтирование запускается только после проверки нашего устройства |
| `mount --all` | Применяет подходящие записи таблицы, без ручного указания источника и точки в команде |
| `--fstab "$XFS_FSTAB"` | Выбирает только наш отдельный файл вместо системного `/etc/fstab` |
| `--types xfs` | Ограничивает типом XFS |
| `--verbose` | Печатает сведения о выполненном действии |

**Пример сокращённого результата:**

```text
OK: /dev/loop10p1 belongs to /var/tmp/astra-xfs-1000/disk.img
/mnt/astra-xfs-1000: successfully mounted
```

**Что должно получиться.** Система нашла нужную XFS по UUID из сохранённой таблицы и подключила её с параметрами этой строки. Это целевой аналог этапа применения конфигурации после появления диска.

Параметр `--fstab` здесь обязателен. Не заменяйте команду на общий `sudo mount -a`: он начнёт обрабатывать настоящий системный файл. И не считайте результат доказательством успешной перезагрузки: она не проводилась, а постоянное создание loop-связи не настраивалось.

#### 10.5. Проверьте источник, noatime и данные

```bash
xfs_check_mount
findmnt --mountpoint "$XFS_MNT" --output SOURCE,TARGET,FSTYPE,OPTIONS
sudo blkid "$XFS_PART"
cd "$XFS_MNT/records"
sha256sum -c SHA256SUMS
cd "$HOME"
```

Функция подтверждает точное монтирование нашей XFS. `findmnt --mountpoint` выбирает именно его, `--output` задаёт столбцы. `blkid` показывает UUID текущего раздела. `cd` выбирает каталог, в котором ведомость содержит относительные имена; `sha256sum -c` сверяет контрольную сумму; последний `cd` возвращает домой.

**Пример сокращённого результата:**

```text
OK: ...
OK: ...
SOURCE        TARGET               FSTYPE OPTIONS
/dev/loop10p1 /mnt/astra-xfs-1000   xfs    rw,nosuid,nodev,noexec,noatime,...
/dev/loop10p1: LABEL="X1000" UUID="aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee" TYPE="xfs" ...
journal.txt: OK
```

`findmnt` обычно показывает разрешённое имя устройства, а не текст `UUID=...`. Связку доказывают три наблюдения: строка модели с UUID, этот же UUID у раздела и фактическое монтирование с `noatime`. Один только `lsblk -f` не показывает все параметры монтирования.

### 11. Результаты проекта

#### 11.1. Таблица идентификации и подготовки устройства

Заполняйте результат фактическими значениями вашей практики, а не номерами loop из примеров.

| Параметр | Использованная команда | Что записать |
| --- | --- | --- |
| Файл, изображающий диск | `printf '%s\n' "$XFS_IMAGE"` | Ваш путь `.../disk.img` |
| Имя блочного устройства | `lsblk -o NAME,TYPE,SIZE,FSTYPE,MOUNTPOINT "$XFS_LOOP"` | Значение `$XFS_LOOP` |
| Раздел с XFS | `printf '%s\n' "$XFS_PART"` | Фактический `/dev/loopNp1` |
| Принадлежность образу | `sudo losetup --list --output NAME,BACK-FILE "$XFS_LOOP"` | Совпадение с вашим образом |
| UUID файловой системы | `sudo blkid -s UUID -o value "$XFS_PART"` | Ваш UUID |
| Созданная точка монтирования | `sudo mkdir -m 0755 -- "$XFS_BASE" "$XFS_MNT"` | Ваш `/mnt/astra-xfs-UID` |
| Действующие параметры | `findmnt --mountpoint "$XFS_MNT" --output OPTIONS` | Наличие `noatime` и выбранных ограничений |
| Каталог данных | `ls -ld "$XFS_MNT/records"` | Владелец, группа и `2770` |

Команды в таблице — запись уже выполненных шагов. Повторно создавать каталоги, разметку и файловую систему ради заполнения отчёта не нужно.

#### 11.2. Фактическая конфигурация подключения

```bash
cat "$XFS_FSTAB"
```

`cat` читает готовую модель таблицы; флагов нет.

**Пример результата:**

```text
UUID=aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee /mnt/astra-xfs-1000 xfs defaults,noatime,nosuid,nodev,noexec 0 0
```

Сохраните свою фактическую строку и путь к модели. В отчёте укажите, что реальный `/etc/fstab` не изменялся, а повторное применение таблицы проверено после переподключения образа. Последний столбец для XFS скорректирован с `2` на `0` по объяснению части 1.

#### 11.3. Подтверждение выполнения

Сохраните скриншот терминала, на котором видны:

1. Строка модели `fstab` с вашим UUID.
2. `blkid` для текущего loop-раздела с тем же UUID и типом `xfs`.
3. `findmnt` для точной точки с `noatime` в параметрах.
4. Успешная проверка `journal.txt: OK` после повторного подключения.

При желании дополнительно сохраните сравнение `atime` из раздела 8. Скриншоты делаются на вашем компьютере; устанавливать графическую среду на сервер не нужно. Пароли, ключи SSH и реальные данные в подтверждение не включаются.

#### 11.4. Как это переносится на настоящий новый диск

Для физического диска с уже существующей XFS шаги создания образа, разметки и `mkfs.xfs` пропускаются. Сначала по инвентаризации подтверждают конкретное устройство, его содержимое и UUID, затем готовят точку, права и параметры.

Перед изменением настоящего `/etc/fstab` сохраняют его резервную копию и согласуют запись. После изменения проверяют таблицу и подключают именно нужную точку, а не все диски сервера подряд. При systemd учитывают обновление конфигурации менеджера и зависимости приложения от монтирования. Проверка перед перезагрузкой уменьшает риск, но не заменяет реальную проверку следующей загрузки в согласованном порядке.

Для обязательного хранилища нельзя допустить, чтобы приложение при отсутствии диска продолжило писать в лежащий под точкой каталог системного раздела. Параметр `nofail` не решает эту задачу; нужны согласованные зависимости и проверка доступности хранилища. В учебной модели рабочие службы не перенастраиваются.

### 12. Восстановление после разрыва SSH

Не начинайте снова с форматирования. Повторите только блок переменных из раздела 2.1 части 2, затем посмотрите состояние:

```bash
sudo ls -lh "$XFS_IMAGE"
sudo losetup --associated "$XFS_IMAGE"
findmnt --mountpoint "$XFS_MNT" --output SOURCE,TARGET,FSTYPE,OPTIONS
```

`ls -lh` показывает наличие и размер образа. `losetup --associated` ищет связи только этого файла. `findmnt --mountpoint` проверяет точное монтирование; `--output` задаёт столбцы.

**Возможный пример результата:**

```text
-rw------- 1 root root 512M ... /var/tmp/astra-xfs-1000/disk.img
/dev/loop10: ... (/var/tmp/astra-xfs-1000/disk.img)
SOURCE        TARGET               FSTYPE OPTIONS
/dev/loop10p1 /mnt/astra-xfs-1000   xfs    rw,noatime,...
```

Если связи нет, `losetup` ничего не покажет. Если точного монтирования нет, `findmnt` завершится без строки результата и с ненулевым кодом. Это не означает, что данные в образе пропали.

#### 12.1. Восстановите имена существующего устройства

При одной найденной связи нашего образа:

```bash
XFS_LOOP="$(sudo losetup --list --noheadings --raw --output NAME --associated "$XFS_IMAGE")"
if [[ "$XFS_LOOP" =~ ^/dev/loop[0-9]+$ ]]; then
    XFS_PART="${XFS_LOOP}p1"
    XFS_UUID="$(sudo blkid -s UUID -o value "$XFS_PART")"
    printf '%s\n' "$XFS_LOOP" "$XFS_PART" "$XFS_UUID"
else
    printf '%s\n' 'STOP: expected one existing loop association.'
fi
```

`--list` выбирает таблицу, `--noheadings --raw` убирают заголовок и выравнивание, `--output NAME` оставляет только имя, `--associated` ограничивает образ. Регулярное выражение принимает ровно одно имя вида `/dev/loopN`; пустое значение и несколько строк не подходят.

`blkid -s UUID -o value` восстанавливает UUID существующей файловой системы. `printf` показывает значения.

**Пример результата:**

```text
/dev/loop10
/dev/loop10p1
aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee
```

Заново определите функции блоками из разделов 4.3 и 6.2 части 2. Если файловая система не смонтирована, вторая проверка ожидаемо не подтвердит монтирование. Для существующей и подтверждённой XFS используйте только команду монтирования из раздела 6.1 либо сохранённую модель таблицы, без повторных `sfdisk` и `mkfs.xfs`.

Если loop-связи нет, подключите существующий образ блоком из раздела 4.1, определите функцию проверки, прочитайте его UUID через `blkid` и проверьте совпадение с моделью. Затем монтируйте существующую XFS. Не перезаписывайте модель новым UUID, если он неожиданно отличается: сначала выясните причину.

### 13. Завершение и очистка

Сначала сохраните подтверждения результата. Можно оставить образ для следующего занятия, но завершить работу с ним нужно штатным размонтированием и отключением связи. Удаление образа удалит и находящиеся в нём учебные записи.

#### 13.1. Размонтируйте только свою XFS

```bash
cd "$HOME"
sync
xfs_check_mount && sudo umount "$XFS_MNT"
```

`cd` выводит текущую оболочку из хранилища, `sync` просит записать изменения. `xfs_check_mount` проверяет источник, после успеха `&&` допускает обычный `umount` без флагов.

**Пример результата:** две строки `OK`, успешное размонтирование само по себе обычно молчит. Если файловая система уже была размонтирована, проверка не пройдёт; создавать монтирование заново только ради этой команды не нужно. Подтвердите отсутствие точного монтирования при следующих проверках.

#### 13.2. При необходимости проверьте XFS без исправлений

```bash
if findmnt --noheadings --source "$XFS_PART"; then
    printf '%s\n' 'STOP: unmount the training XFS before checking.'
else
    xfs_check_device && sudo xfs_repair -n "$XFS_PART"
fi
```

`findmnt --source` с `--noheadings` ищет монтирования раздела. Если они есть, выполняется только сообщение об остановке. Иначе проверка принадлежности разрешает вызов `xfs_repair`.

Флаг `-n` означает режим без изменений: инструмент исследует структуры и сообщает о предполагаемых исправлениях, но не выполняет их. Даже такую проверку проводим на размонтированной XFS. В зависимости от версии инструмент может потребовать дополнительные ресурсы; для маленького учебного образа объём ограничен размером раздела.

**Пример сокращённого результата:**

```text
OK: /dev/loop10p1 belongs to /var/tmp/astra-xfs-1000/disk.img
Phase 1 - find and verify superblock...
Phase 2 - using internal log
...
No modify flag set, skipping filesystem flush and exiting.
```

**Что должно получиться.** Нет неожиданных повреждений. Если инструмент сообщает о непроигранном журнале или повреждениях, не добавляйте `-L`: этот параметр сбрасывает журнал и может привести к потере данных. Проверка журнала и восстановление — отдельная задача; переформатирование не является её заменой.

#### 13.3. Отключите loop и подтвердите отсутствие использования

```bash
if findmnt --noheadings --source "$XFS_PART"; then
    printf '%s\n' 'STOP: the training partition is still mounted.'
else
    xfs_check_device && sudo losetup --detach "$XFS_LOOP"
fi
sudo udevadm settle --timeout=10
sudo losetup --associated "$XFS_IMAGE"
if mountpoint -q "$XFS_MNT"; then
    printf '%s\n' 'STOP: training path is still mounted.'
else
    printf '%s\n' 'Training path is not mounted.'
fi
```

`findmnt` проверяет раздел, `losetup --detach` отключает одно проверенное устройство. `udevadm settle --timeout=10` ожидает события, `losetup --associated` показывает оставшиеся связи только образа. `mountpoint -q` отдельно проверяет точку без собственного текста, `if` выводит результат.

**Пример результата:**

```text
OK: /dev/loop10p1 belongs to /var/tmp/astra-xfs-1000/disk.img
Training path is not mounted.
```

Между этими строками список связей должен быть пуст. Если устройство уже было отключено, функция проверки не подтвердит его наличие; ориентируйтесь на подтверждённое отсутствие связи и монтирования. Никогда не заменяйте его другим номером loop ради получения `OK`.

#### 13.4. Удалите только созданные файлы, если они больше не нужны

```bash
printf '%s\n' "$XFS_IMAGE" "$XFS_FSTAB" "$XFS_MNT" "$XFS_BASE"
```

`printf '%s\n'` показывает по одному значению на строку. Флагов нет.

**Пример результата:**

```text
/var/tmp/astra-xfs-1000/disk.img
/var/tmp/astra-xfs-1000/model/etc/fstab
/mnt/astra-xfs-1000
/var/tmp/astra-xfs-1000
```

Продолжайте только при ожидаемых непустых путях. Следующий блок дополнительно проверяет их и отсутствие использования образа:

```bash
if [[ "$XFS_UID" = "$(id -u)" && "$XFS_BASE" = "/var/tmp/astra-xfs-$XFS_UID" && "$XFS_IMAGE" = "$XFS_BASE/disk.img" && "$XFS_MNT" = "/mnt/astra-xfs-$XFS_UID" && "$XFS_FSTAB" = "$XFS_BASE/model/etc/fstab" ]]; then
    if mountpoint -q "$XFS_MNT"; then
        printf '%s\n' 'STOP: unmount the training path first.'
    else
        XFS_ASSOC="$(sudo losetup --associated "$XFS_IMAGE")"
        if [[ $? -eq 0 && -z "$XFS_ASSOC" ]]; then
            sudo rm -i -- "$XFS_IMAGE" "$XFS_FSTAB"
            sudo rmdir -- "$XFS_BASE/model/etc" "$XFS_BASE/model" "$XFS_BASE" "$XFS_MNT"
        else
            printf '%s\n' 'STOP: association remains or its check failed.'
        fi
    fi
else
    printf '%s\n' 'STOP: paths do not match this practice.'
fi
```

| Элемент | Значение |
| --- | --- |
| `[[ ... ]]` | Условие Bash |
| `=` | Равенство строк |
| `&&` | Успех всех перечисленных проверок |
| `$(id -u)` | Повторное получение UID текущего пользователя |
| `mountpoint -q` | Тихая проверка монтирования |
| `XFS_ASSOC="$(...)"` | Сохранение списка связей образа |
| `$? -eq 0` | Предыдущая команда проверки завершилась с нулевым кодом |
| `-z` | Строка списка связей пуста |
| `rm -i` | Подтверждение перед удалением каждого конкретного файла |
| `--` | Завершение списка параметров |
| `rmdir` | Удаление только пустых каталогов, без рекурсивного стирания содержимого |

**Пример запросов:**

```text
rm: remove regular file '/var/tmp/astra-xfs-1000/disk.img'?
rm: remove regular file '/var/tmp/astra-xfs-1000/model/etc/fstab'?
```

Язык и ответ подтверждения зависят от настроек терминала. Если вы отказались, файл останется, а непустой каталог не удалится. При незавершённой практике отдельный файл может отсутствовать; это не повод расширять удаление на системные каталоги.

Настоящий `/etc/fstab`, другие loop-устройства и системные диски не удаляются. Установленные вспомогательные пакеты автоматически не удаляются, драйвер XFS принудительно не выгружается.

### 14. Частые ошибки и их смысл

| Сообщение или наблюдение | Что может означать | Что проверить |
| --- | --- | --- |
| `command not found` | Нет программы в пути поиска | Проверку через `sudo sh -c 'command -v ...'` и подготовку соответствующего пакета |
| `unknown filesystem type 'xfs'` | Ядро не предоставляет XFS | `/proc/filesystems`, штатный модуль и разрешения; не отключать защиту |
| `Operation not permitted` | Не хватает полномочий или среда запрещает mount/loop | Политику учебной ВМ; не подменять объект настоящим диском |
| `cannot find an unused loop device` | Недоступны loop-устройства или свободная связь | Возможность loop в этой среде; не отключать чужие устройства |
| Нет `/dev/loopNp1` | Не прочитана разметка или события устройств не завершены | `sfdisk --dump`, `--partscan`, результат `udevadm settle` |
| `contains a filesystem` у mkfs | Найдено существующее содержимое | Не добавлять `-f`; проверить, не повторяется ли шаг над уже созданной XFS |
| `Permission denied` при записи | Неверные права или дополнительные ограничения | Владельца и группу каталога `records`, точное монтирование, политику Astra Linux |
| `target is busy` | Есть используемый каталог, файл или вложенное монтирование | Выйти из своих каталогов и закрыть свои файлы, не убивать неизвестные процессы |
| UUID не найден | Образ не подключён, иной UUID или нет актуальных сведений об устройстве | `losetup`, `blkid`, udev и точность модели |
| `findmnt --target` показывает системный раздел | Путь существует, но точного монтирования может не быть | Использовать `findmnt --mountpoint` и `mountpoint` |
| В `lsblk -f` не видно noatime | Эта команда не предназначена для полного списка параметров | Вывод `findmnt ... --output OPTIONS` |
| `atime` изменилось | Нет нужного параметра или отметку явно меняет другой процесс | Фактическое монтирование и использование только своего файла |
| `journal.txt: FAILED` | Содержимое отличается от ведомости | Источник и файл; не пересоздавать сумму только ради `OK` |
| После reboot образ не подключился | Loop-связь не была настроена как постоянное устройство | Отличие образа от аппаратного диска; настоящая перезагрузка в практике не предусмотрена |
| XFS жалуется на журнал | Нужна отдельная диагностика состояния | Не использовать `xfs_repair -L` и новое форматирование как обход ошибки |

После завершения вы должны уметь объяснить: какое устройство выбрано, почему оно принадлежит вашему образу, где находится XFS, как UUID связан с её монтированием, что меняет `noatime`, какие права получили пользователи и почему модель `fstab` не равна изменению реальной загрузки.
