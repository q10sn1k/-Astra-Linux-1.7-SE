# Модуль 2. Иерархия файловой системы, монтирование и дисковые устройства

Эта практика выполняется на **одной удалённой Astra Linux Special Edition 1.7**. Вы уже подключились к ней по SSH. Все команды вводятся в Bash удалённой машины; на вашем компьютере ничего создавать и форматировать не требуется.

Сначала разберём каталоги Linux и научимся читать сведения о дисках. Затем создадим виртуальную флешку: обычный файл размером 128 MiB, таблицу разделов внутри него и файловую систему ext4. Подключим образ как loop-устройство, смонтируем его, запишем и прочитаем файлы, проверим режим только для чтения, отключим и подключим снова. Отдельно разберём формат `fstab` и монтирование по UUID.

Образ находится на диске удалённого сервера и использует его свободное место. Loop-устройство позволяет ядру обращаться к этому файлу как к блочному устройству. Это эмуляция накопителя, а не USB-контроллера: в системе появится `/dev/loopN`, а не новая физическая флешка `/dev/sdX`.

Изменения ограничены собственным образом, связанным с ним loop-устройством и новым каталогом в `/mnt`. Системный `/etc/fstab` мы только прочитаем; для тренировки создадим отдельный файл такого же формата. Перезагрузка, остановка SSH и изменение разметки реальных дисков не нужны.

Примеры вывода условные. На вашей машине могут отличаться язык сообщений, версии программ, имена дисков, UUID и номер loop-устройства. В примерах UID и GID равны `1000`, а loop-устройство называется `/dev/loop7`. **Не подставляйте `/dev/loop7` вручную:** нужный путь будет получен командой и сохранён в переменной.

## 1. Как выполнять команды в SSH-сеансе

Копируйте команды по порядку, по одному блоку. Текст из блоков с примерами вывода вводить не нужно. При ошибке остановитесь на текущем шаге и прочитайте пояснение; не продолжайте к форматированию с пустыми переменными или неизвестным устройством.

Многострочный блок с `<<EOF` или `<<'EOF'` вставляйте целиком, включая завершающее `EOF` на отдельной строке. Оно завершает ввод текста для команды. При незавершённом вводе Bash может показать приглашение `>`; Ctrl+C отменяет такой ввод, после чего блок можно вставить заново.

Значения переменных и определённые ниже функции сохраняются только в текущем сеансе Bash. Файлы, монтирование и loop-устройства не исчезают при разрыве SSH. Порядок восстановления после переподключения приведён в разделе 17.

### 1.1. Проверьте удалённую систему и оболочку

```bash
whoami
hostname
cat /etc/os-release
cat /etc/astra_version
printf '%s\n' "$BASH_VERSION"
```

**Что делает каждая команда.**

| Команда или запись | Объяснение |
| --- | --- |
| `whoami` | Показывает имя пользователя текущего сеанса |
| `hostname` | Показывает имя удалённой машины |
| `cat` | Читает указанный текстовый файл и выводит его содержимое |
| `/etc/os-release` | Файл с названием и общими сведениями об ОС |
| `/etc/astra_version` | Сведения о выпуске установленной Astra Linux |
| `printf` | Печатает значения в заданном формате |
| `%s` | Место для строкового значения |
| `\n` | Перевод строки |
| `"$BASH_VERSION"` | Версия текущей Bash; кавычки сохраняют значение одним аргументом |

У `whoami`, `hostname` и приведённых вызовов `cat` флагов нет.

**Пример сокращённого вывода:**

```text
student
astra-lab
PRETTY_NAME="Astra Linux"
NAME="Astra Linux"
...
1.7.x
5.0.3(1)-release
```

**Что должно получиться.** Вы подтвердили, что работаете на нужной Astra Linux и в Bash. Версии в примере не являются требованием к точному номеру вашего обновления. Если `$BASH_VERSION` пуст или выпуск ОС другой, сначала уточните окружение.

### 1.2. Проверьте права и программы

```bash
sudo -v
command -v lsblk findmnt mount umount mountpoint losetup sfdisk blkid mkfs.ext4 e2fsck udevadm truncate
```

`sudo` выполняет разрешённые действия с повышенными правами. Флаг `-v` проверяет возможность использовать `sudo` и обновляет срок действия подтверждения полномочий. При запросе введите пароль своей учётной записи: символы не отображаются.

`command` — встроенный инструмент Bash; его `-v` показывает, где найдена каждая программа. Это другой `-v`, не связанный с параметром `sudo`.

**Пример вывода после возможного запроса пароля:**

```text
/bin/lsblk
/bin/findmnt
/bin/mount
/bin/umount
/bin/mountpoint
/sbin/losetup
/sbin/sfdisk
/sbin/blkid
/sbin/mkfs.ext4
/sbin/e2fsck
/bin/udevadm
/usr/bin/truncate
```

Пути могут начинаться с `/usr/bin` или `/usr/sbin`: это нормально. Отсутствие строки для программы означает, что Bash не нашёл её в текущем пути поиска. Для утилит администратора проверьте также наличие файлов в `/sbin` и `/usr/sbin`, прежде чем считать пакет отсутствующим.

**Что должно получиться.** Все перечисленные команды доступны, а `sudo` разрешён. Проверка наличия программ ещё не гарантирует права на создание loop-устройств и монтирование. В контейнере или при ограничениях политики безопасности эти операции могут быть запрещены даже пользователю root. Для дальнейшей практики нужна учебная ВМ с разрешёнными операциями loop и mount; обходить ограничения не требуется.

### 1.3. Если не хватает инструментов

В Astra Linux пакет `util-linux` содержит многие средства просмотра и управления устройствами, пакет `mount` — средства монтирования и настройки loop, пакет `fdisk` — `sfdisk`, пакет `e2fsprogs` — `mkfs.ext4` и `e2fsck`. Состав установленной системы и разделение пакетов проверяйте по её собственным данным.

Не переустанавливайте всё подряд. Например, если отсутствует только `sfdisk`, сначала посмотрите план установки пакета `fdisk` из уже настроенного разрешённого репозитория вашей Astra Linux:

```bash
sudo apt-get --simulate --no-remove --no-upgrade --no-install-recommends install fdisk
```

| Элемент | Для чего нужен |
| --- | --- |
| `sudo` | Даёт права чтения настроек, соответствующие будущей установке |
| `apt-get` | Обращается к пакетной системе Astra Linux |
| `--simulate` | Показывает план, ничего не устанавливая |
| `--no-remove` | Прерывает операцию, если для неё требуется удаление пакетов |
| `--no-upgrade` | Не обновляет уже установленный пакет, явно названный в команде; не запрещает все возможные обновления зависимостей |
| `--no-install-recommends` | Исключает рекомендации, сохраняя обязательные зависимости |
| `install fdisk` | Выбирает установку пакета с инструментами разметки |

**Пример подходящего плана:**

```text
The following NEW packages will be installed:
  fdisk
0 upgraded, 1 newly installed, 0 to remove ...
```

Если вместо этого предлагается обновление системных библиотек или другие неожиданные изменения, не выполняйте установку ради практики. Если программа уже есть, этот подраздел пропустите.

При ожидаемом плане и разрешённой установке ПО:

```bash
sudo apt-get --no-remove --no-upgrade --no-install-recommends install fdisk
command -v sfdisk
```

Первая команда отличается от предыдущей отсутствием `--simulate`: установка теперь настоящая. Остальные параметры имеют тот же смысл; перед подтверждением снова прочитайте план. Вторая команда с `command -v` проверяет появление `sfdisk`.

**Пример результата:**

```text
Setting up fdisk (...) ...
/sbin/sfdisk
```

На полностью автономной машине недостающие инструменты должны быть подготовлены заранее из разрешённого источника с зависимостями. SSH-доступ сам по себе не даёт доступа к репозиторию. Не подключайте Debian или Ubuntu вместо источников Astra Linux и не устанавливайте сторонние средства разметки.

## 2. Как устроено дерево каталогов Linux

В Linux все пути начинаются от единого корня `/`. Диски не получают обязательные буквы вроде `C:` и `D:`. Файловая система другого раздела становится доступна в выбранном каталоге — точке монтирования.

Например, путь `/mnt/astra-usb-1000/training/report.txt` будет означать файл внутри виртуальной флешки, пока она смонтирована в `/mnt/astra-usb-1000`. После размонтирования этот же каталог снова покажет содержимое исходной файловой системы сервера.

| Каталог | Что в нём находится | Для чего это знать |
| --- | --- | --- |
| `/` | Корень единого дерева путей | Это не домашний каталог root и не обязательно весь физический диск |
| `/boot` | Файлы загрузки, ядра, начальные образы | Здесь ничего не изменяем в упражнении по SSH |
| `/etc` | Системные конфигурационные файлы | Здесь находится настоящий `/etc/fstab` |
| `/home` | Домашние каталоги обычных пользователей | Здесь обычно располагается домашний каталог вашей учётной записи |
| `/root` | Домашний каталог пользователя root | Отличается от корня `/` |
| `/usr` | Большая часть программ, библиотек и общих данных | Это не каталог личных документов пользователя |
| `/usr/local` | Локально установленное администратором ПО | Отделяет локальные установки от обычного пакетного набора |
| `/var` | Изменяемые системные данные, журналы, базы | Заполнение этого раздела может мешать службам |
| `/tmp` | Временные файлы | Очистка зависит от правил системы |
| `/var/tmp` | Временные файлы, обычно сохраняемые дольше, чем в `/tmp` | Здесь создадим собственный образ; политика очистки всё равно возможна |
| `/run` | Данные текущего запуска системы | Содержимое обычно не переживает перезагрузку |
| `/dev` | Файлы устройств | Здесь появятся loop-устройство и его раздел |
| `/proc` | Представление сведений о процессах и ядре | Обычно это виртуальная файловая система, а не обычные файлы на диске |
| `/sys` | Представление устройств и других объектов ядра | Запись в отдельные файлы может менять поведение системы |
| `/mnt` | Каталоги для ручного монтирования | Здесь создадим собственную точку монтирования |
| `/media` | Каталоги съёмных носителей, часто используемые автомонтированием | В SSH-сеансе автоматическое монтирование не гарантировано |
| `/opt` | Дополнительные приложения | Не обязательно находится на отдельном разделе |

Одинаковое дерево каталогов может быть распределено между несколькими разделами. И наоборот: `/`, `/home` и `/var` могут находиться на одной файловой системе. Название каталога само по себе не доказывает наличие отдельного диска.

### 2.1. Посмотрите каталоги и символические ссылки

```bash
pwd
ls -ld / /boot /etc /home /root /usr /var /tmp /var/tmp /run /dev /proc /sys /mnt /media /opt
ls -ld /bin /sbin /lib
```

`pwd` выводит текущий каталог. `ls` показывает сведения об указанных путях; `-l` включает подробный формат, `-d` показывает сам каталог, а не перечисляет всё его содержимое. Сочетание `-ld` равнозначно двум флагам `-l -d`.

**Пример сокращённого вывода:**

```text
/home/student
drwxr-xr-x ... root root ... /
drwxr-xr-x ... root root ... /etc
drwxrwxrwt ... root root ... /tmp
drwxr-xr-x ... root root ... /mnt
...
```

Для `/bin`, `/sbin` и `/lib` на части систем могут отображаться символические ссылки с `->`. Это зависит от устройства конкретной установки. Не превращайте их в обычные каталоги и не переносите содержимое вручную.

**Что должно получиться.** Вы увидели реальные пути и их владельцев. Буква `d` в начале строки означает каталог, `l` — символическую ссылку. Остальные символы описывают права. Для текущего просмотра права менять не требуется.

## 3. Устройство, раздел, файловая система и монтирование

| Понятие | Простое объяснение | Пример |
| --- | --- | --- |
| Блочное устройство | Объект, который позволяет читать и записывать данные блоками | Виртуальный диск сервера или `/dev/loopN` |
| Таблица разделов | Описание областей внутри устройства | MBR/DOS или GPT |
| Раздел | Область с заданным началом и размером | Первый раздел loop-устройства: `/dev/loopNp1` |
| Файловая система | Структуры, с помощью которых хранятся файлы, имена и права | ext4 внутри раздела |
| Монтирование | Подключение файловой системы к дереву путей | Подключение раздела к `/mnt/astra-usb-1000` |
| Точка монтирования | Каталог, в котором видно содержимое подключённой файловой системы | `/mnt/astra-usb-1000` |
| Метка, LABEL | Короткое удобное имя файловой системы | `USB1000` |
| UUID | Идентификатор файловой системы | Строка, которую получит `blkid` |

Создание раздела не создаёт файловую систему. Создание файловой системы не монтирует её. Монтирование не форматирует устройство. Эти операции выполняют разные задачи.

Настоящие диски могут называться `/dev/sda`, `/dev/vda`, `/dev/nvme0n1`, а разделы — `/dev/sda1`, `/dev/vda1`, `/dev/nvme0n1p1`. В этой практике над ними выполняется только просмотр. В команды разметки и форматирования реальные пути дисков не подставляются.

## 4. Исследование дисков без изменения данных

### 4.1. Прочитайте список блочных устройств

```bash
lsblk -o NAME,TYPE,SIZE,FSTYPE,LABEL,UUID,MOUNTPOINT
```

`lsblk` перечисляет блочные устройства. Флаг `-o` задаёт нужные столбцы; список после него передаётся одним аргументом, без пробелов между именами.

| Столбец | Что показывает |
| --- | --- |
| `NAME` | Имя устройства или раздела |
| `TYPE` | Тип: например, `disk`, `part`, `loop`, `lvm` |
| `SIZE` | Размер устройства |
| `FSTYPE` | Обнаруженный тип файловой системы |
| `LABEL` | Метку файловой системы, если она есть |
| `UUID` | Идентификатор файловой системы, если он обнаружен |
| `MOUNTPOINT` | Отображаемую точку монтирования; один столбец не описывает все возможные повторные монтирования |

**Пример сокращённого вывода:**

```text
NAME   TYPE SIZE FSTYPE LABEL UUID                                 MOUNTPOINT
vda    disk  30G
vda1   part  29G ext4         ...                                  /
vda2   part   1G swap         ...                                  [SWAP]
```

Вывод вашей машины может включать LVM, шифрование и другие устройства. Пустой `MOUNTPOINT` не означает, что устройство можно форматировать: оно может использоваться как swap, часть LVM или другим способом. Даже пустой `FSTYPE` не доказывает отсутствие ценных данных.

**Что должно получиться.** Вы различаете диск целиком и его разделы, но ничего на них не меняете.

### 4.2. Узнайте, где находится корневая файловая система

```bash
findmnt --target / --output SOURCE,TARGET,FSTYPE,OPTIONS
```

`findmnt` читает сведения о монтировании. `--target /` ищет файловую систему, содержащую путь `/`. `--output` выбирает столбцы: источник, точку монтирования, тип и параметры.

**Пример сокращённого вывода:**

```text
SOURCE    TARGET FSTYPE OPTIONS
/dev/vda1 /      ext4   rw,relatime,...
```

`rw` означает возможность записи. Источник может оказаться логическим томом, а не простым разделом. Корневое устройство из этого вывода не используется в последующих изменяющих командах.

### 4.3. Сравните размер файловой системы и свободное место

```bash
df -hT / /var /home /var/tmp
df -i /
```

`df` показывает заполнение файловых систем. Флаг `-h` выводит размеры в удобных единицах, `-T` добавляет тип файловой системы. Путь выбирает файловую систему, на которой находится указанный каталог.

Во второй команде `-i` показывает использование inode — записей, в которых файловая система хранит сведения об объектах. Место для данных и свободные inode — разные ресурсы.

**Пример сокращённого вывода:**

```text
Filesystem     Type Size Used Avail Use% Mounted on
/dev/vda1      ext4  29G  12G   16G  43% /
/dev/vda1      ext4  29G  12G   16G  43% /
...
Filesystem     Inodes IUsed IFree IUse% Mounted on
/dev/vda1         ...   ...   ...    8% /
```

Повторяющиеся строки допустимы: несколько каталогов могут относиться к одному разделу. Для образа оставьте свободного места заметно больше 128 MiB; на почти заполненном сервере практику не начинайте. Установку дополнительных инструментов также нужно учитывать отдельно.

### 4.4. Посмотрите реальные настройки fstab

```bash
cat /etc/fstab
```

`cat` выводит содержимое файла; флагов нет. `/etc/fstab` содержит постоянные описания файловых систем, которые могут использоваться при загрузке и ручном монтировании.

**Пример структуры вывода:**

```text
# ...
UUID=... / ext4 defaults 0 1
...
```

**Что должно получиться.** Вы увидели формат существующих записей. Ничего из примера в настоящий файл не переносите. Ошибка в загрузочных записях может затруднить следующий запуск машины; далее тренируемся с отдельным файлом.

## 5. Подготовка собственных объектов

### 5.1. Сохраните имена и пути в переменные

```bash
LAB_UID="$(id -u)"
LAB_GID="$(id -g)"
LAB_BASE="/var/tmp/astra-storage-$LAB_UID"
LAB_IMAGE="$LAB_BASE/usb.img"
LAB_MNT="/mnt/astra-usb-$LAB_UID"
LAB_LABEL="USB$LAB_UID"
LAB_FSTAB="$LAB_BASE/fstab.example"
printf '%s\n' "$LAB_BASE" "$LAB_IMAGE" "$LAB_MNT" "$LAB_LABEL" "$LAB_FSTAB"
```

`id -u` выводит UID пользователя, `id -g` — его основную GID. Конструкция `$(...)` подставляет результат команды. Присваивание `ИМЯ="значение"` сохраняет значение для следующих шагов; пробелов вокруг `=` нет.

| Переменная | Смысл |
| --- | --- |
| `LAB_UID` | Числовой идентификатор вашей учётной записи |
| `LAB_GID` | Числовой идентификатор вашей основной группы |
| `LAB_BASE` | Только наш новый каталог для образа и примера конфигурации |
| `LAB_IMAGE` | Файл, который изображает весь накопитель |
| `LAB_MNT` | Новая точка монтирования |
| `LAB_LABEL` | Короткая метка будущей ext4 |
| `LAB_FSTAB` | Отдельный учебный файл формата fstab |

`printf '%s\n'` печатает по одному значению на строку. Двойные кавычки сохраняют подставленный путь одним аргументом. Знак `$` в дальнейших командах означает использование переменной: вручную заменять его на значения из примера не нужно.

**Пример вывода:**

```text
/var/tmp/astra-storage-1000
/var/tmp/astra-storage-1000/usb.img
/mnt/astra-usb-1000
USB1000
/var/tmp/astra-storage-1000/fstab.example
```

### 5.2. Убедитесь, что эти пути ещё не заняты

```bash
ls -ld "$LAB_BASE" "$LAB_MNT"
```

`ls -l` показывает подробности, `-d` — сами каталоги. Здесь намеренно проверяются ещё не созданные пути.

**Ожидаемый пример вывода при первом запуске:**

```text
ls: cannot access '/var/tmp/astra-storage-1000': No such file or directory
ls: cannot access '/mnt/astra-usb-1000': No such file or directory
```

Это ожидаемые сообщения об отсутствии наших объектов. Если каталог уже есть, не перезаписывайте его: сначала разберитесь с предыдущим запуском по разделам 17 и 18. Отсутствие прав доступа — другая ситуация, её не следует принимать за отсутствие файла.

### 5.3. Создайте каталоги

```bash
sudo mkdir -m 0755 -- "$LAB_BASE" "$LAB_MNT"
ls -ld "$LAB_BASE" "$LAB_MNT"
```

`mkdir` создаёт два каталога. `sudo` делает владельцем root. `-m 0755` задаёт права: владельцу чтение, запись и проход, остальным — чтение и проход. `--` завершает список флагов, после него идут пути. Флага `-p` нет: занятый путь вызовет ошибку, а не будет молча использован повторно.

В правах `7` означает чтение `4` + запись `2` + выполнение `1`; `5` — чтение и выполнение. Для каталога выполнение означает возможность проходить по пути. Обычный пользователь сможет читать каталог образа, но не заменять лежащие в нём файлы.

**Пример вывода команды проверки:**

```text
drwxr-xr-x 2 root root ... /mnt/astra-usb-1000
drwxr-xr-x 2 root root ... /var/tmp/astra-storage-1000
```

Сама `mkdir` при успехе ничего не печатает. При любой ошибке создания не переходите к следующему шагу.

## 6. Создание образа накопителя

### 6.1. Создайте файл размером 128 MiB

```bash
sudo test ! -e "$LAB_IMAGE" && sudo truncate -s 128M "$LAB_IMAGE"
sudo chmod 0600 "$LAB_IMAGE"
sudo ls -lh "$LAB_IMAGE"
sudo du -h "$LAB_IMAGE"
```

| Элемент | Что делает |
| --- | --- |
| `test ! -e путь` | Проверяет, что путь не существует: `-e` — существование, `!` — отрицание |
| `&&` | Выполняет следующую команду только при успехе предыдущей |
| `truncate` | Задаёт длину обычного файла |
| `-s 128M` | Устанавливает размер 128 × 1024 × 1024 байт |
| `chmod 0600` | Оставляет чтение и запись только владельцу root |
| `ls -l` | Показывает подробности файла |
| `ls -h` | Делает размер удобным для чтения |
| `du -h` | Показывает фактически занятое дисковое место в удобных единицах |

**Пример результата:**

```text
-rw------- 1 root root 128M ... /var/tmp/astra-storage-1000/usb.img
0       /var/tmp/astra-storage-1000/usb.img
```

`truncate` может создать разреженный файл: логическая длина уже 128 MiB, а незаписанные области ещё не занимают соответствующее место на диске. Поэтому `ls` и `du` показывают разное. По мере разметки, форматирования и записи данных занятое место увеличится.

**Что должно получиться.** Появился обычный файл-образ. Это ещё не раздел и не файловая система. Не выполняйте `truncate` повторно над образом, с которым уже работаете.

### 6.2. Запишите таблицу разделов внутрь образа

```bash
sudo sfdisk "$LAB_IMAGE" <<'EOF'
label: dos
unit: sectors

start=2048, size=245760, type=83
EOF
```

`sfdisk` создаёт таблицу разделов по текстовому описанию. Единственный аргумент — **наш файл `$LAB_IMAGE`**. Флагов в этом вызове нет. Ввод после `<<'EOF'` передаётся программе до завершающего маркера; одинарные кавычки запрещают подстановку переменных в описании.

| Строка или поле | Что означает |
| --- | --- |
| `label: dos` | Таблица разделов MBR, также называемая DOS; это не файловая система Windows |
| `unit: sectors` | Размеры и смещения указаны в секторах |
| `start=2048` | Первый раздел начинается с сектора 2048 |
| `size=245760` | Раздел содержит 245760 секторов |
| `type=83` | В MBR это идентификатор Linux-раздела; ext4 пока не создана |

Для создаваемого образа сектор равен 512 байтам. Начало раздела находится на отметке 1 MiB, размер раздела равен 120 MiB. Часть образа остаётся вне раздела; это допустимо. GPT тоже используется в Linux, но для маленького учебного накопителя MBR достаточно.

**Пример сокращённого вывода:**

```text
Disk /var/tmp/astra-storage-1000/usb.img: 128 MiB, 134217728 bytes, 262144 sectors
Created a new DOS disklabel ...
...usb.img1: Created a new partition 1 of type 'Linux' and of size 120 MiB.
The partition table has been altered.
```

**Что должно получиться.** Таблица разделов записана только в образ. Если вместо пути `.../usb.img` в сообщениях оказался реальный диск сервера, не продолжайте: команды этой практики не предполагают такую подмену. Повторный запуск разметки после форматирования и записи файлов не нужен.

### 6.3. Проверьте разметку

```bash
sudo sfdisk --dump "$LAB_IMAGE"
```

`--dump` выводит описание уже существующей таблицы в текстовом виде. Это чтение, а не новая разметка. `sudo` нужен, потому что доступ к образу оставлен только root.

**Пример сокращённого вывода:**

```text
label: dos
label-id: ...
device: /var/tmp/astra-storage-1000/usb.img
unit: sectors

...usb.img1 : start=2048, size=245760, type=83
```

**Что должно получиться.** Вы видите ровно один раздел с ожидаемыми началом и размером. Имя `usb.img1` в этом выводе описывает раздел внутри образа; это не отдельный обычный файл, который нужно создавать вручную.

## 7. Эмуляция подключения флешки

### 7.1. Свяжите образ со свободным loop-устройством

```bash
LAB_LOOP="$(sudo losetup --find --show --partscan --nooverlap "$LAB_IMAGE")"
LAB_PART="${LAB_LOOP}p1"
sudo udevadm settle --timeout=10
printf '%s\n' "$LAB_LOOP" "$LAB_PART"
```

`losetup` связывает обычный файл с loop-устройством. `$(...)` сохраняет напечатанный путь в `LAB_LOOP`. Команда требует прав администратора.

| Параметр | Для чего нужен |
| --- | --- |
| `--find` | Выбирает свободное loop-устройство |
| `--show` | Печатает имя выбранного устройства |
| `--partscan` | Просит ядро прочитать таблицу разделов при подключении |
| `--nooverlap` | Проверяет использование того же образа; при уже существующей связи использует её вместо создания второй независимой связи |
| `"$LAB_IMAGE"` | Указывает файл-основу именно нашего накопителя |

`LAB_PART="${LAB_LOOP}p1"` формирует путь первого раздела. Фигурные скобки отделяют имя переменной от добавляемого текста `p1`. Например, из `/dev/loop7` получается `/dev/loop7p1`.

`udevadm settle` ожидает обработки очереди событий устройств; `--timeout=10` ограничивает ожидание десятью секундами. Это не перезапуск udev и не сканирование реальных дисков на изменение разметки.

**Пример вывода:**

```text
/dev/loop7
/dev/loop7p1
```

**Что должно получиться.** `LAB_LOOP` содержит один непустой путь `/dev/loopN`, а раздел доступен как `/dev/loopNp1`. При ошибках `losetup` или ожидания остановитесь. Нельзя заменить недоступный loop случайным `/dev/sdX`.

### 7.2. Проверьте, какой файл стоит за устройством

```bash
sudo losetup --list --output NAME,BACK-FILE "$LAB_LOOP"
lsblk -o NAME,TYPE,SIZE,FSTYPE,MOUNTPOINT "$LAB_LOOP"
```

У `losetup` флаг `--list` включает табличный вывод, `--output NAME,BACK-FILE` выбирает имя и файл-основу. Аргумент `$LAB_LOOP` ограничивает просмотр нашим устройством.

`lsblk -o` выбирает столбцы; указание `$LAB_LOOP` показывает только его ветку устройств. `FSTYPE` пока должен быть пуст: раздел уже есть, но файловая система ещё не создана.

**Пример вывода:**

```text
NAME       BACK-FILE
/dev/loop7 /var/tmp/astra-storage-1000/usb.img
NAME      TYPE  SIZE FSTYPE MOUNTPOINT
loop7     loop  128M
loop7p1   part  120M
```

Продолжайте только при совпадении `BACK-FILE` с вашим `$LAB_IMAGE` и наличии одного ожидаемого раздела.

### 7.3. Определите проверку устройства перед изменениями

```bash
lab_check_device() {
    local backing
    if [[ ! "$LAB_LOOP" =~ ^/dev/loop[0-9]+$ ]] || [[ "$LAB_PART" != "${LAB_LOOP}p1" ]] || [[ ! -b "$LAB_PART" ]]; then
        printf '%s\n' 'STOP: expected loop partition was not found.' >&2
        return 1
    fi
    backing="$(sudo losetup --list --noheadings --raw --output BACK-FILE "$LAB_LOOP")" || return 1
    if [[ "$backing" != "$LAB_IMAGE" ]]; then
        printf '%s\n' 'STOP: loop device belongs to another image.' >&2
        return 1
    fi
    printf '%s\n' "OK: $LAB_PART belongs to $LAB_IMAGE"
}
lab_check_device
```

Это функция Bash — именованная последовательность проверок. Её определение не форматирует устройство. Вызов последней строкой проверяет текущие значения.

| Запись | Объяснение |
| --- | --- |
| `lab_check_device() { ...; }` | Определение функции; в блоке команды расположены по строкам |
| `local backing` | Временная переменная, существующая только внутри вызова функции |
| `[[ ... ]]` | Проверка условия средствами Bash |
| `=~ ^/dev/loop[0-9]+$` | Соответствие имени: начало строки, `/dev/loop`, одна или больше цифр, конец строки |
| `!` | Отрицание условия |
| `!=` | Строки не равны |
| `-b` | Путь существует как блочное устройство |
| `||` | Выполнение следующей части, если предыдущая неуспешна; в условии объединяет варианты ошибки |
| `--noheadings` | Вывод без заголовка таблицы |
| `--raw` | Формат без выравнивающих отступов таблицы |
| `--output BACK-FILE` | Только имя файла-основы loop-устройства |
| `>&2` | Вывод диагностического сообщения в поток ошибок |
| `return 1` | Выход из функции с признаком ошибки |

`--list` по-прежнему выбирает табличный режим `losetup`, а `printf '%s\n'` выводит строку. При успехе функция сравнивает файл-основу с нашим образом и печатает `OK`.

**Пример результата:**

```text
OK: /dev/loop7p1 belongs to /var/tmp/astra-storage-1000/usb.img
```

**Что должно получиться.** Перед форматированием можно повторно подтвердить принадлежность раздела нашему образу. Проверка не заменяет последовательное выполнение шагов: не переподключайте устройства между проверкой и следующей командой.

## 8. Создание файловой системы ext4

### 8.1. Отформатируйте только проверенный раздел образа

```bash
lab_check_device && sudo mkfs.ext4 -L "$LAB_LABEL" "$LAB_PART"
```

`lab_check_device` выполняет разобранные проверки. `&&` разрешает форматирование только после их успеха. `sudo` предоставляет права записи в блочное устройство. `mkfs.ext4` создаёт файловую систему ext4; `-L` задаёт метку из `$LAB_LABEL`; последний аргумент — **раздел**, а не весь образ и не реальный диск сервера.

Здесь нет флага принудительного форматирования. Если программа сообщает о неожиданной существующей файловой системе, устройстве в использовании или требует подтверждения перезаписи, остановитесь и проверьте предыдущие действия. Этот шаг выполняется один раз, до создания пользовательских файлов.

**Пример сокращённого вывода:**

```text
OK: /dev/loop7p1 belongs to /var/tmp/astra-storage-1000/usb.img
mke2fs ...
Creating filesystem with ... blocks and ... inodes
Filesystem UUID: ...
Allocating group tables: done
Writing inode tables: done
Creating journal ... done
Writing superblocks and filesystem accounting information: done
```

`mkfs.ext4` использует средства `mke2fs`, поэтому это имя встречается в выводе. Суперблок содержит основные параметры файловой системы, inode описывают объекты, журнал помогает согласованности метаданных после прерываний. Журнал не заменяет резервную копию.

**Что должно получиться.** Внутри раздела создана ext4 с меткой `USBваш_UID`. Монтирования пока нет.

### 8.2. Прочитайте тип, метку и UUID

```bash
sudo blkid "$LAB_PART"
LAB_UUID="$(sudo blkid -s UUID -o value "$LAB_PART")"
printf '%s\n' "$LAB_UUID"
lsblk -o NAME,TYPE,SIZE,FSTYPE,LABEL,UUID,MOUNTPOINT "$LAB_LOOP"
```

`blkid` определяет сигнатуры и свойства файловой системы. В первом вызове флагов нет. Во втором `-s UUID` выбирает только поле UUID, `-o value` печатает только его значение, без имени поля и кавычек. Подстановка сохраняет его в `LAB_UUID`.

`printf` показывает сохранённое значение. `lsblk -o` выводит выбранные столбцы нашего loop-устройства и раздела.

**Пример сокращённого вывода:**

```text
/dev/loop7p1: LABEL="USB1000" UUID="11111111-2222-3333-4444-555555555555" TYPE="ext4" ...
11111111-2222-3333-4444-555555555555
NAME     TYPE  SIZE FSTYPE LABEL   UUID                                 MOUNTPOINT
loop7    loop  128M
loop7p1  part  120M ext4   USB1000 11111111-2222-3333-4444-555555555555
```

**Что должно получиться.** Тип — ext4, метка ваша, UUID непустой. Сохранённый UUID не нужно заменять числом из примера. UUID файловой системы отличается от идентификатора таблицы разделов и `PARTUUID` раздела.

## 9. Монтирование виртуальной флешки

### 9.1. Подготовьте наглядный пример с каталогом

```bash
printf '%s\n' 'This file belongs to the server directory before mounting.' | sudo tee "$LAB_MNT/before-mount.txt"
ls -l "$LAB_MNT"
```

`printf '%s\n'` создаёт строку. Символ `|` передаёт её следующей программе. `sudo tee` записывает поток в указанный файл с правами root и одновременно показывает его в терминале. Флагов у `tee` здесь нет, файл создаётся в нашей новой точке монтирования. `ls -l` проверяет содержимое.

**Пример вывода:**

```text
This file belongs to the server directory before mounting.
total ...
-rw-r--r-- 1 root root ... before-mount.txt
```

Этот файл пока лежит на файловой системе сервера, а не в образе. После монтирования он станет временно невидим через этот путь; после размонтирования появится снова. Монтирование не удаляет его.

### 9.2. Смонтируйте раздел

```bash
lab_check_device && sudo mount -t ext4 -o rw,nosuid,nodev,noexec "$LAB_PART" "$LAB_MNT"
findmnt --mountpoint "$LAB_MNT" --output SOURCE,TARGET,FSTYPE,OPTIONS
ls -la "$LAB_MNT"
```

`lab_check_device` проверяет принадлежность раздела образу. `&&` допускает вызов `mount` только после успеха. `mount` подключает файловую систему; `-t ext4` явно задаёт тип, `-o` передаёт список параметров через запятую. Два последних аргумента — источник и точка монтирования.

| Параметр монтирования | Что даёт |
| --- | --- |
| `rw` | Чтение и запись |
| `nosuid` | Не использовать биты set-user-ID/set-group-ID и соответствующие привилегии файлов на этом монтировании |
| `nodev` | Не интерпретировать специальные файлы устройств на этой файловой системе как устройства |
| `noexec` | Запретить непосредственный запуск исполняемых файлов с этого монтирования |

Эти параметры ограничивают некоторые способы использования носителя, но не превращают его в изолированную среду. Например, `noexec` не запрещает программе читать текст сценария как данные.

`findmnt --mountpoint` ищет **точное монтирование** в указанном каталоге. Это отличается от `--target`, который может показать содержащую путь файловую систему. `--output` выбирает столбцы. `ls -l` показывает подробности, `-a` включает скрытые имена `.` и `..`.

**Пример сокращённого вывода:**

```text
SOURCE       TARGET               FSTYPE OPTIONS
/dev/loop7p1 /mnt/astra-usb-1000   ext4   rw,nosuid,nodev,noexec,relatime,...
total ...
drwxr-xr-x ... root root ... .
drwxr-xr-x ... root root ... ..
drwx------ ... root root ... lost+found
```

Сам `mount` при успехе обычно ничего не печатает. `before-mount.txt` исчез из списка, потому что теперь здесь виден корень ext4 внутри образа. `lost+found` создаётся при формировании ext4 для возможного восстановления объектов.

### 9.3. Определите проверку точки монтирования

```bash
lab_check_mount() {
    local source
    lab_check_device || return 1
    source="$(findmnt --noheadings --raw --mountpoint "$LAB_MNT" --output SOURCE)" || return 1
    if [[ "$source" != "$LAB_PART" ]]; then
        printf '%s\n' 'STOP: another filesystem is mounted at the training path.' >&2
        return 1
    fi
    printf '%s\n' "OK: $LAB_MNT is mounted from $LAB_PART"
}
lab_check_mount
```

Первая функция проверяет устройство; эта дополнительно проверяет, что в нашем каталоге смонтирован именно наш раздел. `local source` создаёт временную переменную. `|| return 1` останавливает функцию при ошибке. `findmnt --noheadings --raw` печатает данные без заголовка и табличного выравнивания; `--mountpoint` выбирает точное монтирование, `--output SOURCE` — только источник. `!=` сравнивает строки на неравенство, `>&2` направляет сообщение в поток ошибок.

**Пример результата:**

```text
OK: /dev/loop7p1 belongs to /var/tmp/astra-storage-1000/usb.img
OK: /mnt/astra-usb-1000 is mounted from /dev/loop7p1
```

**Что должно получиться.** Перед записью можно отличить содержимое виртуальной флешки от лежащего под ней каталога сервера.

## 10. Запись файлов и проверка прав

### 10.1. Создайте на флешке каталог для своей учётной записи

```bash
lab_check_mount && sudo install -d -o "$LAB_UID" -g "$LAB_GID" -m 0700 "$LAB_MNT/training"
ls -ld "$LAB_MNT/training"
```

`install` в этом режиме создаёт каталог: `-d` выбирает именно создание каталогов, `-o` назначает владельца по UID, `-g` — группу по GID, `-m 0700` — права. Владельцу разрешены чтение, запись и проход, группе и остальным — ничего. `sudo` нужен, потому что корень новой ext4 первоначально принадлежит root. Проверка перед `&&` подтверждает правильное монтирование.

**Пример результата:**

```text
OK: ...
OK: ...
drwx------ 2 student student ... /mnt/astra-usb-1000/training
```

**Что должно получиться.** Весь носитель не открыт на запись всем пользователям: вам принадлежит только учебный подкаталог. Для ext4 права и владельцы записаны в самой файловой системе. Параметры `uid=` и `gid=`, используемые с некоторыми другими файловыми системами, здесь не заменяют обычные права ext4.

### 10.2. Запишите и прочитайте файл

```bash
lab_check_mount && printf '%s\n' 'Astra Linux storage practice' 'The file is stored inside the USB image.' > "$LAB_MNT/training/report.txt"
cat "$LAB_MNT/training/report.txt"
ls -l "$LAB_MNT/training/report.txt"
```

`printf` печатает два строковых аргумента по формату `%s\n`; формат применяется к каждому аргументу. `>` перенаправляет вывод в файл, создавая его или заменяя содержимое. Вся запись расположена после `&&`, поэтому не начинается при неуспешной проверке. Здесь `sudo` уже не нужен: каталог принадлежит вам.

`cat` читает файл, флагов нет. `ls -l` показывает его права, владельца и размер.

**Пример результата:**

```text
OK: ...
OK: ...
Astra Linux storage practice
The file is stored inside the USB image.
-rw-r--r-- 1 student student ... /mnt/astra-usb-1000/training/report.txt
```

Права нового файла зависят также от маски создания файлов вашей оболочки; например, могут быть `-rw-------`. Главное — вы можете прочитать созданный файл. Команда заменила только наш `report.txt`.

### 10.3. Сохраните контрольную сумму и проверьте её

```bash
cd "$LAB_MNT/training"
sha256sum report.txt > SHA256SUMS
cat SHA256SUMS
sha256sum -c SHA256SUMS
```

`cd` меняет текущий каталог; флагов нет. `sha256sum` вычисляет SHA-256 файла. `>` сохраняет сумму вместе с относительным именем в ведомость `SHA256SUMS`; `cat` показывает её. Флаг `-c` включает проверку файлов по ведомости.

**Пример вывода:**

```text
<64 шестнадцатеричных символа>  report.txt
report.txt: OK
```

В реальном выводе вместо описания будут 64 символа суммы. Относительное имя позволит проверить файл после повторного подключения к той же точке. Контрольная сумма помогает заметить изменение данных, но сама по себе не подтверждает автора файла.

### 10.4. Сравните размеры и использование пространства

```bash
df -hT "$LAB_MNT"
df -i "$LAB_MNT"
du -sh "$LAB_MNT/training"
sudo ls -lh "$LAB_IMAGE"
sudo du -h "$LAB_IMAGE"
```

`df -hT` показывает заполнение и тип смонтированной файловой системы; `-i` — использование inode. У `du` флаг `-s` выводит итог по каталогу, `-h` — удобные единицы. `ls -lh` показывает логическую длину образа, `du -h` — выделенное ему место. `sudo` позволяет читать образ с правами `0600`.

**Пример структуры вывода:**

```text
Filesystem     Type Size Used Avail Use% Mounted on
/dev/loop7p1    ext4  ...  ...   ...   ... /mnt/astra-usb-1000
Filesystem     Inodes IUsed IFree IUse% Mounted on
/dev/loop7p1       ...   ...   ...   ... /mnt/astra-usb-1000
... /mnt/astra-usb-1000/training
-rw------- 1 root root 128M ... /var/tmp/astra-storage-1000/usb.img
... /var/tmp/astra-storage-1000/usb.img
```

**Что должно получиться.** Файл образа остаётся 128 MiB, раздел внутри него — 120 MiB, а доступное для пользовательских данных пространство ext4 ещё меньше из-за служебных структур, журнала и резервирования. Это разные величины, а не потерянные файлы.

## 11. Режим только для чтения

### 11.1. Выйдите из каталога флешки и переключите режим

```bash
cd "$HOME"
sync
lab_check_mount && sudo mount -o remount,ro,nosuid,nodev,noexec "$LAB_MNT"
findmnt --mountpoint "$LAB_MNT" --output SOURCE,TARGET,OPTIONS
```

`cd "$HOME"` возвращает в домашний каталог на сервере. `sync` просит записать накопленные изменения на устройства хранения; флагов нет, это не размонтирование.

`mount -o` передаёт параметры. `remount` меняет режим уже существующего монтирования, `ro` означает только чтение, `nosuid,nodev,noexec` повторно сохраняют выбранные ограничения. Указана только наша точка монтирования; проверка перед `&&` подтверждает её источник.

`findmnt --mountpoint` выбирает точную точку; `--output` задаёт столбцы.

**Пример результата:**

```text
OK: ...
OK: ...
SOURCE       TARGET               OPTIONS
/dev/loop7p1 /mnt/astra-usb-1000   ro,nosuid,nodev,noexec,relatime,...
```

**Что должно получиться.** Среди параметров есть `ro`. В этой практике переключается наша исправная ext4. Режим `ro` не является универсальным способом криминалистического доступа без любой записи: при подключении повреждённой журналируемой файловой системы возможна обработка журнала, требующая отдельных мер.

### 11.2. Проверьте чтение и ожидаемый запрет записи

```bash
cat "$LAB_MNT/training/report.txt"
lab_check_mount && touch "$LAB_MNT/training/readonly-test.txt"
```

`cat` читает файл без флагов. `touch` обычно создаёт пустой файл или меняет временные отметки существующего; флагов здесь нет. Каталог `training` уже принадлежит вам, поэтому ожидаемый отказ связан с режимом файловой системы, а не с отсутствием прав на этот каталог.

**Пример вывода:**

```text
Astra Linux storage practice
The file is stored inside the USB image.
OK: ...
OK: ...
touch: cannot touch '.../readonly-test.txt': Read-only file system
```

**Что должно получиться.** Чтение работает, запись отвергнута, файл `readonly-test.txt` не создан. Это ожидаемая ошибка данного шага. Если файл создался, проверьте фактические параметры монтирования, прежде чем продолжать.

### 11.3. Верните режим чтения и записи

```bash
lab_check_mount && sudo mount -o remount,rw,nosuid,nodev,noexec "$LAB_MNT"
findmnt --mountpoint "$LAB_MNT" --output SOURCE,TARGET,OPTIONS
```

Здесь `-o` снова задаёт параметры `mount`, `remount` меняет существующее монтирование, `rw` возвращает запись; остальные три ограничения сохранены. Функция перед `&&` проверяет принадлежность монтирования. `findmnt` показывает результат.

**Пример результата:**

```text
OK: ...
OK: ...
SOURCE       TARGET               OPTIONS
/dev/loop7p1 /mnt/astra-usb-1000   rw,nosuid,nodev,noexec,relatime,...
```

## 12. Почему бывает «target is busy» и как правильно размонтировать

### 12.1. Смоделируйте занятую точку

```bash
cd "$LAB_MNT/training"
pwd
lab_check_mount && sudo umount "$LAB_MNT"
```

`cd` переводит вашу оболочку внутрь флешки. `pwd` печатает текущий каталог. `umount` отключает файловую систему от дерева путей; флагов нет. Имя команды именно `umount`, без буквы `n` после `u`.

**Пример результата:**

```text
/mnt/astra-usb-1000/training
OK: ...
OK: ...
umount: /mnt/astra-usb-1000: target is busy.
```

**Что должно получиться.** Размонтирование не выполнено: текущий каталог вашей Bash находится внутри этой файловой системы. Это намеренно воспроизведённая ситуация; SSH при этом не закрывается. Другими причинами занятости могут быть открытый файл, текущий каталог другой оболочки или вложенное монтирование.

### 12.2. Освободите каталог и размонтируйте

```bash
cd "$HOME"
sync
lab_check_mount && sudo umount "$LAB_MNT"
if mountpoint -q "$LAB_MNT"; then
    printf '%s\n' 'STOP: the training path is still mounted.'
else
    printf '%s\n' 'The training path is not mounted.'
fi
ls -l "$LAB_MNT"
```

`cd` выводит текущую оболочку с носителя, `sync` просит завершить накопленные записи. `umount` без флагов выполняет обычное размонтирование после проверки источника.

`mountpoint` проверяет, является ли путь точкой монтирования. `-q` отключает текстовый вывод самой проверки. Конструкция `if ...; then ... else ... fi` выбирает сообщение по результату команды. `printf` выводит строку, а `ls -l` показывает снова доступное содержимое каталога сервера.

**Пример результата:**

```text
OK: ...
OK: ...
The training path is not mounted.
total ...
-rw-r--r-- 1 root root ... before-mount.txt
```

`report.txt` не потерян: он остался в образе, который сейчас не подключён к каталогу. `before-mount.txt` появился снова, поскольку лежал под монтированием на файловой системе сервера.

Если путь всё ещё смонтирован, не переходите к отключению loop-устройства. Не используйте здесь принудительное или ленивое размонтирование: сначала устраните занятость своего учебного объекта.

### 12.3. Сравните точное монтирование и содержащую файловую систему

```bash
findmnt --target "$LAB_MNT" --output SOURCE,TARGET,FSTYPE
```

`--target` ищет файловую систему, содержащую путь; `--output` выбирает столбцы. Поэтому после размонтирования флешки команда обычно покажет системный раздел, на котором находится каталог `/mnt`.

**Пример результата:**

```text
SOURCE    TARGET FSTYPE
/dev/vda1 /      ext4
```

Это не означает, что флешка снова смонтировалась. Для проверки именно её точки используйте `mountpoint` или `findmnt --mountpoint`, как в предыдущих шагах.

## 13. Проверка ext4 и эмуляция извлечения

### 13.1. Проверьте только размонтированную файловую систему

```bash
if findmnt --noheadings --source "$LAB_PART"; then
    printf '%s\n' 'STOP: unmount the training partition before checking it.'
else
    lab_check_device && sudo e2fsck -f -n "$LAB_PART"
fi
```

`findmnt --source` ищет монтирования указанного раздела; `--noheadings` убирает заголовок. Если хотя бы одно найдено, выполняется только сообщение об остановке. Иначе `lab_check_device` проверяет образ и разрешает запуск `e2fsck`.

`e2fsck` проверяет файловые системы семейства ext. `-f` просит полную проверку даже при отметке чистого состояния; `-n` открывает файловую систему для чтения и отвечает «нет» на предложения исправлений. Автоматическое исправление в этом упражнении не выполняется.

**Пример сокращённого результата:**

```text
OK: /dev/loop7p1 belongs to /var/tmp/astra-storage-1000/usb.img
e2fsck ...
Pass 1: Checking inodes, blocks, and sizes
Pass 2: Checking directory structure
Pass 3: Checking directory connectivity
Pass 4: Checking reference counts
Pass 5: Checking group summary information
USB1000: ... files, ... blocks
```

**Что должно получиться.** Проверка завершена без неисправленных ошибок. Если найдены ошибки, не добавляйте `-y` и не переносите команду на системный раздел. Даже проверка без исправления на смонтированной ext4 не даёт надёжного результата; поэтому здесь предусмотрено предварительное размонтирование.

### 13.2. Отсоедините только своё loop-устройство

```bash
if findmnt --noheadings --source "$LAB_PART"; then
    printf '%s\n' 'STOP: the training partition is still mounted.'
else
    lab_check_device && sudo losetup --detach "$LAB_LOOP"
fi
sudo udevadm settle --timeout=10
sudo losetup --associated "$LAB_IMAGE"
```

Проверка `findmnt` не даёт продолжать при обнаруженном монтировании раздела. `losetup --detach` отключает **одно** устройство, путь которого хранится в `$LAB_LOOP`. Проверка `lab_check_device` перед `&&` подтверждает его связь с образом.

`udevadm settle --timeout=10` ожидает обработки событий. `losetup --associated` перечисляет связи только для указанного образа, не затрагивая остальные loop-устройства.

**Пример результата:**

```text
OK: /dev/loop7p1 belongs to /var/tmp/astra-storage-1000/usb.img
```

Само отключение и успешное ожидание обычно не печатают текст; последняя команда должна дать **пустой вывод**. Если связь осталась, не удаляйте образ. Отключение loop может быть отложено ядром при сохранённых ссылках на устройство; сначала нужно убедиться в завершении использования.

Это аналог извлечения именно виртуального накопителя: файл образа сохраняется. Другие loop-устройства могут использоваться системой, поэтому общий сброс всех связей не применяется.

## 14. Повторное подключение и сохранность данных

### 14.1. Подключите тот же образ без повторного форматирования

```bash
LAB_LOOP="$(sudo losetup --find --show --partscan --nooverlap "$LAB_IMAGE")"
LAB_PART="${LAB_LOOP}p1"
sudo udevadm settle --timeout=10
lab_check_device
sudo blkid "$LAB_PART"
```

`--find` выбирает свободное устройство, `--show` сообщает его путь, `--partscan` читает разметку, `--nooverlap` предотвращает создание независимой повторной связи для того же образа. Переменные обновляются для нового подключения. `udevadm settle --timeout=10` ждёт обработки событий. Функция снова проверяет принадлежность, `blkid` читает сведения о файловой системе без её изменения.

**Пример сокращённого результата:**

```text
OK: /dev/loop8p1 belongs to /var/tmp/astra-storage-1000/usb.img
/dev/loop8p1: LABEL="USB1000" UUID="11111111-2222-3333-4444-555555555555" TYPE="ext4" ...
```

Номер мог измениться с `loop7` на `loop8`, а UUID и данные должны сохраниться. Именно поэтому нельзя записывать номер loop вручную и считать его постоянным именем флешки.

### 14.2. Сравните UUID и смонтируйте существующую ext4

```bash
LAB_CURRENT_UUID="$(sudo blkid -s UUID -o value "$LAB_PART")"
if [[ -n "$LAB_UUID" && "$LAB_CURRENT_UUID" = "$LAB_UUID" ]]; then
    lab_check_device && sudo mount -t ext4 -o rw,nosuid,nodev,noexec "$LAB_PART" "$LAB_MNT"
else
    printf '%s\n' 'STOP: the filesystem UUID is different or was not saved.'
fi
```

У `blkid` параметр `-s UUID` выбирает UUID, `-o value` — только значение. Оно сохраняется в отдельную переменную, чтобы не затереть прежний UUID.

`[[ -n ... ]]` проверяет непустую строку; `&&` требует успеха обеих проверок, `=` сравнивает UUID. Если они совпали, `mount -t ext4` подключает существующую файловую систему; `-o rw,nosuid,nodev,noexec` задаёт прежние параметры. Сборка таблицы разделов и форматирование не повторяются.

**Пример результата:** строки `OK` проверки устройства; при успехе сам `mount` молчит. Сообщение `STOP` означает, что продолжать к записи не нужно.

### 14.3. Проверьте файл после переподключения

```bash
lab_check_mount
cat "$LAB_MNT/training/report.txt"
cd "$LAB_MNT/training"
sha256sum -c SHA256SUMS
cd "$HOME"
```

`lab_check_mount` проверяет точное монтирование. `cat` читает сохранённый файл. `cd` сначала выбирает каталог с относительными именами из ведомости, затем возвращает в домашний каталог. `sha256sum -c` проверяет данные по сохранённой сумме.

**Пример результата:**

```text
OK: ...
OK: ...
Astra Linux storage practice
The file is stored inside the USB image.
report.txt: OK
```

**Что должно получиться.** Данные пережили размонтирование, отключение и новое подключение. Они находились внутри образа, а не в памяти терминала.

## 15. Монтирование по UUID и отдельный файл формата fstab

Для постоянных накопителей обычно удобнее указывать UUID файловой системы, чем изменчивое имя устройства. Но учебный loop-образ сам по себе не обязан автоматически подключаться при загрузке. Добавление его UUID в настоящий `/etc/fstab` не создаёт loop-связь заранее.

Поэтому сейчас используем отдельный `$LAB_FSTAB`: он демонстрирует формат и ручное применение записи, но не меняет загрузку сервера.

### 15.1. Запишите одну учебную строку

```bash
printf 'UUID=%s %s ext4 noauto,nofail,nosuid,nodev,noexec 0 0\n' "$LAB_UUID" "$LAB_MNT" | sudo tee "$LAB_FSTAB"
```

`printf` подставляет UUID и точку монтирования в два `%s`, `\n` завершает строку. Конвейер `|` передаёт её `sudo tee`, который записывает в наш отдельный файл и печатает в терминал. Флагов у `tee` нет. Настоящий `/etc/fstab` не используется как путь назначения.

**Пример вывода:**

```text
UUID=11111111-2222-3333-4444-555555555555 /mnt/astra-usb-1000 ext4 noauto,nofail,nosuid,nodev,noexec 0 0
```

Запись состоит из шести полей, разделённых пробелами:

| Поле | Значение | Объяснение |
| --- | --- | --- |
| 1 | `UUID=...` | Какую файловую систему подключать |
| 2 | `/mnt/astra-usb-1000` | Куда её подключать |
| 3 | `ext4` | Какой драйвер файловой системы использовать |
| 4 | `noauto,nofail,nosuid,nodev,noexec` | Параметры, разделённые запятыми |
| 5 | `0` | Не включать эту файловую систему в отбор резервного копирования утилитой dump |
| 6 | `0` | Не назначать ей порядок автоматической проверки fsck по этой записи |

`noauto` исключает запись из автоматического общего монтирования; явный вызов для нужной точки остаётся возможным. `nofail` задаёт допускающее отсутствие устройства поведение при соответствующей обработке таблицы; он не исправляет UUID и не гарантирует успешное ручное монтирование. `nosuid,nodev,noexec` имеют разобранный ранее смысл. Здесь режим записи используется по умолчанию, отдельного `ro` нет.

В реальной загрузке systemd также интерпретирует параметры `fstab`. Наш отдельный файл не подключён к загрузке, поэтому его создание не создаёт постоянный системный mount-юнит.

### 15.2. Проверьте запись без монтирования всех устройств

```bash
sudo findmnt --verify --verbose --tab-file "$LAB_FSTAB"
```

`findmnt --verify` проверяет содержимое таблицы: разбор записи, источник и точку. `--verbose` выводит подробности проверки; `--tab-file` выбирает наш файл вместо стандартного `/etc/fstab`. `sudo` даёт доступ к данным устройств.

**Пример сокращённого результата:**

```text
/mnt/astra-usb-1000
   [ ] target exists
   [ ] UUID=... translated to /dev/loop8p1
   [ ] FS type is ext4
Success, no errors or warnings detected
```

**Что должно получиться.** Нет ошибок проверки; UUID соответствует текущему разделу образа. Если UUID не разрешается, проверьте успешность подключения и обработки udev, фактический вывод `blkid` и записанную строку. Не подставляйте вместо него UUID системного раздела.

Эта проверка не заменяет настоящий вызов `mount`. Общий `mount -a` для проверки конфигурации не нужен: он способен затронуть другие записи системы.

### 15.3. Размонтируйте и подключите по учебной записи

```bash
cd "$HOME"
sync
lab_check_mount && sudo umount "$LAB_MNT"
lab_check_device && sudo mount --fstab "$LAB_FSTAB" "$LAB_MNT"
findmnt --mountpoint "$LAB_MNT" --output SOURCE,TARGET,FSTYPE,OPTIONS
```

`cd` освобождает текущий каталог, `sync` просит записать накопленные изменения. `umount` без флагов отключает наше проверенное монтирование.

У `mount` параметр `--fstab` выбирает отдельную таблицу. Единственный аргумент после неё — точка монтирования; источник, тип и параметры берутся из соответствующей строки файла. Это явный вызов, поэтому `noauto` ему не мешает. `lab_check_device` предварительно подтверждает наличие нашего loop-раздела.

`findmnt --mountpoint` проверяет точное монтирование, `--output` задаёт столбцы.

**Пример результата:**

```text
OK: ...
OK: ...
OK: ...
SOURCE       TARGET               FSTYPE OPTIONS
/dev/loop8p1 /mnt/astra-usb-1000   ext4   rw,nosuid,nodev,noexec,relatime,...
```

**Что должно получиться.** Источник найден по UUID, а не по старому номеру loop. Флаги `noauto` и `nofail` не обязаны отображаться в параметрах ядра: часть параметров используется средствами монтирования в пользовательском пространстве.

### 15.4. Ещё раз проверьте данные

```bash
lab_check_mount
cd "$LAB_MNT/training"
sha256sum -c SHA256SUMS
cd "$HOME"
```

Функция проверяет устройство и точное монтирование. `cd` выбирает каталог данных; `sha256sum -c` сверяет файл с ведомостью; последний `cd` выводит оболочку из флешки перед завершением работы.

**Пример результата:**

```text
OK: ...
OK: ...
report.txt: OK
```

## 16. Что сохранить как результат

После выполнения вы должны уметь объяснить не только команды, но и цепочку: **файл-образ → loop-устройство → раздел → ext4 → точка монтирования → файл пользователя**.

| Выполнено | Результат | Как подтверждается |
| --- | --- | --- |
| [ ] | Изучены основные каталоги Linux | Просмотр путей и понимание назначения `/etc`, `/dev`, `/mnt`, `/var/tmp` |
| [ ] | Найдена корневая файловая система без её изменения | Вывод `findmnt --target /` |
| [ ] | Создан образ 128 MiB | `ls -lh` и объяснение отличия от `du` |
| [ ] | Внутри образа есть один раздел 120 MiB | `sfdisk --dump` |
| [ ] | Подтверждена связь loop с образом | `losetup --list` со столбцом `BACK-FILE` |
| [ ] | Создана ext4 с собственной меткой и UUID | `blkid` и `lsblk` |
| [ ] | Флешка смонтирована с ограничениями | `findmnt` с `nosuid,nodev,noexec` |
| [ ] | Записан файл от обычного пользователя | `cat` и `ls -l` |
| [ ] | Проверен режим `ro` | Параметры монтирования и ожидаемый отказ `touch` |
| [ ] | Понятна причина занятого монтирования | Ошибка `target is busy` и успешный выход из каталога |
| [ ] | Данные сохранились после извлечения и подключения | `report.txt: OK` после нового loop-подключения |
| [ ] | Проверена и применена запись с UUID | Отдельный `fstab.example`, проверка `findmnt --verify`, ручной вызов `mount --fstab` |
| [ ] | Учебное устройство отключено после работы | Пустой вывод `losetup --associated` для нашего образа |

Для подтверждения можно сохранить скриншоты `lsblk`, связи `BACK-FILE`, вывода `findmnt`, содержимого файла и результата `sha256sum -c`. Не включайте в них пароль или ключи SSH. Скриншоты делаются средствами вашего компьютера; графическое окружение на сервере устанавливать не нужно.

## 17. Если SSH-соединение разорвалось

Не начинайте заново с разметки и форматирования. Выйти из SSH — не то же самое, что размонтировать файловую систему. После входа в новую Bash сначала повторите **только блок переменных из раздела 5.1**, а затем прочитайте текущее состояние:

```bash
sudo ls -lh "$LAB_IMAGE"
sudo losetup --associated "$LAB_IMAGE"
findmnt --mountpoint "$LAB_MNT" --output SOURCE,TARGET,FSTYPE,OPTIONS
```

`ls -lh` показывает наличие и размер образа. `losetup --associated` ищет связи только нашего файла. `findmnt --mountpoint` показывает точное монтирование, `--output` выбирает столбцы. Все эти действия — просмотр.

**Возможный пример вывода:**

```text
-rw------- 1 root root 128M ... /var/tmp/astra-storage-1000/usb.img
/dev/loop8: ... (/var/tmp/astra-storage-1000/usb.img)
SOURCE       TARGET               FSTYPE OPTIONS
/dev/loop8p1 /mnt/astra-usb-1000   ext4   rw,nosuid,nodev,noexec,...
```

Если связи нет, `losetup` ничего не напечатает. Если точного монтирования нет, `findmnt` завершится без строки результата с ненулевым кодом; это может быть нормальным состоянием после размонтирования, а не потерей данных.

### 17.1. Восстановите переменные существующей связи

Этот блок используется, только если предыдущий просмотр показал ровно одно loop-устройство нашего образа:

```bash
LAB_LOOP="$(sudo losetup --list --noheadings --raw --output NAME --associated "$LAB_IMAGE")"
if [[ "$LAB_LOOP" =~ ^/dev/loop[0-9]+$ ]]; then
    LAB_PART="${LAB_LOOP}p1"
    LAB_UUID="$(sudo blkid -s UUID -o value "$LAB_PART")"
    printf '%s\n' "$LAB_LOOP" "$LAB_PART" "$LAB_UUID"
else
    printf '%s\n' 'STOP: expected exactly one existing loop association.'
fi
```

`--list` выбирает таблицу `losetup`, `--noheadings --raw` убирают заголовок и выравнивание, `--output NAME` оставляет только имя, `--associated` ограничивает связи нашим образом. Регулярное выражение `^/dev/loop[0-9]+$` принимает только одно имя; несколько строк или пустой результат не проходят проверку.

`LAB_PART` снова обозначает первый раздел; `blkid -s UUID -o value` восстанавливает UUID из существующей ext4. `printf` показывает значения.

**Пример результата:**

```text
/dev/loop8
/dev/loop8p1
11111111-2222-3333-4444-555555555555
```

Затем заново определите функции блоками из разделов 7.3 и 9.3. Вторая функция при отсутствии монтирования ожидаемо не подтвердит его. Если образ подключён, но не смонтирован, после успешной проверки устройства выполните только монтирование из раздела 9.2, без разметки и `mkfs`.

Если loop-связи нет, но существующий образ и его разметка сохранены, восстановление подключения начинается с раздела 14.1. Получите UUID текущей ext4 через `blkid`, определите функции и подключите существующий раздел по разделу 9.2. Не создавайте новый образ поверх старого и не форматируйте его для «исправления» потери переменных.

Если обнаружены несколько связей или непонятный источник в точке монтирования, остановитесь и разберите состояние до любых изменений.

## 18. Завершение работы и очистка

Удаление образа удалит находящиеся в нём учебные файлы. Сначала сохраните нужные результаты. Можно оставить образ для следующего занятия, но файловую систему следует штатно размонтировать, а loop-связь — отключить.

### 18.1. Размонтируйте последнюю учебную сессию

```bash
cd "$HOME"
sync
lab_check_mount && sudo umount "$LAB_MNT"
```

`cd` выводит оболочку с носителя, `sync` просит завершить накопленные записи, `lab_check_mount` проверяет источник. После успеха `&&` допускает обычный `umount` без флагов.

**Пример результата:** две строки `OK`; само успешное размонтирование не печатает текст. Если вы уже размонтировали файловую систему раньше, проверка монтирования не пройдёт — не нужно снова монтировать носитель только ради этого шага. Убедитесь, что точка свободна, следующим просмотром.

### 18.2. Отключите связь и проверьте состояние

```bash
if findmnt --noheadings --source "$LAB_PART"; then
    printf '%s\n' 'STOP: the training partition is still mounted.'
else
    lab_check_device && sudo losetup --detach "$LAB_LOOP"
fi
sudo udevadm settle --timeout=10
sudo losetup --associated "$LAB_IMAGE"
if mountpoint -q "$LAB_MNT"; then
    printf '%s\n' 'STOP: the training path is still mounted.'
else
    printf '%s\n' 'The training path is not mounted.'
fi
```

`findmnt --source` с `--noheadings` проверяет использование именно раздела. `losetup --detach` отключает только наше проверенное устройство. `udevadm settle --timeout=10` ждёт события, `--associated` показывает оставшиеся связи образа. `mountpoint -q` отдельно проверяет точку монтирования без собственного текста, `if` выводит понятный результат.

**Пример результата:**

```text
OK: /dev/loop8p1 belongs to /var/tmp/astra-storage-1000/usb.img
The training path is not mounted.
```

Между этими строками `losetup --associated` ничего не должен вывести. Если связь или монтирование остались, не удаляйте файлы. Если связь уже была отключена ранее, проверка устройства не пройдёт; оценивайте подтверждённое отсутствие связи и монтирования, а не повторяйте отключение чужого loop-устройства.

### 18.3. При необходимости удалите образ и учебные каталоги

Сначала ещё раз покажите точные пути:

```bash
printf '%s\n' "$LAB_BASE" "$LAB_IMAGE" "$LAB_FSTAB" "$LAB_MNT"
```

`printf '%s\n'` печатает по одному значению на строку; флагов нет.

**Пример результата:**

```text
/var/tmp/astra-storage-1000
/var/tmp/astra-storage-1000/usb.img
/var/tmp/astra-storage-1000/fstab.example
/mnt/astra-usb-1000
```

Если значения пусты или отличаются от созданных путей, не продолжайте. Следующий блок проверяет принадлежность путей практике, отсутствие точного монтирования и отсутствие loop-связи:

```bash
if [[ "$LAB_UID" = "$(id -u)" && "$LAB_BASE" = "/var/tmp/astra-storage-$LAB_UID" && "$LAB_IMAGE" = "$LAB_BASE/usb.img" && "$LAB_FSTAB" = "$LAB_BASE/fstab.example" && "$LAB_MNT" = "/mnt/astra-usb-$LAB_UID" ]]; then
    if mountpoint -q "$LAB_MNT"; then
        printf '%s\n' 'STOP: unmount the training path before deleting files.'
    else
        LAB_ASSOC="$(sudo losetup --associated "$LAB_IMAGE")"
        if [[ $? -eq 0 && -z "$LAB_ASSOC" ]]; then
            sudo rm -i -- "$LAB_IMAGE" "$LAB_FSTAB" "$LAB_MNT/before-mount.txt"
            sudo rmdir -- "$LAB_MNT" "$LAB_BASE"
        else
            printf '%s\n' 'STOP: an association remains or its check failed.'
        fi
    fi
else
    printf '%s\n' 'STOP: training paths do not match. Nothing was removed.'
fi
```

| Элемент | Значение |
| --- | --- |
| `[[ ... ]]` | Условие Bash |
| `=` | Проверка равенства строк |
| `&&` | Все перечисленные проверки должны быть успешны |
| `$(id -u)` | Текущий UID, заново полученный перед удалением |
| `mountpoint -q` | Тихая проверка наличия монтирования |
| `LAB_ASSOC="$(...)"` | Сохранение вывода связей нашего образа |
| `$? -eq 0` | Предыдущая проверка завершилась успешно: код равен нулю |
| `-z "$LAB_ASSOC"` | Список связей пуст |
| `rm -i` | Спрашивать подтверждение перед удалением каждого указанного файла |
| `--` | Далее передаются пути, а не флаги |
| `rmdir` | Удалять только пустые каталоги |

**Пример результата при подтверждении удаления:**

```text
rm: remove regular file '/var/tmp/astra-storage-1000/usb.img'?
rm: remove regular file '/var/tmp/astra-storage-1000/fstab.example'?
rm: remove regular file '/mnt/astra-usb-1000/before-mount.txt'?
```

Ответ зависит от языка сообщений. Если файл ещё не был создан или вы отказались от удаления, он останется либо появится сообщение об отсутствии; `rmdir` не удалит непустой каталог. Здесь нет рекурсивного удаления, поэтому неожиданные дополнительные файлы не будут автоматически стёрты.

Удаляются только названные объекты практики. Остальные разделы, loop-устройства, каталоги `/mnt` и `/var/tmp` сохраняются. Дополнительные инструменты, если вы устанавливали их в начале, автоматически не удаляются.

## 19. Если что-то не получилось

| Сообщение или ситуация | Возможный смысл | Что делать |
| --- | --- | --- |
| `command not found` | Нет программы в пути поиска | Проверить установку инструмента и пути `/sbin`, `/usr/sbin`; подготовку пакетов разобрали в разделе 1 |
| `Operation not permitted` для loop или mount | Недостаточно полномочий или действует ограничение среды | Проверить разрешения с администратором; не отключать средства защиты Astra Linux |
| `cannot find an unused loop device` | Недоступен драйвер, устройства или свободная связь | Не использовать настоящий диск взамен; уточнить возможность loop в учебной ВМ |
| Нет `/dev/loopNp1` | Не прочитана таблица, не завершены события udev или среда не разрешает разделы loop | Проверить `sfdisk --dump`, подключение с `--partscan` и результат ожидания; не создавать узлы устройств вручную |
| `wrong fs type` или `bad superblock` | Выбран неверный объект, нет ext4 или она повреждена | Сверить `BACK-FILE`, путь раздела и `blkid`; не запускать новое форматирование поверх данных |
| `Permission denied` при записи | Не тот владелец каталога или действуют дополнительные ограничения | Проверить `ls -ld` и точное монтирование; создать свой подкаталог по разделу 10 |
| `Read-only file system` | Действует `ro` | В разделе 11 это ожидаемо; вне его сначала проверить параметры и состояние файловой системы |
| `target is busy` | Процесс использует файловую систему | Выйти из её каталога, закрыть свои открытые файлы; не завершать неизвестные процессы сервера |
| После размонтирования видны другие файлы | Снова видно содержимое каталога под монтированием | Это нормальный эффект, показанный через `before-mount.txt` |
| UUID не найден | Образ отключён, другой UUID или не обработаны события устройств | Сверить `losetup`, `blkid`, `udevadm settle` и учебную запись |
| `report.txt: FAILED` | Данные не совпали с ведомостью | Проверить источник и содержимое; не переписывать ведомость только ради получения `OK` |
| `No space left on device` | Закончились блоки или inode | Сравнить `df -hT` и `df -i`; не чистить системные каталоги наугад |
| Пустые `LAB_LOOP` или `LAB_PART` | Ошибка подключения или новый сеанс Bash | Восстановить состояние по разделу 17; не подставлять номер устройства из примера |

Сведения о системных устройствах в этой практике читаются для понимания. Разметка выполняется внутри нового файла, форматирование — только на проверенном разделе этого образа. Перезагрузка, изменение сетевых настроек, общий демонтаж файловых систем, переписывание настоящего `fstab` и форматирование реальных дисков для выполнения задания не требуются.
