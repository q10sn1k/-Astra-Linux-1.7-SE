# Простая инструкция по Git и GitHub 

Эта инструкция описывает  простой рабочий сценарий: установить Git, создать аккаунт на GitHub, создать репозиторий, скопировать его на компьютер, внести изменения, сохранить их в Git и отправить на GitHub.

Здесь  не рассматриваются дополнительные сложные темы. 

Цель — освоить базовый путь работы с уже созданным репозиторием GitHub.

---

## 0. Что такое Git и GitHub

**Git** — это программа для контроля версий. Она хранит историю изменений файлов: что изменилось, когда изменилось и с каким комментарием было сохранено.

**GitHub** — это онлайн-платформа, где можно хранить Git-репозитории. Репозиторий можно представить как папку проекта, у которой есть история изменений и удалённая копия в интернете.

Простыми словами:

- Git работает на вашем компьютере;
- GitHub хранит копию проекта в интернете;
- команды `git add`, `git commit`, `git push` и `git pull` помогают переносить изменения между компьютером и GitHub.

## 0.1. Установка Git на Windows

Официальная страница установки Git для Windows:

https://git-scm.com/install/windows

Что нужно сделать:

1. Откройте ссылку.
2. Скачайте установщик Git for Windows.
3. Запустите установку.
4. На первых этапах можно оставить настройки по умолчанию.
5. После установки откройте **Git Bash** или обычный терминал.
6. Проверьте, что Git установлен:

```bash
git --version
```

Если Git установлен корректно, терминал покажет версию, например:

```bash
git version 2.xx.x
```

Точная версия может отличаться. Это нормально.

## 0.2. Установка Git на macOS

Официальная страница установки Git для macOS:

https://git-scm.com/install/mac

Что нужно сделать:

1. Откройте ссылку.
2. Выберите удобный способ установки.
3. После установки откройте приложение **Terminal**.
4. Проверьте установку командой:

```bash
git --version
```

Если Git уже установлен, терминал покажет его версию. На некоторых компьютерах Mac Git может быть уже доступен, но всё равно полезно проверить это командой выше.

## 1. Создание аккаунта на GitHub

Официальная страница регистрации:

https://github.com/signup

Что нужно сделать:

1. Откройте страницу регистрации.
2. Укажите email.
3. Придумайте пароль.
4. Придумайте username — имя пользователя на GitHub.
5. Подтвердите email, если GitHub попросит это сделать.

Username будет использоваться в ссылках на ваши репозитории. Например, если username — `ivanov`, то ссылка на репозиторий может выглядеть так:

```text
https://github.com/ivanov/my-project
```

Важно: используйте email, к которому у вас есть постоянный доступ. GitHub может отправлять на него уведомления и подтверждения.

## 2. Создание access token на GitHub

GitHub не использует обычный пароль как пароль для Git-команд через HTTPS. Вместо пароля используется **Personal Access Token**. Его часто называют просто **token** или **access token**.

Официальная документация GitHub по personal access token:

https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens

Зачем нужен token:

- он заменяет пароль при работе с GitHub из терминала;
- с ним можно выполнять `git clone`, `git push`, `git pull` для доступных репозиториев;
- его можно ограничить по сроку действия и правам доступа;
- его можно отозвать, если он случайно попал не туда.

Простой порядок создания token:

1. Войдите в GitHub.
2. Откройте настройки аккаунта: **Settings**.
3. Перейдите в раздел **Developer settings**.
4. Откройте **Personal access tokens**.
5. Выберите вариант создания token.
6. Укажите название token, например `git-token-for-study`.
7. Укажите срок действия token.
8. Выберите доступ к нужному репозиторию.
9. Для обычной работы с файлами выберите права на чтение и запись содержимого репозитория, то есть **Contents: Read and write**.
10. Создайте token.
11. Скопируйте token и сохраните его в безопасном месте.

Важно: GitHub показывает token только один раз. Если вы закрыли страницу и не сохранили token, посмотреть его заново обычно нельзя. В таком случае нужно создать новый token.

Как token используется в терминале:

- когда Git спросит username, введите ваш GitHub username;
- когда Git спросит password, вставьте token вместо пароля.

Пример:

```text
Username: your-github-username
Password: вставьте personal access token
```

В терминале символы пароля могут не отображаться. Это нормально: token вводится, даже если вы не видите его на экране.

## 3. Создание репозитория на GitHub

Репозиторий — это проект на GitHub. В нём хранятся файлы и история изменений.

Страница создания нового репозитория:

https://github.com/new

Что нужно сделать:

1. Откройте страницу создания репозитория.
2. В поле **Repository name** укажите название проекта, например:

```text
my-first-project
```

3. Выберите тип репозитория:

   - **Public** — репозиторий виден всем;
   - **Private** — репозиторий виден только вам и тем, кому вы дадите доступ.

4. При необходимости добавьте описание в поле **Description**.
5. Для первого учебного проекта можно включить опцию **Add a README file**. Тогда в репозитории сразу появится файл `README.md`.
6. Нажмите **Create repository**.

После создания GitHub покажет страницу репозитория. На ней будет кнопка **Code**. Через неё можно получить ссылку для клонирования.

Пример ссылки:

```text
https://github.com/your-username/my-first-project.git
```

В этой ссылке:

- `your-username` — ваш username на GitHub;
- `my-first-project` — название вашего репозитория.

## 4. Настройка Git config

Перед первой работой нужно настроить имя и email. Эти данные будут попадать в историю коммитов. Коммит — это сохранённое состояние изменений в Git.

Настройка имени:

```bash
git config --global user.name "Ваше Имя"
```

Настройка email:

```bash
git config --global user.email "your.email@example.com"
```

Пример:

```bash
git config --global user.name "Ivan Ivanov"
git config --global user.email "ivanov@example.com"
```

Флаг `--global` означает, что настройка применяется ко всем Git-проектам на этом компьютере.

Проверить настройки можно командой:

```bash
git config --global --list
```

В результате вы должны увидеть примерно такие строки:

```text
user.name=Ivan Ivanov
user.email=ivanov@example.com
```

Если вы работаете на учебном или чужом компьютере, внимательно проверьте, какой email указан в настройках. Иначе ваши коммиты могут быть подписаны чужими данными.

## 5. Клонирование репозитория: `git clone`

Клонирование — это скачивание репозитория с GitHub на компьютер.

Сначала откройте терминал и перейдите в папку, где хотите хранить проекты. Например:

```bash
cd Desktop
```

Затем выполните команду:

```bash
git clone https://github.com/your-username/my-first-project.git
```

Замените ссылку на ссылку вашего репозитория.

После выполнения команды появится папка проекта. Перейдите в неё:

```bash
cd my-first-project
```

Теперь вы находитесь внутри локальной копии репозитория. Именно здесь нужно создавать, изменять и сохранять файлы проекта.

Если репозиторий private, GitHub может попросить username и password. В поле password нужно вставить personal access token, а не обычный пароль от GitHub.

## 6. Проверка состояния: `git status`

Команда `git status` показывает текущее состояние репозитория.

```bash
git status
```

Она помогает понять:

- какие файлы изменены;
- какие файлы новые;
- какие файлы уже подготовлены к коммиту;
- есть ли изменения, которые ещё не сохранены в истории Git.

Пример обычной ситуации:

```text
On branch main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean
```

Это означает, что изменений нет, всё сохранено, локальный репозиторий совпадает с GitHub.

Если вы изменили файл, Git может показать примерно такое сообщение:

```text
Changes not staged for commit:
  modified: README.md
```

Это означает, что файл изменён, но ещё не подготовлен к коммиту.

Рекомендуемое правило: перед `add`, перед `commit` и перед `push` полезно выполнять `git status`. Это снижает риск отправить не те файлы или забыть нужные изменения.

---

## 7. Подготовка файлов к коммиту: `git add`

Команда `git add` подготавливает изменения к коммиту. Она не отправляет файлы на GitHub и не создаёт коммит. Она только говорит Git: «эти изменения нужно включить в ближайшее сохранение».

Добавить все изменённые и новые файлы:

```bash
git add .
```

Точка означает «всё в текущей папке и внутри неё».

Добавить только конкретные файлы:

```bash
git add filename1.txt filename2.md
```

Пример:

```bash
git add README.md notes.txt
```

Когда использовать `git add .`:

- если вы точно хотите добавить все текущие изменения;
- если проект небольшой;
- если вы перед этим проверили `git status`.

Когда лучше указывать файлы вручную:

- если изменено много файлов;
- если часть изменений ещё не готова;
- если вы хотите сделать аккуратный коммит только по одной задаче.

После `git add` снова выполните:

```bash
git status
```

Если всё готово к коммиту, Git покажет изменения в блоке `Changes to be committed`.

---

## 8. Создание коммита: `git commit -m`

Коммит — это сохранённая точка в истории проекта. В коммите фиксируется, какие изменения были сделаны.

Команда:

```bash
git commit -m "комментарий"
```

Пример:

```bash
git commit -m "Добавил описание проекта"
```

Комментарий должен кратко объяснять, что изменилось. Не стоит писать слишком общие сообщения вроде:

```text
update
changes
fix
```

Лучше писать конкретно:

```text
Добавил инструкцию по установке Git
Исправил описание команды git status
Обновил README для первого запуска
```

Хороший комментарий помогает потом понять историю проекта. Через неделю или месяц будет видно, зачем был сделан конкретный коммит.

Если после `git commit` появляется сообщение `nothing to commit`, значит нет подготовленных изменений. В этом случае нужно выполнить:

```bash
git status
```

и проверить, были ли выполнены команды `git add`.

## 9. Отправка изменений на GitHub: `git push origin main`

Команда `git push` отправляет локальные коммиты на GitHub.

Обычная команда:

```bash
git push origin main
```

Здесь:

- `push` означает отправку изменений;
- `origin` — имя удалённого репозитория на GitHub;
- `main` — основная линия работы в репозитории.

Если GitHub попросит логин и пароль:

- введите username от GitHub;
- вместо пароля вставьте personal access token.

После успешного `push` откройте репозиторий на GitHub в браузере и обновите страницу. Ваши изменения должны появиться там.

Если команда пишет ошибку доступа, проверьте:

- правильно ли скопирована ссылка репозитория;
- есть ли у вас доступ к этому репозиторию;
- не истёк ли срок действия token;
- есть ли у token право на запись в репозиторий;
- правильно ли указано имя `main` в команде отправки.

Если в вашем репозитории основная линия работы называется не `main`, используйте фактическое имя, которое указано на странице репозитория. Для первого учебного сценария обычно используется `main`.

---

## Отдельно: получение изменений с GitHub через `git pull`

Команда `git pull` получает изменения с GitHub в локальную папку.

Обычная команда:

```bash
git pull origin main
```

Она нужна, если:

- вы работали с репозиторием на другом компьютере;
- другой человек добавил изменения в репозиторий;
- вы изменили файлы прямо на GitHub через браузер;
- нужно обновить локальную копию перед новой работой.

Простое правило:

```text
Перед началом работы полезно выполнить git pull origin main.
После завершения работы выполнить git add, git commit и git push origin main.
```

Так локальная папка и репозиторий на GitHub будут оставаться согласованными.


## Типовые ошибки новичка

### Ошибка 1. Вставить обычный пароль вместо token

GitHub при работе через HTTPS ожидает personal access token. Если вставить обычный пароль от аккаунта, команда может не сработать.

### Ошибка 2. Забыть выполнить `git add`

Если файл изменён, но не добавлен через `git add`, он не попадёт в коммит.

Проверка:

```bash
git status
```

### Ошибка 3. Сделать `commit`, но забыть `push`

Коммит сохраняет изменения только локально. Чтобы изменения появились на GitHub, нужно выполнить:

```bash
git push origin main
```

### Ошибка 4. Начать работу без `git pull`

Если на GitHub уже есть новые изменения, а локальная папка не обновлена, могут возникнуть проблемы при отправке. Поэтому перед началом работы полезно выполнить:

```bash
git pull origin main
```

### Ошибка 5. Работать не в той папке

Git-команды нужно выполнять внутри папки репозитория. Если вы скачали репозиторий командой `git clone`, сначала перейдите в папку проекта:

```bash
cd repository-name
```

Потом выполняйте `git status`, `git add`, `git commit`, `git push`.

---

## Главное правило

Обычная работа с GitHub чаще всего выглядит так:

```bash
git pull origin main
git status
git add .
git commit -m "понятный комментарий"
git push origin main
```

Если запомнить эту последовательность и регулярно проверять `git status`, базовая работа с GitHub станет понятной и предсказуемой.
