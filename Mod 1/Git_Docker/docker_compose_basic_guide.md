# Docker Compose: простая инструкция 

Эта инструкция объясняет базовую работу с Docker Compose на примере `docker-compose.yml`. Цель — понять, как установить инструменты, где запускать команды, что означает каждая строка файла и как выполнить полный цикл: запустить контейнер, проверить, остановить и удалить.

Инструкция рассчитана на полный начальный уровень. Здесь не рассматриваются сложные темы вроде собственных Dockerfile, сетей, сборки образов, CI/CD и production-развёртывания.

---

## 1. Что такое Docker простыми словами

Docker — это инструмент для запуска приложений в контейнерах.

Контейнер можно представить как изолированную среду, внутри которой уже есть всё необходимое для работы приложения: системные библиотеки, настройки, зависимости и само приложение. Благодаря этому приложение запускается одинаково на разных компьютерах: у преподавателя, студента, разработчика, тестировщика или на сервере.

Например, RStudio Server можно не устанавливать вручную на компьютер. Вместо этого можно запустить готовый контейнер с RStudio. Docker скачает готовый образ, создаст контейнер и запустит сервис внутри него.

Важно различать два понятия:

- **образ** — это шаблон, из которого создаётся контейнер;
- **контейнер** — это уже запущенный экземпляр образа.

Если провести аналогию, образ похож на установочный файл или шаблон виртуальной машины, а контейнер — на реально запущенную программу.

---

## 2. Что такое Docker Compose

Docker Compose — это инструмент для запуска контейнеров по описанию из файла.

Обычно файл называется:

```text
docker-compose.yml
```

или:

```text
compose.yml
```

В этом файле заранее описывается, какой контейнер нужно запустить, какой образ использовать, какие порты открыть, какие переменные окружения передать и какие папки подключить к контейнеру.

Без Docker Compose пришлось бы писать длинную команду `docker run` с большим количеством параметров. С Docker Compose параметры хранятся в одном понятном файле. Поэтому запуск становится простым:

```bash
docker compose up -d
```

Одна команда читает `docker-compose.yml` и запускает всё, что в нём описано.

---

## 3. Что нужно установить перед работой

Для базовой работы понадобится:

1. **Visual Studio Code** — редактор, в котором удобно открыть папку проекта и файл `docker-compose.yml`.
2. **Docker Desktop** — приложение, которое запускает Docker на Windows и macOS.
3. **Терминал** — PowerShell, Windows Terminal, Terminal на macOS или терминал внутри VS Code.

Docker Desktop должен быть запущен в фоне. Если Docker Desktop закрыт, команды `docker` и `docker compose` могут не работать.

## 4. Установка Visual Studio Code

### 4.1. Windows

Откройте официальный сайт:

```text
https://code.visualstudio.com/download
```

Скачайте установщик для Windows. Обычно подходит вариант **User Installer x64**. После скачивания запустите файл и установите VS Code.

Во время установки удобно включить дополнительные пункты:

- **Add to PATH** — чтобы команда `code` была доступна из терминала;
- **Open with Code** — чтобы можно было открыть папку через контекстное меню.

После установки откройте VS Code и проверьте, что он запускается.

### 4.2. macOS

Откройте официальный сайт:

```text
https://code.visualstudio.com/download
```

Скачайте версию для macOS. Обычно сайт сам предлагает подходящий вариант для Apple Silicon или Intel.

После скачивания откройте файл и перенесите Visual Studio Code в папку **Applications**.

Открыть VS Code можно из Launchpad или из папки Applications.

## 5. Установка Docker Desktop на Windows

Официальная страница установки:

```text
https://docs.docker.com/desktop/setup/install/windows-install/
```

### 5.1. Проверка версии Windows

Для Docker Desktop нужна современная 64-битная Windows.

Минимально ориентируйтесь на Windows 10 или Windows 11. По текущим требованиям Docker Desktop для WSL 2 backend указаны Windows 10 64-bit Enterprise, Pro или Education версии 22H2 и Windows 11 64-bit Enterprise, Pro или Education версии 23H2 или выше. На Windows Home обычно работают Linux-контейнеры через WSL 2, но не Windows-контейнеры.

Проверить версию Windows можно так:

1. Нажмите `Win + R`.
2. Введите:

```text
winver
```

3. Нажмите Enter.
4. Посмотрите версию Windows.

Если версия слишком старая, сначала обновите Windows.

### 5.2. Виртуализация в BIOS/UEFI

Docker Desktop на Windows использует виртуализацию. Для WSL 2 и Hyper-V требуется аппаратная виртуализация.

Проверить её можно так:

1. Нажмите `Ctrl + Shift + Esc`.
2. Откройте **Диспетчер задач**.
3. Перейдите на вкладку **Производительность**.
4. Выберите **ЦП**.
5. Найдите строку **Виртуализация**.

Если там написано **Включено**, всё хорошо.

Если написано **Отключено**, виртуализацию нужно включить в BIOS/UEFI.

Общий порядок такой:

1. Перезагрузите компьютер.
2. Во время запуска нажмите клавишу входа в BIOS/UEFI. Часто это `F2`, `Del`, `F10`, `Esc`, иногда другая клавиша. Она зависит от производителя ноутбука или материнской платы.
3. Найдите настройку виртуализации.
4. У Intel она может называться:
   - `Intel Virtualization Technology`;
   - `VT-x`;
   - `Virtualization Technology`.
5. У AMD она может называться:
   - `SVM Mode`;
   - `AMD-V`.
6. Включите настройку: `Enabled`.
7. Сохраните изменения и выйдите из BIOS/UEFI. Обычно это `F10`, затем подтверждение сохранения.

После перезагрузки снова проверьте виртуализацию в Диспетчере задач.

### 5.3. Установка WSL 2 на Windows

WSL — это Windows Subsystem for Linux. Он позволяет запускать Linux-среду внутри Windows. Docker Desktop на Windows часто использует WSL 2 как backend, то есть как основу для Linux-контейнеров.

Откройте PowerShell или Windows Terminal **от имени администратора**.

Для установки WSL выполните:

```powershell
wsl --install
```

После установки перезагрузите компьютер.

Проверить WSL можно командой:

```powershell
wsl --status
```

Проверить установленные дистрибутивы и их версии можно так:

```powershell
wsl -l -v
```

Если у дистрибутива стоит версия `1`, переключите его на WSL 2:

```powershell
wsl --set-version Ubuntu 2
```

Если нужно сделать WSL 2 версией по умолчанию:

```powershell
wsl --set-default-version 2
```

Если Ubuntu ещё не установлена, команда `wsl --install` обычно предлагает установить дистрибутив автоматически. Если нет, Ubuntu можно установить из Microsoft Store.

### 5.4. Установка Docker Desktop на Windows

Скачайте Docker Desktop с официальной страницы:

```text
https://docs.docker.com/desktop/setup/install/windows-install/
```

Дальше:

1. Запустите `Docker Desktop Installer.exe`.
2. Следуйте шагам установщика.
3. Если установщик предлагает использовать WSL 2, оставьте этот вариант включённым.
4. После установки перезагрузите компьютер, если установщик попросит.
5. Запустите Docker Desktop из меню Пуск.

Docker Desktop должен быть запущен в фоне. Обычно в трее Windows появляется значок Docker.

Проверить работу Docker можно в PowerShell:

```powershell
docker --version
```

Проверить Docker Compose:

```powershell
docker compose version
```

Если команды не работают, сначала убедитесь, что Docker Desktop открыт и полностью запустился.

## 6. Про `sudo` в Windows

В Linux и macOS команда `sudo` используется для запуска команды с правами администратора.

В Windows долгое время привычного `sudo` не было. Обычно использовался другой подход: открыть PowerShell или Windows Terminal **от имени администратора**.

В современных версиях Windows 11 есть отдельная функция **Sudo for Windows**. Она доступна начиная с Windows 11 версии 24H2 и выше. Её можно включить в настройках Windows. Но для обычной работы с Docker Desktop чаще всего `sudo` не нужен.

Для новичка проще запомнить так:

- если команда обычная, например `docker ps`, запускайте её в обычном терминале;
- если нужно установить WSL или изменить системные настройки, откройте PowerShell **от имени администратора**;
- если у вас Windows 11 с включённым sudo, можно использовать `sudo`, но для Docker Compose это обычно не требуется.

Пример запуска PowerShell от имени администратора:

1. Откройте меню Пуск.
2. Найдите PowerShell или Windows Terminal.
3. Нажмите правой кнопкой.
4. Выберите **Запуск от имени администратора**.

## 7. Установка Docker Desktop на macOS

Официальная страница установки:

```text
https://docs.docker.com/desktop/setup/install/mac-install/
```

На macOS Docker Desktop можно установить двумя способами:

1. вручную через `.dmg` файл;
2. через Homebrew.

### 7.1. Установка через `.dmg`

1. Скачайте Docker Desktop для вашего Mac.
2. Откройте `Docker.dmg`.
3. Перетащите Docker в папку **Applications**.
4. Откройте Docker из папки Applications.
5. Примите условия использования.
6. Если macOS попросит пароль, введите пароль пользователя macOS.

Docker Desktop должен быть открыт и работать в фоне.

### 7.2. Установка через Homebrew

Если Homebrew уже установлен, можно выполнить:

```bash
brew install --cask docker
```

После установки Docker Desktop нужно запустить:

```bash
open -a Docker
```

Важно: на macOS обычно **не используется** команда:

```bash
systemctl start docker
```

`systemctl` относится к Linux-системам с systemd. macOS не использует systemd как обычный Linux-сервер. Поэтому на macOS Docker запускают как приложение Docker Desktop.

Проверить Docker можно так:

```bash
docker --version
```

Проверить Docker Compose:

```bash
docker compose version
```

Если команды не работают, убедитесь, что Docker Desktop открыт и полностью запустился.

### 7.3. Про `sudo` на macOS

На macOS команда `sudo` есть. Она запускает команду с повышенными правами.

Пример:

```bash
sudo mkdir /some/system/folder
```

После ввода команды macOS попросит пароль пользователя. При вводе пароль может не отображаться — это нормально.

Но для обычных команд Docker Desktop на macOS обычно не нужно писать `sudo`. Команды обычно выполняются так:

```bash
docker ps
```

```bash
docker compose up -d
```

Если Docker Desktop во время установки попросит пароль, это отдельное действие для настройки системных компонентов. Это не означает, что каждую команду Docker нужно запускать через `sudo`.

## 8. Где должен лежать `docker-compose.yml`

Создайте отдельную папку проекта. Например:

```text
rstudio-docker
```

Внутри этой папки должен лежать файл:

```text
docker-compose.yml
```

Пример структуры:

```text
rstudio-docker/
└── docker-compose.yml
```

Все команды Docker Compose нужно запускать **из той директории, где лежит файл `docker-compose.yml`**.

Если вы находитесь в другой папке, Docker Compose может не найти файл.

Перейти в папку можно командой `cd`.

Пример Windows:

```powershell
cd C:\Users\User\Documents\rstudio-docker
```

Пример macOS:

```bash
cd ~/Documents/rstudio-docker
```

Проверить, что файл действительно есть в текущей папке:

Windows PowerShell:

```powershell
dir
```

macOS Terminal:

```bash
ls
```

В списке должен быть файл `docker-compose.yml`.

## 9. Пример `docker-compose.yml`

Ниже пример файла, который запускает RStudio Server в Docker-контейнере.

```yaml
services:
    rstudio:
        image: rocker/rstudio:latest

        container_name: rstudio

        ports:
        - "8787:8787"

        environment:

        - PASSWORD=lab
        - USERID=1000
        - GROUPID=1000

        - TZ=Europe/Moscow

        volumes:
        - /home/q10sn1k/r_studio:/home/rstudio/workspace
        - /home/q10sn1k/.rstudio_config:/home/rstudio/.config/rstudio

        restart: unless-stopped
```

Этот файл описывает один сервис — `rstudio`. Docker Compose прочитает файл, скачает образ `rocker/rstudio:latest`, создаст контейнер с именем `rstudio`, откроет порт `8787`, передаст настройки окружения и подключит папки с компьютера внутрь контейнера.

## 10. Разбор `docker-compose.yml` построчно

### 10.1. `services:`

```yaml
services:
```

Раздел `services` означает: ниже будут описаны контейнеры, которые нужно запустить.

В Docker Compose каждый сервис обычно соответствует одному контейнеру. Например, один сервис может быть базой данных, второй — веб-приложением, третий — RStudio.

В нашем примере сервис один.

---

### 10.2. `rstudio:`

```yaml
    rstudio:
```

Это имя сервиса.

Оно нужно Docker Compose, чтобы понимать, какой контейнер описывается. Имя можно было бы выбрать другим, например `app` или `rstudio-server`, но `rstudio` понятно отражает назначение.

Команды можно применять ко всему проекту сразу или к отдельному сервису.

Например:

```bash
docker compose stop rstudio
```

Эта команда остановит только сервис `rstudio`.

---

### 10.3. `image: rocker/rstudio:latest`

```yaml
        image: rocker/rstudio:latest
```

`image` указывает Docker-образ, из которого нужно создать контейнер.

В этом примере используется образ:

```text
rocker/rstudio:latest
```

Он содержит готовый RStudio Server.

Часть `latest` означает тег образа. Тег показывает версию или вариант образа. `latest` обычно означает последнюю версию, которую авторы образа считают актуальной.

Для учебного примера `latest` удобен. Для стабильного рабочего проекта лучше иногда фиксировать конкретную версию, чтобы среда не менялась неожиданно после обновления образа.

---

### 10.4. `container_name: rstudio`

```yaml
        container_name: rstudio
```

`container_name` задаёт имя контейнера.

Если его не указать, Docker Compose создаст имя автоматически. Оно может выглядеть примерно так:

```text
rstudio-docker-rstudio-1
```

С явным именем проще выполнять команды и читать список контейнеров.

Например, после запуска в `docker ps` будет видно имя:

```text
rstudio
```

Важно: если контейнер с таким именем уже существует, Docker может выдать ошибку. Тогда старый контейнер нужно остановить и удалить или изменить имя.

---

### 10.5. `ports:`

```yaml
        ports:
        - "8787:8787"
```

Раздел `ports` пробрасывает порт из контейнера на ваш компьютер.

Запись:

```yaml
- "8787:8787"
```

читается так:

```text
порт_на_компьютере:порт_внутри_контейнера
```

В нашем случае:

```text
8787:8787
```

Первый `8787` — порт на вашем компьютере.

Второй `8787` — порт внутри контейнера, где работает RStudio Server.

После запуска можно открыть браузер и перейти по адресу:

```text
http://localhost:8787
```

Если порт `8787` уже занят другой программой, можно изменить левую часть.

Например:

```yaml
- "8788:8787"
```

Тогда RStudio будет доступен по адресу:

```text
http://localhost:8788
```

---

### 10.6. `environment:`

```yaml
        environment:
```

Раздел `environment` задаёт переменные окружения.

Переменные окружения — это настройки, которые передаются внутрь контейнера при запуске.

Контейнер читает эти значения и настраивает своё поведение.

---

### 10.7. `PASSWORD=lab`

```yaml
        - PASSWORD=lab
```

Эта строка задаёт пароль для входа в RStudio Server.

В нашем примере пароль:

```text
lab
```

После запуска RStudio обычно используется логин:

```text
rstudio
```

и пароль:

```text
lab
```

Для учебного локального примера это удобно. Для реальной работы пароль должен быть сложнее.

---

### 10.8. `USERID=1000` и `GROUPID=1000`

```yaml
        - USERID=1000
        - GROUPID=1000
```

Эти строки задают идентификатор пользователя и группы внутри контейнера.

В Linux у каждого пользователя есть числовой ID. Часто первый обычный пользователь имеет ID `1000`. Эти настройки помогают сделать так, чтобы файлы, созданные внутри контейнера, не становились чужими для пользователя на компьютере.

Если вы работаете на Linux или в WSL, такие значения часто подходят.

На Windows и macOS эти настройки тоже могут работать, но смысл прав доступа может отличаться, потому что файлы проходят через слой Docker Desktop.

---

### 10.9. `TZ=Europe/Moscow`

```yaml
        - TZ=Europe/Moscow
```

Эта строка задаёт часовой пояс контейнера.

`TZ` означает timezone.

В примере указан московский часовой пояс:

```text
Europe/Moscow
```

Если нужен другой часовой пояс, его можно заменить.

Например:

```yaml
- TZ=Europe/Amsterdam
```

Это полезно, если внутри контейнера создаются файлы, логи или временные метки.

---

### 10.10. `volumes:`

```yaml
        volumes:
```

Раздел `volumes` подключает папки с компьютера внутрь контейнера.

Это нужно, чтобы данные не пропадали после остановки или удаления контейнера.

Контейнер можно удалить и создать заново, но файлы в подключённой папке на компьютере сохранятся.

---

### 10.11. Первая папка `volume`

```yaml
        - /home/q10sn1k/r_studio:/home/rstudio/workspace
```

Эта строка подключает папку с компьютера внутрь контейнера.

Формат такой:

```text
папка_на_компьютере:папка_внутри_контейнера
```

В примере:

```text
/home/q10sn1k/r_studio
```

это папка на компьютере.

А:

```text
/home/rstudio/workspace
```

это папка внутри контейнера.

Если в RStudio сохранять файлы в `/home/rstudio/workspace`, они будут лежать на вашем компьютере в папке `/home/q10sn1k/r_studio`.

Для другого пользователя путь нужно заменить.

Например, на Linux или в WSL:

```yaml
- /home/your_username/r_studio:/home/rstudio/workspace
```

Для новичка часто проще использовать относительный путь:

```yaml
- ./r_studio:/home/rstudio/workspace
```

Тогда Docker создаст папку `r_studio` рядом с файлом `docker-compose.yml`.

---

### 10.12. Вторая папка `volume`

```yaml
        - /home/q10sn1k/.rstudio_config:/home/rstudio/.config/rstudio
```

Эта строка сохраняет настройки RStudio.

Левая часть:

```text
/home/q10sn1k/.rstudio_config
```

это папка на компьютере.

Правая часть:

```text
/home/rstudio/.config/rstudio
```

это папка настроек RStudio внутри контейнера.

Если контейнер будет удалён и создан заново, настройки RStudio сохранятся в папке на компьютере.

Для новичка можно сделать путь относительным:

```yaml
- ./.rstudio_config:/home/rstudio/.config/rstudio
```

Так файл будет проще переносить между компьютерами.

---

### 10.13. `restart: unless-stopped`

```yaml
        restart: unless-stopped
```

Эта строка задаёт политику перезапуска контейнера.

`unless-stopped` означает: перезапускать контейнер автоматически, если он упал или если Docker перезапустился, но не запускать его снова, если пользователь сам явно остановил контейнер.

Это удобно, если вы хотите, чтобы сервис поднимался после перезагрузки Docker Desktop.

Для учебного примера можно оставить эту настройку.

---

## 11. Более переносимый вариант файла для новичка

В исходном примере используются абсолютные пути:

```text
/home/q10sn1k/r_studio
/home/q10sn1k/.rstudio_config
```

На другом компьютере таких папок может не быть.

Для обучения удобнее вариант с относительными путями:

```yaml
services:
  rstudio:
    image: rocker/rstudio:latest
    container_name: rstudio
    ports:
      - "8787:8787"
    environment:
      - PASSWORD=lab
      - USERID=1000
      - GROUPID=1000
      - TZ=Europe/Moscow
    volumes:
      - ./r_studio:/home/rstudio/workspace
      - ./.rstudio_config:/home/rstudio/.config/rstudio
    restart: unless-stopped
```

Здесь папки `r_studio` и `.rstudio_config` будут находиться рядом с `docker-compose.yml`.

Пример структуры:

```text
rstudio-docker/
├── docker-compose.yml
├── r_studio/
└── .rstudio_config/
```

Даже если этих папок нет, Docker часто создаст их автоматически при запуске.

## 13. Запуск контейнера

Команда:

```bash
docker compose up -d
```

Что она делает:

- читает файл `docker-compose.yml`;
- скачивает образ, если его ещё нет на компьютере;
- создаёт контейнер;
- подключает порты;
- подключает папки;
- передаёт переменные окружения;
- запускает сервис в фоновом режиме.

Флаг `-d` означает detached mode, то есть запуск в фоне.

Если не указать `-d`, терминал будет занят выводом логов контейнера.

После успешного запуска можно открыть браузер:

```text
http://localhost:8787
```

Для примера RStudio:

```text
login: rstudio
password: lab
```

---

## 14. Проверка запущенных контейнеров

Команда:

```bash
docker ps
```

Она показывает только запущенные контейнеры.

В списке нужно найти контейнер `rstudio`.

Обратите внимание на столбцы:

- `CONTAINER ID` — внутренний идентификатор контейнера;
- `IMAGE` — образ, из которого создан контейнер;
- `STATUS` — состояние контейнера;
- `PORTS` — какие порты проброшены;
- `NAMES` — имя контейнера.

Если контейнер запущен, в `STATUS` будет что-то вроде:

```text
Up 2 minutes
```

Если контейнер не виден в `docker ps`, можно посмотреть все контейнеры, включая остановленные:

```bash
docker ps -a
```

## 15. Проверка контейнеров именно текущего Compose-проекта

Команда:

```bash
docker compose ps
```

Она показывает контейнеры, которые относятся к текущему `docker-compose.yml`.

Эту команду нужно запускать из папки с файлом `docker-compose.yml`.

## 16. Просмотр логов

Если контейнер не запускается или сайт не открывается, посмотрите логи:

```bash
docker compose logs
```

Если нужно смотреть логи в реальном времени:

```bash
docker compose logs -f
```

Чтобы выйти из режима просмотра логов, нажмите:

```text
Ctrl + C
```

Это остановит просмотр логов, но не обязательно остановит сам контейнер.

---

## 17. Остановка контейнера без удаления

Команда:

```bash
docker compose stop
```

Она останавливает контейнеры, но не удаляет их.

Это похоже на выключение сервиса.

После `stop` контейнер можно снова запустить:

```bash
docker compose start
```

Когда использовать `stop`:

- нужно временно освободить ресурсы компьютера;
- нужно остановить сервис, но сохранить контейнер;
- не нужно пересоздавать контейнер с нуля.

---

## 18. Остановка и удаление контейнера

Команда:

```bash
docker compose down
```

Она останавливает и удаляет контейнеры, созданные этим Compose-проектом.

Важно: `down` удаляет контейнер, но не обязан удалять папки, которые подключены через `volumes` как папки на компьютере.

В нашем примере рабочие файлы сохраняются в папках:

```text
./r_studio
./.rstudio_config
```

или в абсолютных путях, если используются они.

Когда использовать `down`:

- нужно полностью остановить проект;
- нужно пересоздать контейнер после изменения `docker-compose.yml`;
- нужно убрать контейнер из списка `docker ps -a`.

После `down` проект можно снова поднять:

```bash
docker compose up -d
```

---

## 19. Разница между `stop` и `down`

`docker compose stop`:

- останавливает контейнер;
- контейнер остаётся существовать;
- его можно быстро запустить через `docker compose start`.

`docker compose down`:

- останавливает контейнер;
- удаляет контейнер;
- при следующем `docker compose up -d` контейнер будет создан заново.

Для новичка можно запомнить так:

- `stop` — временно остановить;
- `down` — остановить и убрать контейнер проекта.

---

## 20. Обновление образа

Если нужно скачать свежую версию образа:

```bash
docker compose pull
```

После этого можно пересоздать контейнер:

```bash
docker compose up -d
```

Если контейнер уже был создан, иногда полезно выполнить:

```bash
docker compose up -d --force-recreate
```

Это пересоздаст контейнер с учётом текущих настроек.

---

## 21. Если изменили `docker-compose.yml`

Если вы поменяли порт, пароль, volume или другую настройку, выполните:

```bash
docker compose down
```

Затем:

```bash
docker compose up -d
```

Так контейнер будет создан заново с новыми настройками.

Если вы поменяли только файлы внутри подключённой папки, контейнер обычно пересоздавать не нужно.

## 22. Частые ошибки новичков

### Ошибка 1. Docker Desktop не запущен

Симптом:

```text
Cannot connect to the Docker daemon
```

Что делать:

1. Откройте Docker Desktop.
2. Подождите, пока он полностью запустится.
3. Повторите команду.

---

### Ошибка 2. Команда запущена не из той папки

Симптом:

```text
no configuration file provided
```

Что делать:

1. Перейдите в папку, где лежит `docker-compose.yml`.
2. Проверьте наличие файла через `dir` или `ls`.
3. Запустите команду снова.

---

### Ошибка 3. Порт уже занят

Симптом может быть связан с тем, что порт `8787` уже используется другой программой.

Что делать:

Измените левую часть порта:

```yaml
ports:
  - "8788:8787"
```

После этого перезапустите проект:

```bash
docker compose down
docker compose up -d
```

Открывать нужно будет:

```text
http://localhost:8788
```

---

### Ошибка 4. Неправильные отступы в YAML

YAML чувствителен к отступам.

Нельзя случайно смешивать уровни вложенности.

Правильно:

```yaml
services:
  rstudio:
    image: rocker/rstudio:latest
```

Неправильно:

```yaml
services:
rstudio:
image: rocker/rstudio:latest
```

Если Docker Compose ругается на синтаксис, сначала проверьте отступы.

---

### Ошибка 5. Неверный путь в `volumes`

Если указана папка, которой нет, или путь написан неправильно, файлы могут оказаться не там, где ожидается.

Для новичка безопаснее использовать относительные пути:

```yaml
volumes:
  - ./r_studio:/home/rstudio/workspace
  - ./.rstudio_config:/home/rstudio/.config/rstudio
```

Так папки будут рядом с `docker-compose.yml`.

```bash
docker compose up -d
```

```bash
docker ps
```

```bash
docker compose stop
```

Файл `docker-compose.yml` должен лежать в папке проекта.

Команды `docker compose ...` нужно запускать из той же папки.
