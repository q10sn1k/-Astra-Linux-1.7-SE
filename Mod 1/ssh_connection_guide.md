# Подключение к Astra Linux SE 1.7 по SSH из Arch Linux, Debian, Ubuntu и Windows

Пошаговая инструкция для начинающих: установка клиента, первое подключение, проверка удалённой системы, диагностика, завершение сеанса и работа с зависшими SSH-процессами.

**Все адреса, логины, имена компьютеров, PID, версии и отпечатки в примерах условные. Реальные пароли, ключи и параметры учебной инфраструктуры в материал не включены.** Примеры вывода показывают возможный результат, а не результат проверки действующего сервера. Язык сообщений, версии, размеры и оформление могут отличаться.

## 1. Что такое SSH и какие данные нужны

**SSH (Secure Shell — защищённая оболочка)** позволяет управлять удалённым компьютером через зашифрованное соединение. Вы вводите команду на своём компьютере, удалённая Astra Linux выполняет её и возвращает результат.

**SSH-клиент** запускается на вашем Arch Linux, Debian, Ubuntu или Windows. **SSH-сервер** работает на удалённой Astra Linux и принимает подключения. Для выполнения этой инструкции слушателю нужен клиент; устанавливать и запускать сервер на личном компьютере не требуется.

У администратора нужно получить:

| Данные | Для чего нужны |
| --- | --- |
| Адрес входа | Внешний IP-адрес или домен сервера |
| SSH-порт | Номер порта, выделенного для подключения |
| Логин | Имя учётной записи на удалённой Astra Linux |
| Способ входа | Пароль или пользовательский ключ по правилам инфраструктуры |
| Отпечаток ключа сервера | Для проверки подлинности сервера при первом подключении |
| Требования к сети | Нужен ли университетский VPN или доступ разрешён напрямую |

В этой инструкции используются следующие условные значения:

| Обозначение | Значение в примерах | Что подставить при работе |
| --- | --- | --- |
| Адрес сервера | `203.0.113.10` | Выданный адрес входа |
| Порт | `2222` | Выданный SSH-порт |
| Логин | `student` | Выданное имя пользователя |
| Имя учебной ВМ | `astra-lab` | Покажет удалённая система |
| Локальный Linux-пользователь | `learner` | Ваше имя на личном компьютере |
| PID | `12345`, `12346` | Числа из текущего списка процессов |

Адрес `203.0.113.10` относится к диапазону TEST-NET-3, зарезервированному для документации. **Он не является адресом учебного сервера.** Не пытайтесь подключиться к нему: перед выполнением сетевых команд замените адрес, порт и логин на выданные вам значения. Пароль в команду не добавляйте.

Порт по умолчанию для SSH — 22, но администратор может назначить другой. Внешний порт на шлюзе может отличаться от порта внутри ВМ: используйте именно выданный порт входа.

Внутренний IP обычно доступен только из соответствующей сети или через настроенный для неё VPN. Наличие внешнего адреса само по себе ещё не гарантирует доступ: могут действовать ограничения по сети и источнику подключения.

## 2. Где выполняются команды

До подключения вы работаете **на своём компьютере**. После успешного входа через SSH команды выполняются **на удалённой Astra Linux**. После выхода управление возвращается локальной оболочке.

**Оболочка (shell)** — программа, которая читает и выполняет команды. Bash, fish и PowerShell — разные оболочки. **Терминал** — окно для взаимодействия с оболочкой. Windows Terminal может открывать вкладки PowerShell; это разные компоненты.

| Действие | Где выполнять |
| --- | --- |
| Установка SSH-клиента | На личном компьютере |
| Запуск подключения | На личном компьютере |
| Проверка версии Astra Linux и дисков | В открытом SSH-сеансе |
| Поиск и завершение зависшего локального SSH-клиента | В другом локальном терминале |
| Выход из удалённой оболочки | В SSH-сеансе |

В блоках команд нет символов приглашения: копируйте только саму команду. Приглашения вроде `student@astra-lab:~$` в примерах вывода показывают, где вы находитесь; их вводить не нужно. Многоточие в выводе означает пропущенные строки, а не буквальный текст программы.

## 3. Arch Linux: fish и Bash

Откройте установленный терминал. Команды этого раздела одинаковы для fish и Bash.

### 3.1. Проверить SSH-клиент

**На своём Arch Linux:**

```bash
ssh -V
```

Пример вывода:

```text
OpenSSH_9.2p1, OpenSSL 3.0.11 19 Sep 2023
```

- `ssh` — запуск SSH-клиента.
- `-V` — показать версию клиента и завершить работу. Это заглавная латинская буква V.
- `OpenSSH` — реализация SSH; `OpenSSL` — криптографическая библиотека, сведения о которой может показывать сборка клиента.

Команда не устанавливает соединение. Если оболочка сообщает, что команда не найдена, установите пакет из следующего шага. Если версия уже появилась, переходите к подключению.

### 3.2. Установить клиент, если он отсутствует

На системе с актуальными согласованными пакетами и базами:

```bash
sudo pacman -S openssh
```

Пример сокращённого вывода:

```text
[sudo] password for learner:
resolving dependencies...
looking for conflicting packages...
Packages (1) openssh-...
:: Proceed with installation? [Y/n]
...
(1/1) installing openssh
```

- `sudo` — выполнить следующую команду с правами администратора; обычно запрашивается пароль **локального** пользователя.
- `pacman` — менеджер пакетов Arch Linux.
- `-S` — установить указанный пакет из настроенных репозиториев с необходимыми зависимостями.
- `openssh` — пакет с SSH-инструментами. Наличие в нём сервера не требует запуска серверной службы для исходящего подключения.
- `[Y/n]` — запрос подтверждения: `Y` означает согласие, `n` — отказ; Enter выбирает значение по умолчанию.

Если базы и пакеты давно не обновлялись, используйте полное обновление с установкой:

```bash
sudo pacman -Syu openssh
```

Пример сокращённого вывода:

```text
:: Synchronizing package databases...
 core downloading...
 extra downloading...
:: Starting full system upgrade...
resolving dependencies...
...
:: Proceed with installation? [Y/n]
```

- `sudo`, `pacman`, `openssh` имеют тот же смысл, что выше.
- `-Syu` объединяет три флага: `-S` — работа с пакетами репозиториев; `-y` — обновить базы пакетов; `-u` — обновить установленные пакеты.

Эта команда может обновить много пакетов во всей локальной системе. Просмотрите предложенные изменения. Не обновляйте только базы без согласованного обновления системы: частичные обновления Arch Linux не поддерживаются.

### 3.3. Начать подключение

```bash
ssh -p 2222 student@203.0.113.10
```

Пример вывода при уже проверенном и сохранённом ключе сервера:

```text
student@203.0.113.10's password:
```

- `ssh` — установить защищённое подключение.
- `-p` — указать порт сервера; здесь используется строчная латинская p.
- `2222` — условное значение порта после `-p`.
- `student` — удалённый пользователь.
- `@` — разделитель имени пользователя и адреса.
- `203.0.113.10` — условный адрес сервера.

При первом подключении сначала потребуется проверить ключ сервера: порядок описан в разделе 7.

## 4. Debian

Откройте терминал на своём Debian. Для установки пакетов нужны права, разрешающие выполнение административных команд. Если `sudo` недоступна вашей учётной записи, попросите администратора установить клиент.

### 4.1. Проверить SSH

```bash
ssh -V
```

Пример вывода:

```text
OpenSSH_9.2p1 Debian-2+deb12u1, OpenSSL 3.0.9 30 May 2023
```

`ssh` — SSH-клиент; `-V` — показать его версию без подключения. Версия зависит от выпуска и обновлений Debian. Если клиент есть, установку можно пропустить.

### 4.2. Обновить сведения о пакетах

```bash
sudo apt update
```

Пример сокращённого вывода:

```text
...
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
All packages are up to date.
```

- `sudo` — выполнить команду с административными правами.
- `apt` — средство управления пакетами.
- `update` — обновить сведения о доступных пакетах из настроенных источников; это подкоманда, а не флаг.
- Флагов у `apt` в этом примере нет.

Само действие `update` не обновляет все установленные программы. Сообщение о доступных обновлениях может отличаться от примера.

### 4.3. Установить клиент

```bash
sudo apt install openssh-client
```

Пример сокращённого вывода:

```text
Reading package lists... Done
Building dependency tree... Done
...
The following NEW packages will be installed:
  openssh-client
...
Do you want to continue? [Y/n]
...
Setting up openssh-client (...)
```

- `sudo` — административные права.
- `apt` — менеджер пакетов.
- `install` — установить указанный пакет и необходимые зависимости; подкоманда без дефиса.
- `openssh-client` — пакет клиента SSH.
- `[Y/n]` — подтверждение установки; просмотрите список и нажмите Enter для согласия.

Могут дополнительно устанавливаться или обновляться зависимости. Если пакет уже установлен, `apt` сообщит об этом.

### 4.4. Подключиться

```bash
ssh -p 2222 student@203.0.113.10
```

Пример вывода при сохранённом ключе:

```text
student@203.0.113.10's password:
```

`ssh` запускает подключение; `-p 2222` задаёт условный порт; `student` — удалённый логин; `@` разделяет логин и адрес; `203.0.113.10` — условный сервер. Порядок первого входа — в разделе 7.

## 5. Ubuntu

Откройте терминал, например сочетанием Ctrl+Alt+T, если оно настроено в вашем окружении. На Ubuntu используются те же подкоманды `apt`, что и на Debian.

### 5.1. Проверить клиент

```bash
ssh -V
```

Пример вывода:

```text
OpenSSH_9.6p1 Ubuntu-3ubuntu13, OpenSSL 3.0.13 30 Jan 2024
```

`ssh` — клиент SSH; `-V` — вывести версию и завершиться. Это пример версии, а не требование к вашей системе.

### 5.2. Обновить сведения о пакетах при необходимости установки

```bash
sudo apt update
```

Пример сокращённого вывода:

```text
...
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
All packages are up to date.
```

`sudo` даёт административные права; `apt` управляет пакетами; `update` обновляет список доступных пакетов. Дополнительных флагов нет. Установленные программы эта команда сама по себе не обновляет.

### 5.3. Установить клиент

```bash
sudo apt install openssh-client
```

Пример сокращённого вывода:

```text
Reading package lists... Done
...
The following NEW packages will be installed:
  openssh-client
...
Do you want to continue? [Y/n]
...
Setting up openssh-client (...)
```

`sudo` — административные права; `apt` — менеджер пакетов; `install` — подкоманда установки; `openssh-client` — пакет клиента. Просмотрите изменения и подтвердите установку. Серверный пакет для исходящего подключения не требуется.

### 5.4. Подключиться

```bash
ssh -p 2222 student@203.0.113.10
```

Пример вывода при сохранённом ключе:

```text
student@203.0.113.10's password:
```

`ssh` запускает подключение; `-p` задаёт порт; `2222` — условный порт; `student` — логин на Astra Linux; `@` разделяет логин и адрес; `203.0.113.10` — условный адрес. Далее выполните действия раздела 7.

## 6. Windows: PowerShell и PuTTY

### 6.1. Открыть PowerShell

В меню «Пуск» найдите PowerShell и запустите его. Можно открыть вкладку PowerShell в Windows Terminal. Обычное подключение не требует запуска от имени администратора.

### 6.2. Проверить OpenSSH Client

```powershell
ssh -V
```

Пример вывода:

```text
OpenSSH_for_Windows_9.5p1, LibreSSL 3.8.2
```

`ssh` — SSH-клиент Windows; `-V` — показать версию без подключения. `LibreSSL` — криптографическая библиотека, используемая в соответствующей сборке.

Если клиент найден, переходите к подключению. Если Windows сообщает, что команда не распознана, установите дополнительный компонент **OpenSSH Client**.

### 6.3. Установить клиент, если он отсутствует

Откройте **Windows PowerShell от имени администратора** и выполните:

```powershell
Add-WindowsCapability -Online -Name OpenSSH.Client~~~~0.0.1.0
```

Пример вывода:

```text
Path          :
Online        : True
RestartNeeded : False
```

- `Add-WindowsCapability` — установить дополнительный компонент Windows; дефисы внутри имени являются частью названия команды.
- `-Online` — работать с текущей запущенной Windows; здесь слово не означает «проверить интернет».
- `-Name` — задать имя устанавливаемого компонента.
- `OpenSSH.Client~~~~0.0.1.0` — системный идентификатор клиента; четыре тильды `~~~~` нужно сохранить.
- `RestartNeeded` — нужна ли перезагрузка; если `True`, сохраните работу и выполните требуемую перезагрузку.

Для установки может требоваться доступ к разрешённому источнику компонентов Windows. Если установка запрещена политикой организации, обратитесь к администратору. Также клиент можно установить через поиск «Дополнительные компоненты» в параметрах Windows, выбрав OpenSSH Client.

После установки откройте обычную вкладку PowerShell и повторите проверку из пункта 6.2.

### 6.4. Подключиться через PowerShell

```powershell
ssh -p 2222 student@203.0.113.10
```

Пример вывода при сохранённом ключе:

```text
student@203.0.113.10's password:
```

- `ssh` — клиент подключения.
- `-p` — указать порт; `2222` — его условное значение.
- `student` — пользователь на удалённой системе.
- `@` — разделитель пользователя и сервера.
- `203.0.113.10` — условный адрес.

При первом входе проверьте ключ по разделу 7. После входа команды выполняются оболочкой Astra Linux, обычно Bash. Команды PowerShell для управления локальными процессами выполняйте в **другой локальной вкладке**, а не в удалённой оболочке.

### 6.5. Подключиться через PuTTY

Получите программу на [официальной странице PuTTY](https://www.chiark.greenend.org.uk/~sgtatham/putty/latest.html).

1. Запустите PuTTY.
2. В **Host Name (or IP address)** укажите выданный адрес сервера.
3. В **Port** укажите выданный SSH-порт.
4. Выберите **SSH** в разделе **Connection type**.
5. Нажмите **Open**.
6. Сверьте отпечаток ключа с данными администратора и подтвердите доверие только после проверки.
7. Введите выданный логин и пароль.

Пример текста в окне после проверки ключа:

```text
login as: student
student@203.0.113.10's password:
...
student@astra-lab:~$
```

Логин отображается при вводе, пароль обычно не отображается. Запрос ключа PuTTY показывает отдельным диалогом. Для штатного выхода используйте команду из раздела 9.

## 7. Первое подключение и пароль

Этот раздел относится к командам подключения из разделов 3–6. Здесь показано продолжение их вывода.

### 7.1. Проверить ключ сервера

При первом подключении OpenSSH может вывести:

```text
The authenticity of host '[203.0.113.10]:2222' can't be established.
ED25519 key fingerprint is SHA256:<УСЛОВНЫЙ_ОТПЕЧАТОК>.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

`<УСЛОВНЫЙ_ОТПЕЧАТОК>` — обозначение для документа, а не настоящий отпечаток.

**Ключ сервера (host key)** помогает проверить, к какому серверу вы подключаетесь. **Отпечаток (fingerprint)** — компактное представление ключа. `ED25519` обозначает алгоритм ключа; `SHA256` — алгоритм вычисления отпечатка.

Сверьте отпечаток с администратором по доверенному каналу. Только при совпадении введите ответ `yes` и нажмите Enter. Это ответ на запрос клиента, а не отдельная команда оболочки; флагов у него нет.

Пример следующего сообщения:

```text
Warning: Permanently added '[203.0.113.10]:2222' (ED25519) to the list of known hosts.
student@203.0.113.10's password:
```

Клиент запоминает ключ. В Linux он обычно хранится в `~/.ssh/known_hosts`, в Windows OpenSSH — в `%USERPROFILE%\.ssh\known_hosts`. Знак `~` означает домашний каталог пользователя Linux, `%USERPROFILE%` — каталог профиля Windows.

Если появляется предупреждение **REMOTE HOST IDENTIFICATION HAS CHANGED**, остановитесь и уточните причину у администратора. Возможны переустановка ВМ, замена ключа или подключение не к тому серверу. Не удаляйте сохранённый ключ автоматически и не отключайте проверку.

### 7.2. Ввести пароль

В ответ на запрос пароля введите выданный пароль и нажмите Enter. Символов и звёздочек может не быть — это нормальное поведение терминала. Пароль не следует вводить в строку запуска клиента или добавлять в файлы репозитория.

Пример результата успешного входа:

```text
Last login: ...
student@astra-lab:~$
```

Приглашение может выглядеть иначе. В примере `student` — текущий пользователь, `astra-lab` — имя удалённого компьютера, `~` — домашний каталог, `$` — обычное приглашение оболочки. Проверьте систему следующими командами.

## 8. Первые команды на Astra Linux

Все команды этого раздела выполняйте **после успешного подключения, на удалённой Astra Linux**. Они одинаковы независимо от локальной ОС. Приведённые команды только читают сведения.

### 8.1. Узнать пользователя

```bash
whoami
```

Пример вывода:

```text
student
```

`whoami` означает «кто я?» и выводит имя пользователя, с правами которого выполняется команда. Флагов и аргументов нет.

### 8.2. Узнать имя компьютера

```bash
hostname
```

Пример вывода:

```text
astra-lab
```

`hostname` показывает сетевое имя текущего компьютера. Флагов и аргументов нет. Имя должно соответствовать выданной учебной машине.

### 8.3. Узнать операционную систему

```bash
cat /etc/os-release
```

Пример фрагмента вывода:

```text
PRETTY_NAME="Astra Linux"
NAME="Astra Linux"
ID=astra
...
```

- `cat` — вывести содержимое указанного файла.
- `/etc/os-release` — файл со сведениями об ОС; это аргумент-путь, а не флаг.
- Флагов нет.

Состав и значения полей зависят от установленного выпуска. Если точный номер обновления в этом файле не указан, не определяйте его по одному названию ОС: уточните выпуск в выданных данных или у администратора.

### 8.4. Узнать версию ядра

```bash
uname -r
```

Условный пример вывода:

```text
5.15.0-example-amd64
```

`uname` выводит сведения о системе; `-r` выбирает выпуск ядра. Ядро — основная часть ОС, управляющая процессами, памятью и устройствами. Пример строки вымышленный; версия ядра не равна версии дистрибутива.

### 8.5. Узнать текущий каталог

```bash
pwd
```

Пример вывода:

```text
/home/student
```

`pwd` (print working directory) показывает полный путь к текущему рабочему каталогу. Флагов и аргументов нет. После входа это часто домашний каталог пользователя.

### 8.6. Посмотреть диски и разделы

```bash
lsblk
```

Пример вывода:

```text
NAME   MAJ:MIN RM SIZE RO TYPE MOUNTPOINT
sda      8:0    0  30G  0 disk
└─sda1   8:1    0  30G  0 part /
sdb      8:16   0  10G  0 disk
```

`lsblk` (list block devices) показывает блочные устройства. Флагов и аргументов нет.

| Столбец | Значение |
| --- | --- |
| `NAME` | Имя устройства; дерево показывает вложенность разделов |
| `MAJ:MIN` | Основной и дополнительный номера устройства в ядре |
| `RM` | Признак съёмного устройства: 1 — да, 0 — нет |
| `SIZE` | Размер |
| `RO` | Признак доступа только для чтения: 1 — да, 0 — нет |
| `TYPE` | Тип: `disk` — диск, `part` — раздел; возможны и другие типы |
| `MOUNTPOINT` | Каталог, в котором доступна смонтированная файловая система |

В новых версиях утилиты может отображаться столбец `MOUNTPOINTS`. Имена дисков также бывают другими, например `vda` или `nvme0n1`. Пустая точка монтирования не доказывает, что диск свободен и его можно форматировать. Команда просмотра не меняет содержимое устройств.

## 9. Правильное завершение сеанса

### 9.1. Выйти из удалённой оболочки

**На удалённой Astra Linux:**

```bash
exit
```

Пример вывода при завершении основной SSH-оболочки:

```text
logout
Connection to 203.0.113.10 closed.
```

`exit` — встроенная команда выхода из текущей оболочки. Флагов и аргументов в примере нет. После закрытия соединения снова появится локальное приглашение: например, `$`, `➜ ~` или `PS C:\Users\learner>`.

Если вы ранее открыли вложенную оболочку, первый выход закроет её; повторный выход завершит основную SSH-оболочку. **Выход из SSH не выключает ВМ.**

### 9.2. Разобраться с сочетаниями клавиш

| Действие | Когда использовать | Что произойдёт |
| --- | --- | --- |
| `exit` | Работа в удалённой оболочке закончена | Текущая оболочка завершится |
| Ctrl+D в пустой строке | Альтернатива выходу из оболочки | Обычно завершит оболочку, если её настройки это разрешают |
| Ctrl+C до входа | Нужно отменить попытку подключения | Обычно прервёт локальный SSH-клиент |
| Ctrl+C после входа | Нужно прервать удалённую программу | Обычно воздействует на программу на удалённой стороне и сохраняет SSH-сеанс |
| Ctrl+Z в локальном Linux-терминале | Управление заданиями | Может приостановить локальную программу; выходом из SSH не является |

После входа Ctrl+Z обычно передаётся удалённому терминалу и может приостановить **удалённую** программу. Место выполнения имеет значение.

### 9.3. Разорвать уже установленный зависший сеанс OpenSSH

В интерактивном сеансе OpenSSH с обычным символом выхода последовательно нажмите **Enter**, затем на английской раскладке введите **`~.`** — тильду и точку. Это последовательность клавиш клиента, а не команда Bash или PowerShell; флагов у неё нет.

Пример сообщения:

```text
Connection to 203.0.113.10 closed.
```

Enter обеспечивает начало новой строки, `~` включает обработку специальной последовательности, `.` завершает соединение. Способ действует для терминального сеанса при включённой обработке таких последовательностей. Он обрывает соединение: несохранённая работа может потеряться. В PuTTY используются собственные средства закрытия сеанса.

## 10. Зависшее подключение в Linux

Раздел подходит для локальных Arch Linux, Debian и Ubuntu; показанные команды работают в Bash и fish. Откройте **новую локальную вкладку или окно терминала**. Не выполняйте поиск локального клиента на удалённой ВМ.

Сначала попробуйте Ctrl+C, если вход ещё не состоялся, или выход по разделу 9, если соединение установлено. Состояние ожидания само по себе не означает зависание.

### 10.1. Найти процессы SSH

```bash
ps -u "$USER" -o pid,stat,cmd | grep '[s]sh'
```

Пример вывода:

```text
  12345 T    ssh -p 2222 student@203.0.113.10
  12346 S+   ssh -p 2222 student@203.0.113.10
```

| Часть | Пояснение |
| --- | --- |
| `ps` | Показать снимок списка процессов |
| `-u` | Отобрать процессы по эффективному пользователю |
| `"$USER"` | Подставить имя текущего локального пользователя из переменной оболочки; двойные кавычки сохраняют значение одним аргументом |
| `-o` | Задать формат вывода |
| `pid,stat,cmd` | Показать идентификатор, состояние и командную строку процесса |
| `\|` | Конвейер: передать вывод `ps` на вход `grep` |
| `grep` | Выбрать строки, соответствующие шаблону |
| `'[s]sh'` | Регулярное выражение, соответствующее тексту `ssh`; одинарные кавычки защищают шаблон от обработки оболочкой |

Шаблон `[s]sh` находит `ssh`, но не совпадает с буквальной записью `[s]sh` в командной строке самого поиска. Поэтому строка `grep` обычно не появляется. Заголовок `ps` тоже отфильтровывается: он не содержит `ssh`.

Это поиск по тексту командной строки: он может показать, например, `ssh-agent` или другую команду, содержащую `ssh`. **Перед завершением проверьте всю строку**, адрес, порт и назначение процесса. Не завершайте агент или рабочее подключение только потому, что строка попала в результат.

**PID (Process Identifier)** — числовой идентификатор процесса. После завершения процесса система может использовать его номер повторно. Перед отправкой сигнала берите PID из свежего вывода.

### 10.2. Понять состояния

| Значение | Что означает | Чего не доказывает |
| --- | --- | --- |
| `T` | Процесс остановлен сигналом управления заданиями | Что он завершён или что причина обязательно Ctrl+Z |
| `S` | Прерываемое ожидание события | Что процесс завис: ожидание ввода или сети может быть нормальным |
| `+` | Процесс входит в группу переднего плана своего терминала | Что это обязательно текущая вкладка |

Строка `S+` сочетает состояние `S` и дополнительный признак `+`. Один снимок `ps` не показывает, на каком именно сетевом шаге остановилось подключение.

### 10.3. Попросить один ненужный процесс завершиться

```bash
kill 12346
```

Пример результата при успешной отправке сигнала:

```text
learner@local:~$
```

Обычно сама команда ничего не печатает: возвращается приглашение локальной оболочки.

- `kill` — отправить сигнал процессу; название не означает, что любой сигнал обязательно завершает процесс.
- `12346` — условный PID выбранного ненужного SSH-клиента.
- Флагов нет; по умолчанию отправляется `SIGTERM` — сигнал завершения №15.

Успешная отправка сигнала не гарантирует мгновенного исчезновения процесса. Проверьте результат командой из пункта 10.1.

Тот же запрос с явным указанием сигнала:

```bash
kill -TERM 12346
```

Пример результата:

```text
learner@local:~$
```

`kill` отправляет сигнал; `-TERM` явно выбирает `SIGTERM`; `12346` — текущий PID. Это альтернатива предыдущей команде, а не обязательный второй шаг для уже завершившегося процесса.

### 10.4. Завершить два выбранных ненужных процесса

```bash
kill 12345 12346
```

Пример результата:

```text
learner@local:~$
```

`kill` отправляет `SIGTERM` по умолчанию; `12345` и `12346` — два отдельных PID, разделённых пробелом. Флагов нет. Выполняйте команду только после проверки, что **оба** процесса больше не нужны.

### 10.5. Проверить, что осталось после сигнала

```bash
ps -u "$USER" -o pid,stat,cmd | grep '[s]sh'
```

Пример возможного результата после завершения двух процессов:

```text
  12345 T    ssh -p 2222 student@203.0.113.10
```

Здесь первый процесс пока остался. `ps` показывает процессы; `-u "$USER"` ограничивает их текущим пользователем; `-o pid,stat,cmd` выбирает поля; `|` передаёт строки поиску `grep`; `'[s]sh'` отбирает текст `ssh`.

Остановленный процесс может не обработать ожидающий `SIGTERM`, пока его выполнение не продолжится. Это объясняет возможную ситуацию, когда процесс с `S+` исчез, а процесс с `T` остался.

### 10.6. Продолжить остановленный процесс

Для уже выбранного ненужного процесса со статусом `T`:

```bash
kill -CONT 12345
```

Пример результата успешной отправки:

```text
learner@local:~$
```

`kill` отправляет сигнал; `-CONT` выбирает `SIGCONT` (continue — продолжить выполнение); `12345` — PID. Этот сигнал сам по себе не завершает процесс. Если ранее был отправлен `SIGTERM`, после продолжения процесс может сразу завершиться.

Снова выполните проверку из пункта 10.1. Если тот же SSH-процесс ещё существует и больше не нужен:

```bash
kill -TERM 12345
```

Пример результата:

```text
learner@local:~$
```

`kill` отправляет сигнал; `-TERM` — запрос завершения `SIGTERM`; `12345` — заново проверенный PID. Если процесс уже исчез, повторять сигнал не нужно.

### 10.7. Вернуть приостановленное задание в терминал

Это альтернативный путь, если задание было приостановлено **в этой же локальной оболочке**. В новой вкладке список заданий другой.

```bash
jobs
```

Пример вывода Bash:

```text
[1]+  Stopped                 ssh -p 2222 student@203.0.113.10
```

Пример вывода fish:

```text
Job Group   CPU State   Command
1   12345   0%  stopped ssh -p 2222 student@203.0.113.10
```

`jobs` — встроенная команда просмотра заданий текущей оболочки. Флагов и аргументов нет. Номер задания `1` и PID `12345` — разные величины. Если заданий нет, Bash может ничего не вывести; оформление fish зависит от версии.

Для задания с номером 1:

```bash
fg %1
```

Пример вывода Bash:

```text
ssh -p 2222 student@203.0.113.10
```

В fish может появиться сообщение о переводе задания на передний план. Затем терминалом снова управляет SSH-клиент; точный текст зависит от оболочки.

- `fg` (foreground) — вернуть задание на передний план и продолжить его, если оно было остановлено.
- `%1` — задание номер 1 из `jobs`, а не PID и не флаг. Поддерживается Bash и fish.

Если подключение ещё устанавливается, используйте Ctrl+C. Если удалённая оболочка уже открыта, завершите её по разделу 9. Для задания из другой вкладки этот способ не подходит.

### 10.8. Принудительно завершить процесс

Если обычное завершение не помогло, снова проверьте PID и командную строку, затем:

```bash
kill -9 12345
```

Пример результата:

```text
learner@local:~$
```

`kill` отправляет сигнал; `-9` выбирает `SIGKILL` — сигнал №9; `12345` — PID выбранного клиента. Обычно вывода нет. Оболочка, в которой запущено задание, может отдельно напечатать уведомление `Killed`.

`SIGKILL` нельзя перехватить для штатной очистки внутри программы. Используйте его после обычных способов: он оборвёт выбранное подключение и может прервать передачу данных. Не используйте широкое завершение всех процессов SSH без проверки.

### 10.9. Убедиться, что ненужных процессов больше нет

```bash
ps -u "$USER" -o pid,stat,cmd | grep '[s]sh'
```

Пример результата, если совпадений нет:

```text
learner@local:~$
```

Между командой и приглашением нет строк вывода. `ps` просматривает процессы; `-u "$USER"` выбирает пользователя; `-o pid,stat,cmd` — поля; `|` — конвейер; `grep '[s]sh'` — текстовый фильтр.

Пустой результат означает отсутствие **совпадающих строк** у этого пользователя. Другие действующие подключения или агент могут остаться в списке — завершать их не требуется. Если появляется `No such process`, выбранный PID уже не существует: обновите список, а не подставляйте старые номера наугад.

## 11. Зависшее подключение в Windows

Откройте **другую локальную вкладку PowerShell**. Параметры Linux-команд просмотра процессов и сигналы Linux сюда напрямую не переносятся.

### 11.1. Найти процессы клиента

```powershell
Get-Process -Name ssh -ErrorAction SilentlyContinue
```

Пример вывода:

```text
Handles  NPM(K)    PM(K)      WS(K)     CPU(s)     Id  SI ProcessName
-------  ------    -----      -----     ------     --  -- -----------
    160      12     3500       9000       0.03  12345   1 ssh
```

- `Get-Process` — получить сведения о процессах Windows.
- `-Name` — отбор по имени процесса.
- `ssh` — имя клиента без расширения `.exe`.
- `-ErrorAction` — определить обработку ошибок команды.
- `SilentlyContinue` — не показывать сообщения об ошибках; в частности, при отсутствии такого процесса вывода обычно нет.
- `Id` — идентификатор процесса; остальные столбцы показывают сведения о ресурсах и сеансе Windows.

Этот список не ограничен автоматически только вашими SSH-процессами. Завершайте лишь собственный проверенный клиент.

### 11.2. Показать только PID и имя

```powershell
Get-Process -Name ssh -ErrorAction SilentlyContinue | Select-Object Id, ProcessName
```

Пример вывода:

```text
   Id ProcessName
   -- -----------
12345 ssh
```

`Get-Process -Name ssh` выбирает процессы клиента; `-ErrorAction SilentlyContinue` скрывает сообщения об ошибках; `|` передаёт **объекты** следующей команде; `Select-Object` выбирает свойства; `Id` и `ProcessName` — имена свойств, разделённые запятой. Это альтернатива полному списку из пункта 11.1.

### 11.3. Увидеть адрес и порт подключения

Если открыто несколько сеансов:

```powershell
Get-CimInstance -ClassName Win32_Process -Filter "Name = 'ssh.exe'" | Select-Object ProcessId, CommandLine
```

Пример вывода:

```text
ProcessId CommandLine
--------- -----------
    12345 "C:\Windows\System32\OpenSSH\ssh.exe" -p 2222 student@203.0.113.10
```

- `Get-CimInstance` — запросить системные сведения через CIM (Common Information Model — общую модель управления).
- `-ClassName` — выбрать класс сведений.
- `Win32_Process` — класс процессов Windows.
- `-Filter` — отбор экземпляров при запросе.
- `"Name = 'ssh.exe'"` — условие: имя исполняемого файла равно `ssh.exe`; двойные кавычки ограничивают строку PowerShell, одинарные — значение внутри фильтра.
- `|` — передать объекты дальше.
- `Select-Object` — выбрать свойства `ProcessId` (PID) и `CommandLine` (командную строку).

Адрес и порт позволяют отличить сеансы. Для части чужих процессов командная строка может быть недоступна. Не выбирайте процесс по одному совпадению имени.

### 11.4. Завершить выбранный процесс

Сначала попробуйте штатный выход или отмену по разделу 9. Если это невозможно и клиент больше не нужен:

```powershell
Stop-Process -Id 12345
```

Пример результата:

```text
PS C:\Users\learner>
```

Обычно команда не выводит текст.

- `Stop-Process` — остановить процесс Windows; это не команда штатного выхода из удалённой оболочки.
- `-Id` — выбрать по числовому идентификатору.
- `12345` — PID из свежего списка.

Команда прекращает локальный клиент и разрывает его подключение. Она не посылает удалённой Astra Linux сигнал `SIGTERM`.

Вариант с подавлением запроса подтверждения:

```powershell
Stop-Process -Id 12345 -Force
```

Пример результата:

```text
PS C:\Users\learner>
```

`Stop-Process` останавливает процесс; `-Id 12345` выбирает PID; `-Force` подавляет запрос подтверждения, когда он требуется этой командой. Это **не отдельный более сильный Unix-сигнал** и не способ обойти права доступа. Для собственного процесса подтверждение обычно не запрашивается и без этого параметра. Не запускайте оба варианта подряд для уже завершённого PID.

### 11.5. Проверить результат

```powershell
Get-Process -Name ssh -ErrorAction SilentlyContinue | Select-Object Id, ProcessName
```

Пример при отсутствии процессов:

```text
PS C:\Users\learner>
```

`Get-Process` получает процессы; `-Name ssh` выбирает клиента; `-ErrorAction SilentlyContinue` скрывает сообщения об ошибках; `|` передаёт объекты; `Select-Object Id, ProcessName` оставляет PID и имя. Если отображается другой действующий сеанс, сохраняйте его.

### 11.6. Альтернатива в CMD

Если PID уже определён, в обычной командной строке Windows можно выполнить:

```bat
taskkill /PID 12345 /F
```

Пример вывода:

```text
SUCCESS: The process with PID 12345 has been terminated.
```

- `taskkill` — завершить процесс Windows.
- `/PID` — указать идентификатор процесса.
- `12345` — проверенный текущий PID.
- `/F` — принудительное завершение.

Это альтернатива остановке через PowerShell. Сообщение может быть на русском языке. Для зависшего PuTTY можно закрыть его окно либо открыть Диспетчер задач, найти **нужный** процесс PuTTY и завершить его; фильтр `ssh` из предыдущих пунктов PuTTY не находит.

## 12. Диагностика сети и SSH

### 12.1. Включить подробный вывод

**На локальном Arch Linux, Debian, Ubuntu или в PowerShell Windows:**

```bash
ssh -v -o ConnectTimeout=5 -p 2222 student@203.0.113.10
```

Пример фрагмента при доступном сервере:

```text
debug1: Connecting to 203.0.113.10 [203.0.113.10] port 2222.
debug1: Connection established.
...
student@203.0.113.10's password:
```

Пример при сетевом тайм-ауте:

```text
debug1: Connecting to 203.0.113.10 [203.0.113.10] port 2222.
...
ssh: connect to host 203.0.113.10 port 2222: Connection timed out
```

| Часть | Пояснение |
| --- | --- |
| `ssh` | Запустить клиент |
| `-v` | Вывести диагностические сообщения; строчная v отличается от `-V`, показывающей версию |
| `-o` | Передать дополнительную настройку клиента |
| `ConnectTimeout=5` | Ограничить ожидание подключения и начального обмена SSH пятью секундами |
| `-p 2222` | Использовать условный порт 2222 |
| `student@203.0.113.10` | Условный логин и адрес, разделённые `@` |

Настройка тайм-аута не ограничивает весь сеанс пятью секундами и не задаёт общий срок на ввод пароля. Разрешение имени и несколько адресов также могут влиять на общее время ожидания. Диагностический вывод может содержать адреса, имена и пути: перед публикацией удаляйте реальные данные.

### 12.2. Проверить TCP-порт из Windows

**В локальном Windows PowerShell:**

```powershell
Test-NetConnection -ComputerName 203.0.113.10 -Port 2222
```

Пример фрагмента вывода:

```text
ComputerName     : 203.0.113.10
RemoteAddress    : 203.0.113.10
RemotePort       : 2222
TcpTestSucceeded : True
```

- `Test-NetConnection` — диагностика сетевого соединения.
- `-ComputerName` — имя или IP проверяемого узла.
- `203.0.113.10` — условный адрес.
- `-Port` — TCP-порт для проверки.
- `2222` — условное значение порта.

`True` означает, что удалось установить TCP-соединение с адресом и портом. Это не подтверждает правильность пароля и даже не гарантирует, что на порту работает SSH. `False` означает неуспешную проверку; причину нужно уточнять.

### 12.3. Проверить выбранный маршрут в Linux

Если подозреваете влияние VPN, **на локальном Linux**:

```bash
ip -4 route get 203.0.113.10
```

Пример вывода при маршруте через VPN:

```text
203.0.113.10 dev wg-demo table 51820 src 192.0.2.20 uid 1000
    cache
```

Все значения в выводе условные.

- `ip` — утилита просмотра и настройки сети из набора iproute2.
- `-4` — использовать IPv4.
- `route` — подкоманда работы с маршрутами.
- `get` — показать маршрут, который ядро выбрало бы до указанного адреса; это просмотр, а не изменение настройки.
- `203.0.113.10` — адрес назначения; команда ожидает IP, а не URL.
- В выводе `dev` — интерфейс, `table` — таблица маршрутизации, `src` — выбранный исходный адрес, `uid` — идентификатор локального пользователя.

Имя интерфейса в примере намекает на VPN, но само по себе ничего не доказывает. Команда не проверяет доступность порта и не показывает весь путь через интернет. Если утилита `ip` отсутствует, попросите администратора установить iproute2.

Личный VPN может менять маршруты и мешать доступу. Если правила учебной инфраструктуры допускают прямое подключение, временно отключите личный VPN и повторите проверку. Университетский VPN, который требуется для доступа, отключать не следует. Одного факта наличия VPN недостаточно для вывода о причине ошибки.

### 12.4. Разобрать сообщение об ошибке

| Сообщение | Что обычно означает | Что проверить |
| --- | --- | --- |
| `Connection timed out` | За время ожидания не удалось завершить нужный этап соединения | Адрес, порт, маршрут, VPN, сетевые фильтры и доступность сервера |
| `Connection refused` | Подключение к порту отклонено | Правильность порта, работу SSH-сервера и правила шлюза у администратора |
| `Permission denied` | Сервер не принял способ входа или учётные данные | Логин, пароль, раскладку, разрешённый метод авторизации |
| `Could not resolve hostname` | Имя не удалось преобразовать в адрес | Опечатки, DNS, отсутствие лишних слов в команде |
| `Host key verification failed` | Проверка ключа сервера не завершилась успешно | Отпечаток, сохранённый ключ и причину изменения у администратора |
| `No route to host` / `Network is unreachable` | Нет подходящего сетевого пути или получено сетевое сообщение о недоступности | Локальную сеть, маршрут, VPN и ограничения инфраструктуры |

Не вводите название программы дважды: в строке подключения должен быть один запуск клиента. Не используйте Ctrl+Z как способ выхода.

Если современный клиент предупреждает о согласовании обмена ключами без постквантового алгоритма, это само по себе не означает сбой авторизации. Покажите предупреждение администратору: изменение серверных алгоритмов выходит за рамки подключения слушателя.
